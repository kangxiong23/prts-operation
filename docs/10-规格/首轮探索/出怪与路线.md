# 出怪与路线

> 状态：讨论中 ｜ 门检测点与停留点形态已立；**采资产模式**的正文

**首轮探索**的正文之一——两个模式见 [README.md](README.md) §2；录轴那一半见[录轴.md](录轴.md)；产出的**资产格式**见[路线](../资产生成器/地形与关卡资产/路线.md)。

本文件管**采资产模式**：工具怎么把出怪与路线从画面里搬出来，以及**哪一部分搬不出来**。

## 1 找出怪事件：只在门检测点上做

**不做全画面检测。**

- 门的位置来自**地形资产** → 投影 → 门格附近一个**小 ROI**；
- **每一帧**算该 ROI 与**参考帧**的差分，跳变即"有东西从这门里出来了"；
- 落一张小截图 + 时刻。

**换通道之后这条判据可以加一条**：跳变**要持续 N 帧**才算一次出怪。30–60 FPS 下假阳性只闪一两帧，而真出怪会一直在——**原设计 0.9 s 一帧时加不了这条，因为 N 帧的"帧"本来就没有**。

**为什么这就够了**：出怪有**极强的位置先验**——它必定发生在**已知的几个点**上。而全画面检测要在**最脏的画面**（怪海 + 特效 + 满血无血条）上做最难的事，而在线方案**已经明确放弃**了那件事（[状态层/敌方单位](../状态层/敌方单位.md) 把位置主通道翻成推算）。**用已知位置把搜索空间从整屏缩到几个小矩形，卷积就没有活干了。**

### 参考帧：用本局开局帧

**门格必定干净**——"初始存在xx怪"出现在**非门上**（词条效果），所以它不污染门格。

**这与[背景帧](../资产生成器/背景帧.md) 是两回事**：那里要**整个战场区**干净，而且**只有无词条局**的开局帧才算数；这里只要**门格**干净，本局开局帧就够。

### 检测点：默认门格，可拖

**门在边缘被 UI 挡住是常事**（慢放下的详情面板、地图边缘的装饰）。**手动把检测点拖到门后一格**就能继续用。

### 假阳性与假阴性

| | 来源 | 怎么办 |
| --- | --- | --- |
| **假阳性** | 我方干员经过门附近 · 特效 | **不致命**——人扫一眼列表就删了。阈值**往松里放** |
| **假阴性** | 慢放下面板挡住门 · 参考帧失配 | **致命**——漏一个出怪。要显式报"这一门这一段没盯住" |

**候选多报不是假事实**（每条都要人确认），**漏报才是**。

**同门同帧出两个怪不考虑**：图像会完全重叠，那属于游戏 bug（用户确认）。

### 一条不需要检测的

**"初始存在xx怪"出现帧 = 0**，时刻**已知**，不需要门检测。它的位置在**非门格**上，靠**全战场差分**（用无词条局的干净帧）抓得到——**开局就与背景不同的色块就是它**。

## 2 临时资产：出怪帧的裁图

从门里出来的那一刻，怪是**完整的、没有重叠、没有特效**的（[特征库](../资产生成器/特征库.md) §2 的排队优先级①）。所以：

> **出怪帧的裁图 = 临时资产**；人标路线时**顺手把名字标了**，它就成了正式资产。**它的像素倾向走原始抓帧**（[README](README.md) §2）——但它只做**聚类分组**，所以录像的 h264 块效应也许无所谓，**要试**。

**采集不单独占动作**——这是第三次实例（前两次：卡面挂 `启动`、难例挂识别）。

**左右朝向互为镜像**（用户确认）→ **资产只存一个朝向，运行时翻转**，省一半条目。**"严格镜像"要验一次**（不对称设计、带光效的怪可能不成立）。

**它处理不了怪本身的特效** → 所以它是**未命中资产库时的后路**，不是主通道。它给的是"**这是一只我没见过的怪**"（聚类分组）；人给名字之后，**它仍需要一次干净采集才算正式资产**。

## 3 路线：观测段、推断段与多轮累积

**怪几乎走不到蓝门**——人要摆干员击杀，否则怪出完游戏就结束了。所以：

- **每只怪只被观测到一段**；
- **最后一节要人根据趋势猜**。

于是：

> **格序列 = 多个个体的观测段的并集 + 人补全的尾部。**

**同一条形状上有多只怪**，越晚出的往往走得越远 → 并集通常覆盖大部分。人凭记忆画的时候本来就在**累积**。

**补全段必须显式标出来**（[路线](../资产生成器/地形与关卡资产/路线.md) §1 的"每一格带来源：观测 / 推断"）：

> 理由不是洁癖：**尾部恰恰是 AI 最关心的那一段**（"还有多久到蓝门"），而它恰好最不可靠。

### 多轮累积是硬需求

**人操作会失误，怪被过早打死是常态**——所以：

> **同一条形状必须能跨多局累积**，而不是"一局画不完就重来"（用户裁定）。

三条连带：

1. **编辑器要能"载入已有形状继续补"。** 这一条几乎不要钱——形状层存的格序列 + 相对恢复时刻**本来就不含任何"这一局"的量**（[路线](../资产生成器/地形与关卡资产/路线.md) §1 那个拆两层正好护住了它），所以跨局合并是干净的；
2. **并集规则：每一格取"或"**——任一周观测到就算观测。跨局之后**连续一串"推断"就是洞**；
3. **来源只存「观测 / 推断」二值**（用户裁定）：**不带局标识**——"局"是制作过程的痕迹，不属于资产的语义。要追溯"我怀疑上一局看错了"时重画即可。这与"绝对恢复时刻不存"同一条纪律：**属于过程的，不给它第二处写错的机会**。

### 一个收获：跨局合并会暴露分叉

第 1 局看到 `A→B→C`，第 2 局看到 `A→B→D`——**合不到一条格邻接路径上**。这不是问题，是**发现**：

> **"这两轮的观测接不上，可能不是同一条形状。"**

**所以「同一形状」的判据不是"同类型同门"，而是"观测段能不能接上"**（用户裁定）——形状的身份由**观测能不能拼成一条格邻接路径**来定，不由我们预先猜的分组来定。

**一条有代价的观测手段**：**故意放一个怪过去**（扣生命值）就能看到完整路线。合约里有时代价很大（有些词条漏怪直接失败），所以它是**选项不是默认**——而采资产模式那一局本来就不带词条，代价最小（见 §5）。

## 4 停留点：怎么量

**机制与字段定义在[路线](../资产生成器/地形与关卡资产/路线.md) §1.1**（怪停留 = 系统还没给它设下一个判定点；记**恢复时刻**，不记起点、不记时长）。本节只写**怎么量**。

### 单边：我们的控制只会让它更晚

阻挡 / 停顿 / 眩晕 / 冻结**只会推迟恢复，不会提前** → `T_观测 ≥ T_真值`：

1. **跨样本取最小值 = 真值**；
2. **全都偏大 → 报"这一条没采到干净值"**；
3. **没有"偏小"的方向** → **零假事实在这里是免费的**。

这是[识别方法](../视觉层/识别方法.md) 那条纪律的又一个实例：**单边只是不准，双边才是假事实**。

**顺带消掉一个人工任务**：人**不需要**判断"这个停是机制造成的还是我们造成的"——我们造成的延长在**取最小值**那一步自动被滤掉。

**而采资产模式从源头就少了一大半干扰**：那一局本来就"少放干员、放怪过去"，我们自己的控制最少。

### 自洽检查（工具自己跑）

**T 是形状的属性，不是个体的属性**（同一形状上每只怪各自到达，但 T 相同）：

| 多个个体给出的 T | 说明 |
| --- | --- |
| **分散** | 有干扰 → 取最小 |
| **收敛到同一个值** | 大概率就是真值 |
| **全都比某个值大** | 这一条没采到干净值，报出来 |

### 取法要定死：出现帧取窗口下界

**T 会与出场时间一同变化**（用户确认：词条改出场时刻时，T 同步位移）→ 所以**存相对恢复时刻**（相对这条记录的出现帧），**给 AI 看时算成绝对**（[路线](../资产生成器/地形与关卡资产/路线.md) §1.1）。

而相对量是**两个观测相减**，取法会决定它还是不是单边：

- **取窗口下界**（上次取像那一帧）→ 出现帧偏小 → **相对量偏大** → **仍是上界** ✓
- 取中点或上界 → 有一半机会偏小 → **单边被破坏** ✗

**而"取窗口下界"的代价是分辨率 = 取像间隔**（0.9 s ≈ 27 帧，[README](README.md) §7 那条）。

**一条可能的第二信号：位置插值。** 不要用"出现 / 不出现"这个**二值量**去夹逼事件时刻，用**位置**这个**连续量**：
第一帧看见它时它已经离红门 `d` 远，速度 `s` 已知（数据库，或两帧差分）→ 时刻 ≈ `T_那一帧 − d / s`。**这跟费用条相位是同一个手法：找一个连续量当尺子。**

**但它和本节的单边纪律有冲突，所以只许当复核、不许当主取法**：

| | 单边？ |
| --- | --- |
| 取窗口下界 | ✓ **只会偏大**——零假事实免费 |
| 位置插值 | ✗ **会偏小**（速度估错、出场动画、被阻挡减速都会）→ **单边被破坏** |

**已裁定：不立，只当复核**（用户裁定）——**单边那条免费保障比分辨率值钱**。插值只用来发现"这里可能漏了一个"，**不产生入账的值**。

## 5 两个模式：哪一局干什么

| 模式 | 词条 | 目标 | 干什么 |
| --- | --- | --- | --- |
| **采资产**（本文件） | **无** | **怪走最远**（少放干员、放它过去） | 背景帧 · **形状** · 基础出现帧 · 地形 |
| **录轴**（[录轴.md](录轴.md)） | **目标那组** | **尽量早击杀** | **轴** · 该组合的出现帧覆盖 · 禁用格覆盖 |

**"打一局不够"因此落在两个模式里**：

| 原因 | 落在哪 |
| --- | --- |
| 背景帧只从无词条局取 | **采资产** |
| 形状要跨多局拼（生命值有限、怪被过早打死） | **采资产**（可能几局） |
| 每个词条组合的出现帧要单独观测 | **录轴** |
| 某局把怪延误过了 T → 那个停留点白观测 | **采资产** |

**不预设"只放某一个门的怪过去"**（用户裁定）：人自己决定。想一局只摸一个门也行——**多轮累积的机制本来就支持它**。

- **"词条不改格序列"要直接确认**：现在是从"改时刻"那三类词条推的（[路线](../资产生成器/地形与关卡资产/路线.md) 的「尚未定」也记着这条）；

- **跟踪要不要做**：人凭记忆点格是主通道，跟踪只服务"停留点的恢复时刻"。**换通道之后它变得可负担**——离线分析没有实时算力预算，所以跟踪、以及位置插值（**只当复核**，§4）这类重算法第一次真正可做。**够不够要试**；
- **出怪密集的时段要不要主动进慢放**（[README](README.md) §7）。
