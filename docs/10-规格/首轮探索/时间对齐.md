# 时间对齐

> 状态：讨论中 ｜ **相位积分当主轴**已立；"整费跳变"这个前提待实测

**首轮探索**的正文之一——定位与形态见 [README.md](README.md)。

线上那套（[时间基](../../30-专题/时间基.md) §4 · [控制层/暂停条件](../控制层/暂停条件.md) §3）是**秒表为主轴、费用读数为校准**——因为线上**时间态是工具自己切的**，秒表知道该按什么速率走。

**首轮是人在切时间态，工具不知道**，所以主从要对调。

## 1 主轴：费用进度条相位

```
余额     = 初始费 + ∫自然回费 dt − Σ消费 + Σ先锋回费
进度条相位 = frac(余额)
```

**消费与先锋回费都是整费跳变**，整数不改变小数部分 → **相位只被自然回费驱动**：

| 人干了什么 | 相位 | 结果 |
| --- | --- | --- |
| 暂停 | 不动 | 逻辑帧不动 ✓ |
| 慢放 | 走得慢 | 逻辑帧跟着慢 ✓ |
| 部署 / 开技能 | **不受影响** | 时间照常走 ✓ |
| 切慢放 | 增长速率的**突变点** | **自动识别时间态切换**，不用人标 |

**取像不断就能积分。** 常速下相位 1 圈 = 30 逻辑帧，而取像周期 0.3–0.5 s = 10–15 帧 = 1/3～1/2 圈，不会绕圈；慢放下只有 1/30 圈。

**顺带一条红利**：时间轴**不依赖任何数字识别**——字形模板认错了也不污染时间轴。这是一条"降级不互相污染"的例子，正是零假事实想要的结构。

## 2 断掉怎么办：手动消耗 + 秒表兜底

**费用满（99）时相位停住，积分断。** 分两层处理：

1. **主手段：让余额到不了 99。** 快到时 **UI 给玩家一个提示**，人花掉即可。**这是对人施加的一条约定，不是保证**——忘了就会断；
2. **兜底：退回秒表**——墙钟积分 × 上次测出的倍率（[时间基](../../30-专题/时间基.md) §4 的"顺带白拿慢放倍率"），并标**这一段精度低**。

**注意提示本身需要余额（整数）**，那一步要读数字。但**它失败了只影响提示，不影响时间轴**——这个分离是对的。

## 3 取像往返：消掉的是「系统性偏移」

发起时刻 `t0`、拿到时刻 `t1`，**画面内容对应的是 `t0` 附近**（延迟主要在传输）。

- **不记它** → 以为"拿到帧的时刻"就是"帧内容的时刻" → **出怪时刻整体后移一个往返耗时**；
- **记它** → 时间戳落在**发起**那一刻。

**区间宽度没变，变的是整体位置。** 系统性偏移比随机误差危险得多：随机误差是"不确定"，**系统性偏移是假的确定值**。

第二个用途：**往返耗时的抖动 = "内容对应发起时刻"这个假设稳不稳**。抖得厉害就把抖动计入不确定度。

## 4 出怪时刻的取法：取窗口下界

出怪事件只知道落在 `(上次取像, 这次取像]` 这个窗口里。

**取窗口下界**，理由在[出怪与路线](出怪与路线.md) §4：停留点的**单边性质**要保住，出现帧必须取**偏小**的那一端。

## 5 与时间基的关系

| | 线上 | 首轮探索 |
| --- | --- | --- |
| 主轴 | **秒表**（每帧都有值） | **相位积分**（每次取像都有值，且是绝对值） |
| 校准 | 费用读数，定期拉回 | **秒表**，只在相位断掉时补位 |
| 时间态从哪知道 | **工具自己切的** | **从相位增长速率的突变推** ← 这一环是新补的 |

线上要秒表当主轴，是因为它**每帧**都得知道游戏时间（暂停条件判定）；首轮探索**不需要取像之间的时间**（人看着画面）。

**[契约层](../契约层/README.md) §3 那条纪律照样适用**：逻辑帧与墙钟毫秒在类型上分开——同一次 0.4 s 的取像往返，常速下是 12 个游戏帧、慢放下只有 1.2 帧。
