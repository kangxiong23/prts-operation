# 时间对齐

> 状态：讨论中 ｜ **相位积分当主轴**已立；"整费跳变"这个前提待实测

**首轮探索**的正文之一——定位与形态见 [README.md](README.md)。

线上那套（[时间基](../../30-专题/时间基.md) §4 · [控制层/暂停条件](../控制层/暂停条件.md) §3）是**秒表为主轴、费用读数为校准**——因为线上**时间态是工具自己切的**，秒表知道该按什么速率走。

**首轮是人在切时间态，工具不知道**，所以主从要对调。

## 1 主轴：费用进度条相位

```
余额     = 初始费 + ∫自然回费 dt − Σ消费 + Σ先锋回费
进度条相位 = frac(余额)
```

**消费与先锋回费都是整费跳变**，整数不改变小数部分 → **相位只被自然回费驱动**：

| 人干了什么 | 相位 | 结果 |
| --- | --- | --- |
| 暂停 | 不动 | 逻辑帧不动 ✓ |
| 慢放 | 走得慢 | 逻辑帧跟着慢 ✓ |
| 部署 / 开技能 | **不受影响** | 时间照常走 ✓ |
| 切慢放 | 增长速率的**突变点** | **自动识别时间态切换**，不用人标 |

**取像不断就能积分——但这条有一个前提：取像周期必须明显短于 1 圈。**

> **这个前提曾不成立。** 原文写的是取像周期 **0.3–0.5 s**（2–3 FPS），而[设备层](../设备层.md) 实测是 **0.9 s ≈ 1.1 FPS**。常速下相位 1 圈 = 30 逻辑帧 = 1.0 s，**0.9 s 就是 0.9 圈——近共振**：每帧相位**倒退 0.1 圈**、10 帧一个循环（[时间基](../../30-专题/时间基.md) §3.3）。于是**积分方向不可判**（分不出"前进 0.9 圈"和"后退 0.1 圈"），而首轮探索**刻意不读数字**（下面那条红利），所以没有整数位来补这个 1。

**解法是换取像通道**（用户裁定 → [D-全局-20](../../20-决策记录/全局.md)）：**首轮探索走设备端 `screenrecord` 录制 + 离线逐帧分析**。30–60 FPS 下，采样间隔折成 **0.03–0.06 圈**，绕圈消失；**出怪时刻的窗口同时从 ±27 帧收到 1–2 逻辑帧**。

**而"精确"不是通道给的**：通道买到的是**密度**，每个时刻的精度始终是**帧自己的相位**给的 **0.2 逻辑帧**。所以 §3 那套"往返偏移"在录制通道下基本退场。

**而"录像帧号 → 时刻"这条折算不存在，也不许造。** `screenrecord` 出的是**变帧率**（实测 487 个不同的帧间隔，6.822–27.222 ms，均值 59.9 FPS）——**"第 n 帧 = n/60 秒"是错的**（±10 ms ≈ ±0.6 逻辑帧）。每一帧的时刻**一律走它自己的相位**：相位给到 0.2 逻辑帧，比按帧号折算准得多。**帧号只用来排序与索引，不用来定时。**

**顺带一条红利**：时间轴**不依赖任何数字识别**——字形模板认错了也不污染时间轴。这是一条"降级不互相污染"的例子，正是零假事实想要的结构。

**而速率本身也在这里测出来**：常速下 `上升总 px ÷ 帧数 × 60 ÷ 153` 就是**自然回费速率** `r`。它**不是常数**（关卡机制与词条都能改，实测有 `1/3` 的关卡），而 `游戏时间 = 累计自然回费量 ÷ r`，**`r` 错 3 倍整条轴就错 3 倍**。所以它是**首轮探索的固定产出之一**，进前提头（[时间基](../../30-专题/时间基.md) §6）。**这是工具搬的、不是人填的**——符合 §3 那条「人的输入里不许有搬运」。

## 2 断掉怎么办：手动消耗 + 秒表兜底

**费用满（99）时相位停住，积分断。** 分两层处理：

1. **主手段：让余额到不了 99。** 快到时 **UI 给玩家一个提示**，人花掉即可。**这是对人施加的一条约定，不是保证**——忘了就会断；
2. **兜底：退回秒表**——墙钟积分 × 上次测出的倍率（[时间基](../../30-专题/时间基.md) §4 的"顺带白拿慢放倍率"），并标**这一段精度低**。

**注意提示本身需要余额（整数）**，那一步要读数字。但**它失败了只影响提示，不影响时间轴**——这个分离是对的。

## 3 取像往返：录制通道下它退场了

**旧通道（实时 `screencap` + `pull`）**里，发起时刻 `t0`、拿到时刻 `t1`，**画面内容对应的是 `t0` 附近**（延迟主要在传输）。于是：

- **不记它** → 以为"拿到帧的时刻"就是"帧内容的时刻" → **出怪时刻整体后移一个往返耗时**；
- **记它** → 时间戳落在**发起**那一刻。

**区间宽度没变，变的是整体位置。** 系统性偏移比随机误差危险得多：随机误差是"不确定"，**系统性偏移是假的确定值**。

**录制通道下这一整套退场**：录下来的帧没有"每次一往返"，而**每一帧自己带相位**——相位直接给出它在游戏时间上的位置（mod 1 秒，0.2 帧）。偏移问题从"每帧减一个往返"缩成"**一个录制起点的常数**"，而那个常数也被相位吸收。

> **要留着的是它的判据，不是它的算法**：`Δ` 的抖动 = "内容对应某个固定时刻"这个假设稳不稳。换通道不是取消这条纪律，是把它换成"**录制节奏稳不稳**"——而录制节奏的抖动同样由相位兜住。

## 4 出怪时刻的取法：取窗口下界

出怪事件只知道落在 `(上次取像, 这次取像]` 这个窗口里。

**取窗口下界**，理由在[出怪与路线](出怪与路线.md) §4：停留点的**单边性质**要保住，出现帧必须取**偏小**的那一端。

## 5 与时间基的关系

| | 线上 | 首轮探索 |
| --- | --- | --- |
| 主轴 | **秒表**（每帧都有值） | **相位积分**（每次取像都有值，且是绝对值） |
| 校准 | 费用读数，定期拉回 | **秒表**，只在相位断掉时补位 |
| 时间态从哪知道 | **工具自己切的** | **从相位增长速率的突变推** ← 这一环是新补的 |

线上要秒表当主轴，是因为它**每帧**都得知道游戏时间（暂停条件判定）；首轮探索**不需要取像之间的时间**（人看着画面）。

**[契约层](../契约层/README.md) §3 那条纪律照样适用**：逻辑帧与墙钟毫秒在类型上分开——同一次 0.4 s 的取像往返，常速下是 12 个游戏帧、慢放下只有 1.2 帧。

## 尚未定

- **"初始费 / 部署消费 / 先锋回费全是整数"这个前提**：只要有一个是小数，相位就不干净了。**一次实测就能答**；
- **录制通道下"这是第几秒"的整数从哪来**：由相位积分给（§1）——但要确认 30–60 FPS 下**编码器丢帧**不会让积分跳圈（丢帧只让间隔变大，只要不接近 1 圈就安全）；
- **录制起点怎么与零点对齐**：零点靠首读算出（[时间基](../../30-专题/时间基.md) §3.4），而录制是另一条时间线，两者要对齐一次；
- **费用满的时段有多长**：人一直在摆干员的话费用花得快，满的时段可能很短——**要真机测频率**；
- **相位积分断了之后怎么接回**：秒表续的那一段与相位重新对上时，差值本身就是"时间基准漂移"的度量（[状态层/全局与HUD](../状态层/全局与HUD.md) 就是这么写的），要不要上报；
- **提示的触发阈值**。
