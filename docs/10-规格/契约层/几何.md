# 几何

> 状态：讨论中 ｜ 见 [README](README.md)


**格坐标是连续的。** 整数部分是格，小数部分是格内偏移：`(5.4, 3.0)` = 第 5 格内偏右 0.4 格、第 3 行。

- 多出来的那一位**表达的是"格内偏移"，不是精度炫耀**——"敌人到第 3 格"这个事件的时刻，整数坐标给不出，而两段式条件存在的全部理由就是卡帧；
- **但小数位不产生精度。** 精度来自**渠道**（识别 / 推算），不来自刻度：推算出来的敌人位置是**格级**的（[状态层/敌方单位](../状态层/敌方单位.md)），所以那个事件的时刻误差是 `1 格 ÷ 速度`。**连续格坐标是表达形式，不是精度来源**——写成小数不会让它变准；
- **不用像素**：格是 AI 全部决策的单位；换算本来免费（投影参数在资产里），AI 付的是理解成本不是换算成本。像素只在调试与 ROI 追溯里出现；
- **一格多物因此天然可区分**（小数不同），"跨在两格之间算哪格"不再需要回答；
- 像素与格坐标**在类型上要分得开**——别让一个 `(float, float)` 既能当格又能当像素。

**区间是一套标量形态**，两端各自可开放。它要提供两件操作——**下界 / 上界与它共用这一套**，§1 的三种载荷就是它的三个具名形态，**没有独立的"标量区间"类型**：

| 操作 | 用途 |
| --- | --- |
| **包含** | 区间 ⊇ 点 / 区间 ⊇ 区间——判断"哪一次读数更强"、"降级有没有发生" |
| **相交** | 两个区间是否可能指同一个值 |

### 位置的"不确定"：一个二维区域（用户裁定；**修正过一次**）

**先说改错的那一次**：曾写成"路线参数上的区间"，理由是"漂移沿路线方向、横向几乎不偏"。**那个前提不成立**——路线资产是**格级的名义路径**，怪**不走正中、拐弯不直角**，被位移之后还会**重走一条新的最短路径**。**路径本身就不确定**，所以横向也有一份不确定。

于是位置的形态是**二维区域**：点 + 不确定半径（或盒）。它是 `locate` 原语的答案（[视觉层/原语.md](../视觉层/原语.md)），并且**是 §1 载荷词表里的第六种**（用户裁定）。**位置字段的载荷是它，距离字段的载荷是区间 / 下界 / 上界**——两者同级，一个是空间上的精度，一个是标量上的精度。

- **"沿路还有多远"是一次算，不是字段的形态**——把那个区域**投影到名义路径**上就有了（D8 问的正是它）。**这样形态才能撑住"连路径都不知道"的情形**，而路线参数区间撑不住；
- 位置本来也不只用于"还有多远"：D9 / D10 问的是"**哪儿有怪**"，而**阻挡的几何判定**更要二维。

### 区间进入条件判定 → 结果是三值

位置是区间时，「敌人到第 3 格」的答案**不是真假二值**，而是**一定真 / 一定假 / 判不了**。

- **这一层定"结果是三值"**（技术上是区间与点求交的三种结果）；
- **"判不了怎么办"已经定了**（[控制层/暂停条件](../控制层/暂停条件.md) §4）：**判不了 ≠ 成立**；每一段都**必填时限**，到点立即暂停，超时后如实报是"**确定不成立**"还是"**从未确定成立**"；
- **为什么现在就要说**：控制层写条件表达式时若默认二值，**"不确定"会被静默当成"否"**——那是零假事实在条件侧的破口。

### 归一化画布：就是捕获分辨率本身，不缩放

概念 §5.4 第 1 条要求"所有识别压到一块归一化画布上，坐标只以该画布为单位；不合规的分辨率直接报错"。**那块画布的尺寸 = 捕获分辨率本身**（用户裁定）——**不做缩放**。

- **为什么不取一个固定尺寸**（比如别家用的 1280×720）：缩放会引入插值误差，而这条链的判据是颜色与统计量、置信度是要报出去的；更麻烦的是它让"不吻合即拒绝"变复杂——**先缩放再拒绝，等于已经适配过了**；
- **代价说清楚**：换一台设备，全部 ROI 与投影一起重来。这正是"定死运行环境"的意思，不是遗漏；
- 画布尺寸进**前提头**（[时序层](../时序层.md) §3），不吻合即拒绝执行。

### 投影

`格坐标 ↔ 像素` 映射的参数**宿主是地形资产**（[状态层/地形](../状态层/地形.md)），但**有两套**：常速一套、慢放一套（慢放时地图右移倾斜，[控制层](../控制层/时间态.md)）。这一层定义映射的**类型**，值在资产里。

**投影类型自带「视图」标识**（用户裁定；**措辞修正过一次**）。那一维叫**视图**（常速 / 慢放，**两值**）——[难例采集](../采集与验收/难例采集.md) §1 用的就是这个词，那里还说"视图那一维不能省"。

> **早先写作"选错之后类型拦得住"，那句话过头了。** 与 §3 同构的只有**"值自带它的单位"**这一半：投影自带视图，所以**调用方不必记得自己在哪一套里**。另一半不一样——§3 混淆的是两个**值**，投影混淆的是两套**配置**，而"该用哪一套"是个**运行期状态**（快照页眉知道），**两个类型也拦不住**。所以落点是**调用点的一次断言**（`Projection.require(view)`），不是类型系统。

**视图与时间态的关系**：**视图 = 时间态去掉「暂停」**。两个类型都留着，因为**类型不该允许不存在的取值**——拿三值的时间态去标投影，等于允许"暂停投影"这种东西存在；那是"让不知道没法伪装成知道"的同一条纪律。

### UI 布局常量：一张「名字 → 像素矩形」的表

设备层与视觉层都要读界面上那些固定矩形（费用读数区 · 备战席 · 按钮……），而两者**互不 import**（[代码结构](../代码结构.md) 规则一）。所以这些常量**住在这一层**：类型与值都在这里（用户裁定，[端口与错误](端口与错误.md) §5）。

| 字段 | 是什么 |
| --- | --- |
| `rects` | 名字 → 像素矩形 的表（只读） |

- **它不在资产端口里**：它不是生成物、不进资产库，也不需要"换一套"或懒取——它是**常量**；
- **坐标是绝对像素**，与上一节同一条纪律：**不缩放、不归一化**。所以它跟画布一起定死在这台设备的分辨率上（"换一台设备，全部 ROI 与投影一起重来"）；
- **形状是表，不是具名字段**：键是名字（非空字符串），值是像素矩形。**名字有哪些不在这里定**——那是视觉层与状态层的事（[README](README.md) 的分界线表）。先定字段名，等于替那些层发明命名；
- **标量不进这张表**（**T5 定**，它是第一个标量需求撞出来的）：值只能是**像素矩形**，所以"卡距"这类标量塞进来只能塞成一个**退化矩形**——那是假事实。**标量住用它的那一层自己的常量**（第一个实例：备战席卡距住[设备层](../设备层.md)，而这张表里只放"最右那张卡"这一个矩形）；
- **交出去之后谁也不能改一个格子**：它是常量，不是一张谁都能写的草稿；
- **留一条后路**：名字定下来之后，要不要升格成具名字段（那样能检查"缺了哪个矩形"），**留到填值时再看**。

### 像素矩形：角 + 宽高

ROI 与 UI 常量的形状。四个数是 **x / y / 宽 / 高**，**不是 left / top / right / bottom**——后者把四个数里塞进两个冗余约束，更容易写出自相矛盾的矩形。**宽高必须为正**。

**原点与朝向不在这层定**（左上还是左下、y 向上还是向下）——那是视觉层与资产的事。这一层只管"它是一个矩形"。
