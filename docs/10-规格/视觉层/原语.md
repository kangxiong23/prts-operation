# 原语

> 状态：讨论中 ｜ **七条已立**（`exists` / `locate` / `measure` / `classify` / `count` / `heading` / `event_time`）；「分类的多候选」按**已知破口**记，见 §5

对应代码：`src/ark/engine/vision/`。

## 它是什么

**原语回答「问什么」。** 它是[字段条目](../状态层/README.md)引用的那一层——字段说"我要问什么"，编排的环说"用哪个方法去问"。

| 层 | 回答什么 | 有几条 | 谁引用它 |
| --- | --- | --- | --- |
| **原语** | **问什么** | **七条**（本文件） | **字段条目** |
| **方法** | **怎么做到** | 多，且允许往上增补（[识别方法.md](识别方法.md)） | **编排的环** |

**是 1:N，这就是原语存在的全部理由**：同一个问法可以换做法——费用数字今天走逐字模板，明天字体变了就换一种匹配——**字段条目一个字都不用改**。

- **结果的形状**（`{矩形, 分数, 载荷}` · 单数 · 说不出"未采样"）与**载荷词表**（精确 / 区间 / 下界 / 上界 / 未知）都由[契约层](../契约层.md) §1 定，**本文件不重复**；
- 本文件只说**每种原语允许用其中哪几个**。

## 1 七条

| 原语 | 问什么 | 允许的载荷 |
| --- | --- | --- |
| `exists` | **在不在** | 精确(有/无) · 未知 |
| `locate` | **在哪** | **二维区域**（[契约层](../契约层.md) §2）· 未知 |
| `measure` | **是多少** | 精确 · 区间 · 下界 · 上界 · 未知 |
| `classify` | **是哪一种** | 精确(标签) · 未知 |
| `count` | **有几个** | 精确 · **下界** · 区间 · 未知 |
| `heading` | **朝哪** | 精确(四方位) · 未知 |
| `event_time` | **什么时候** | 精确 · 区间 · 下界 · 未知 |

**「允许的载荷」这一列是本文件真正的产出物。** 它决定字段条目的「允许的形态」一栏，而且**与方法无关**：`exists` 永远给不出"半个存在"，换什么做法都一样。

**哪几个方法答哪个原语 → 见[识别方法.md](识别方法.md) 的「答哪个原语」列。**

几条边界：

- **`exists` 与 `locate` 是两条，不是一条。** 结果里虽然永远带矩形（[契约层](../契约层.md) §1），但两者的**判据不同**——`exists` 比的是分数阈值，`locate` 比的是位置精度。同一批方法答它们两个。
- **`count` 与 `measure` 是两条。** 区别不在"都是数"，在**诚实答案的默认形态**：`count` 数不清时**天生就该给下界**（[状态层/敌方单位](../状态层/敌方单位.md) 的"数不清是常态"），`measure` 读不准时默认给区间或未知。
- **`heading` 只有四个方位**（上下左右，不含斜向，[设备层](../设备层.md) §2）。角度是方法的中间量，不是原语的答案。
- **`locate` 是唯一一个答案形状不在标量载荷词表里的**——它是**二维区域**，出处是[契约层](../契约层.md) §2，不是本节。见 §6 第一条。

## 2 一行只记三件事

```
原语名（ASCII snake_case） · 问什么 · 允许的载荷
```

**单边双边 / 副作用 / 时间态 / 资产依赖 四样不在这里**，因为**它们是方法的性质，而且随做法变**：

| 性质 | 同一个原语内部会不会变 | 例 |
| --- | --- | --- |
| **资产依赖** | **会** | `measure` 底下：亮区比例不要资产，逐字小模板要字形表 |
| **误差单边 / 双边** | **会** | `measure` 底下：亮区比例被遮挡读低（单边），逐字模板逐位歧义（双边） |
| **副作用** | 会 | 只有"点开技能详情"那一类有（[识别方法.md](识别方法.md)） |
| **时间态** | 会 | 动画状态分类要连续帧，别的不需要 |

四样的**正文**在[识别方法.md](识别方法.md)，**怎么沿编排传播**在[字段编排](../状态层/字段编排.md) §8。本文件不再列一遍——**列了就是三处写同一件事**。

**原语名守 ASCII snake_case**，理由与算子相同（[接口层/算子清单](../接口层/算子清单.md)）：它是字段条目要引用的接口名，**改名等于改接口**。

## 3 引用链

```
字段条目 ──引用──▶ 原语（问什么）
                     │
                     └──候选──▶ 方法（怎么做到）──选定──▶ 编排的环
```

于是[状态层](../状态层/README.md)要的那条**引用完整性检查**有三个方向可查：

| 查什么 | 输入 |
| --- | --- |
| 字段条目里的原语名**存不存在** | 本文件 §1 那张表 |
| 本文件里每个原语**有没有字段在用** | 字段表 + 本文件（没有在用的标「暂无字段」） |
| 某个原语的**候选做法全没了** | [识别方法.md](识别方法.md) 的「答哪个原语」列 |

## 4 只收 A、B 两族

**C 族（算 / 记）的方法不是原语。** 理由是一条硬性质：[契约层](../契约层.md) §1 定**原语必有分数，而置信度只属于"读"**。C 族没有分数，收进来这条就破了。

- C 族的「问什么」**方法名自己就说清了**——`几何判定` 就是问"谁在范围内"，`时间推算` 就是问"还剩多久"；
- 它们**没有多做法**，所以不需要原语这层间接（1:N 里的 N 是 1，间接没有收益）；
- **代价要认**：算类与记类的字段条目**没有可引用的原语**，它们引用的是"输入字段 + 规则"。

## 5 已知破口：分类的多候选没有形态

[卷积分类的失效模式](识别方法.md)写着"两个类型都中等分 → 挑错一个（双边）"。而[契约层](../契约层.md) §1 的载荷里**没有"候选集"**，于是只剩两条路：

| 做法 | 后果 |
| --- | --- |
| 挑一个 | **双边**——正是假事实的入口 |
| 报未知 | 丢掉一半信息（"有东西，我不知道它是什么"） |

**用户裁定：不加候选集形态，按已知破口记。** 加形态等于给"猜"开一个门，而这一层的验收判据是"让不知道没法被伪装成知道"（[契约层](../契约层.md)）。所以选**报未知**，代价是分类这一侧的信息量比理想少。

## 6 尚未定

- **`locate` 的答案形状算不算一种载荷**：[契约层](../契约层.md) §2 的二维区域与 §1 的**标量**载荷词表不是一回事（词表里只有精确 / 区间 / 下界 / 上界 / 未知，而"区间"是标量区间）。它要不要作为第六种载荷进词表，**归契约层定**，本文件只指向 §2。
- **`count` 要不要并进 `measure`**：现在分开，判据是"诚实答案的默认形态"（§1）。若这条判据在实践中站不住，就并。
- **`measure` 的下界 / 上界由谁决定**：现在写在字段的降级策略里（[状态层](../状态层/README.md) G1 的单调性那条），原语只负责"允许"。
- **「暂无字段」要不要真列出来**：引用完整性检查需要它，但现在还没有原语处于这个状态。
