## 1. 要读的东西都画在图层最上层

实例：[战斗示例图——血条和技力条展示.jpg](../../../tests/示例图片/战斗示例图——血条和技力条展示.jpg)（一张**故意截出来的难例**：干员被粉色特效整片包裹）。

| 元素 | 含义 |
| --- | --- |
| **蓝条** | 血条 |
| **绿条** | 技力条，充能中 |
| **橙条** | 技力条，技能**生效中**——显示的是"还剩多久结束" |
| **橙条 + 一列竖线分格** | **弹药类**技能：格数 = 总弹药数 |
| **黄色菱形（内有黑色爆炸形）** | **正下方那个干员技能可手动释放**（出现条件见 §3） |
| **多充能技能的层数指示物** | 可充能多次的技能，场上有一个指示物显示当前层数（实测见过 **2 层**）—— **它的样子与位置还没记**：T4.1 只从帧差看出它在动（[时间基](../../30-专题/时间基.md) §3.5） |

**暂停态下这三样仍在动**（用户确认，T4.1 撞到）：暂停时**整屏不是静止的** —— 实测三处动画，两处是"可手动释放"的黄菱形、一处是多充能技能的层数提示。三处都**小、都好认**。**推论：做背景减法时这一片会变成噪声**（[控制层/识别时机](../控制层/识别时机.md) §4 的灰罩按层）。

**永续类技能特殊**：它的条**一直是橙色**（因为没有结束时刻，条一直满）。所以永续技能读不出"还剩多久"，但**读得出"正在生效"**。

**最大的推论：特效遮挡这道最难的题，对我方干员不存在。**

概念文档 §5.4 为"保护罩把干员整个包住"准备了一整套手段（从原图取掩码、只匹配没被盖住的部分）。而**要读的东西全部画在特效之上**，所以这套手段在我方干员这里用不上。

**能挡住条的只有两样**（用户给的图层事实）：**别的条**（比如怪的）与**黄色菱形**。特效、干员贴图都在条**下面** —— 所以"条被特效染了色"这种事**不存在**。读到一根颜色对不上的条，**先怀疑取区里不止一根条**（格里有好几根、或者条只截了一部分），**不许**先怀疑颜色判据；那一档按"很难判准"处理 → **报未采样**，不许拿一个下界或精确值凑。**反过来是另一件事**：条**看得见**、只是**空的**，那不叫未采样 —— 空就是 **0**；颜色判不出族时落「认得出有东西、但读不准」那一族。**「看不到」与「看到且为空」必须分开落**（用户裁定）。**取区里不止一根条还有更糟的一档**：紧挨着时，**左邻的填充会被当成本条自己的** —— 于是**干员没了、那一格却读出一个值**（**存在性判反**）。见 §5。

**空条是有痕迹的**（用户给的画面事实）：技力条**空了**不等于"什么都没有"—— 它会在那一格留下一条**条形变暗区**，所以**条的内外亮度是有落差的**；而且**空轨道是半透明的，只把背景压暗一点点** —— 落差**小而不过头**；被**不透明**的东西压住时暗得多（甚至会反过来，条内比条外**亮**），所以那一档的判据是「**有落差、而且落差不过头**」这一对，不是"落差够大就行"。而条的位置与形状是**已知**的：它就**紧贴在血条下面**（同样的横向范围），位置由部署记录给（§4）——**不靠「看得见血条」**。**生命极低（例如只剩 1 点）时可以一个血条像素都没有，而人还活着**，所以**「看不到条」不等于「干员死了」**。于是"**条在、只是空了**"与"**条被完全压住**"这两件事**分得开** —— 前者有那道落差，后者没有。判据要用**相对的量**（内外之差），**不要画绝对亮度线**（[备战席](备战席.md) 那条教训：绝对亮度会把真值说反）。**抗锯齿**会把边缘那一两列混色，别把边缘本身算进"内"或"外"。

**身份也不靠识别**：我们知道自己下了谁、下在哪（§5.5 说的"答案是免费的"）。识别只需要回答**"它还在不在、状态如何"**。

## 2. 弹药技：不数格子，读比例

那个 32 发弹药的实例里，橙条被分成 32 个小格，**肉眼几乎数不清**。

但这里根本不该去数：

- **总格数是数据库里的已知量**（技能描述写了 32 发）；
- 所以只读**亮区占总长的比例**，乘总格数就是剩余；
- 比例是统计量，**正是 §5.4 定的主判据**；数格子是逐个实例计数，既难又不必要；
- 分界模糊时**给区间或下界**（"至少 N 发"），而不是猜一个精确数。

## 3. "可释放"是一个可以单独搜的图标

那个黄色菱形挂在干员**上方**，**即使干员本体几乎没露出自己的像素也照样在**。

**但它的出现条件比"技力满"更窄**：

> **只有"手动触发"的技能 且 技力满**才显示这个菱形。

所以：

- 绿条满了却没有菱形 → **不是**"可以放但没放"，而是这条技能**不由我们放**（自动触发 / 被动），或者还差别的条件（例如玛露西尔还要求 35 点魔力）；
- 不要把这个观测往"它忘了放技能"上解读。

于是"技能好没好"从**读数值**降级成**找一个图标在不在**。

**与 MAA 的取舍差异**：它把这件事做成"钉在**格子中心上方**的一个 64×64 小框"里的分类——省算力，但要求格子坐标准。我们改成"**在干员邻域搜索这个图标**"——更稳、更贵，且不要求坐标准。

## 4. 位置校验：本体不靠识别，但可以被识别校验

**干员的位置来自部署记录**（[状态层/我方干员.md](../状态层/我方干员.md)），不靠识别。但推拉类位移会**悄悄**让记录失同步，所以它需要一次**校验**——用的就是敌方块那条主通道：

**判据**：干净关卡帧差分里，**记录的格上应该有一团变化像素**。

读这一团时的三条注意：

1. **用记录的格开宽容窗口**去搜这一团（和血条 / 技力条 / 菱形同一套坐标精度思路）：窗口吸收偏移**只吸收像素级**偏移，**整格错位吸收不了**；而且**它只保到"丢读数"，不保证读数不变**（[视觉层/README](README.md) §坐标精度）；
2. **看不到这一团 = 失同步**——这是**肯定证据的缺失**，可以直接上报，不需要防抖；
3. **被特效包住时这一团会被切碎**：血条 / 技力条 / 黄菱形在特效之上（§1），但**本体不在**——所以此时只能确认"这附近有变化"，**不能精确定位**。

**阻挡中的情形要注意**：干员格上同时有敌人时，这一团是**干员与敌人混在一起**的，分不开 → 别在那里下"位置一定没变"的结论。

## 5. 左缘怎么定：邻条的填充不算本条的

**画面事实**：同一行相邻两格时，两根条挨得**比条宽还近**（这一簇实测 **138 / 139**，条宽 146）—— 所以**左邻的填充会铺到本条左缘的左面 1 列**，中间只隔一道抗锯齿接缝。

**判据**：左缘的候选**只认「亮段的起点」**，而且扫区最左那一列还要过一道门 —— **要连出够长的一段**才算本条的填充（**那两处的列数见代码**）。两条链共用这一条（§6.0 规矩 2）。

**为什么必须这么做**：不设这一条，左邻的填充就会被当成本条自己的。后果不是「读数差几个百分点」，而是**存在性判反** —— 干员已经没了，那一格还会读出一个**有值**的血量（精确 / 区间 / 下界都出现过；实测抹掉本条之后读出 **7.5%–13.7%**）。这是零假事实最怕的方向：值看着正常，通用层那三条信号（置信度低 / 形态变粗 / 三态切换）**一条都不响**。方向是单向的：候选只看本条左缘的**左**边，所以**只有左邻能顶掉你，右邻不能**。

**修完之后的代价（要记住）**：那道门是按「**最长连续亮段**」卡的，所以锚点偏到 **+12 px** 那一档里，**填充短的那些块会丢读数**（基准集 16 帧里实测 **6 块**丢；满条与接近满条的 10 块靠那道门救回来）。**「丢读数」可以接受，「给错值」不行**（[D-全局-33](../../20-决策记录/全局.md)）。

**不许做成「检测到邻条就报未采样」**：那样会**误伤** —— 实测难例批里有 **5 块**的左邻填充都伸进了容差带，而其中一块是**满条**、另两块都有**读得出而且正确**的读数。本条的落法是「**不让邻条的列进来**」，不是「见到邻条就放弃」。

**死活这一层不下结论**：它只能说「这一帧没有证据」（§6 后面那几支）。

## 6. 判定顺序与落档（血条与技力条**分开**列）

**两条链有四处不对称，所以不许合起来讲**：

| | 血条 | 技力条 |
| --- | --- | --- |
| **位置从哪来** | 记下来的位置（§4） | **今天仍是从血条推出来的**（同一条 UI 的两截、左缘一个像素不差）→ **血条一瞎，技力跟着瞎**（规矩 1a 落地后消失） |
| **颜色几族** | 一族（蓝） | 三族（绿 / 橙 / 两族都不是）→ 只有它有「认得出、但读不准」那一档 |
| **被压住时落法** | **下界**（那一小截之前那一截） | **两层**：被别的条压住（缝之后还是本条的填充色）⇒ **下界**；断口之后**自证不是本条轨道**（压在 UI 上的图标）⇒ **未采样** |
| **「空」这一档** | 靠**条上方那一条带**判（它下面紧贴技力条），只当**二值**判据 → 空轨道 **0** | 靠**条两条长边**判（横向），一端量不出就**未采样** → 空轨道 → 填充 **0** + 含义**一律未知** |

### 6.0 顺序：两条链共用的四条硬规矩

1. **前提 1a：行由记录给**（§4）。**今天没落** —— 行还是靠「哪一行最蓝」自己挑（§8）。
2. **前提 1b：左缘不给邻条用** —— 候选只认「亮段的起点」+ 一道最小连长的门（正文见 §5）。
3. **先数填充，最后才问轨道。** 因为**满条时轨道被填充盖住、根本看不见** —— 所以「轨道在不在」只能在「填充认不出族」时才问。**这两步换过来，结论就变。**
4. **「外面」要用得上，那一侧的落差才作数**：一端量不出 ⇒ 判据给「不是空轨道」⇒ **未采样**，不许只拿另一缘一票。⚠ 它**不是**「检测到邻条就报未采样」（误伤见 §5）。

### 6.1 血条

| 序 | 条件（画面上什么样） | 真值 | **应当落成** | 今天链怎么落 |
| --- | --- | --- | --- | --- |
| **if** | 本条这一条上有**黄菱形**压着 | 条在、读数不可信 | **未采样**（用户裁定） | **仍未接进链**（`find_ready_diamond` 没被这两条链调用）—— `r01_12_01` 报的是区间 0.2534–0.2603 |
| **elif** | 认得出蓝 + 中间或右端**有一小截不是本条的填充色**（被压住 / 右端是外来的） | 活着、读数不可信 | **下界**（那一小截之前那一截） | 一致（`r01_01_05` = 下界 0.3973） |
| **elif** | 认得出蓝 + 边界渐变 | 活着 | **区间** | 一致 |
| **elif** | 认得出蓝 + 边界干净 | 活着 | **精确** | 一致 |
| **elif** | **一个蓝像素都没有** + **条上方那一条带**量出来落在半透明该有的一段里（空轨道） | **活着、生命极低**（例如只剩 1 点） | **0**（用户裁定） | **已落地**（在到得了的那一档里）；今天只有一条**合成用例**钉它，**真帧一条都没有** |
| **else** | **一个蓝像素都没有** + 那条带**不是空轨道**（落差过头 / 反过来 / 量不出） | 人没了，或者有东西整体压着 | **未采样**；死活这一层不下结论 | 一致（同一支里落成「不是空轨道」） |

**到得了的范围**：这一支要**行定位得到、左缘找不到**（例如邻条的尾巴凑够了最小列数）。**「连行都定位不到」那一档要等规矩 1a** —— 生命极低时正是那一档。

### 6.2 技力条（含弹药）

| 序 | 条件（画面上什么样） | 真值 | **应当落成** | 今天链怎么落 |
| --- | --- | --- | --- | --- |
| **if** | 本条这一条上有**黄菱形**压着 | 条在、读数不可信 | **未采样**（用户裁定） | **仍未接进链** —— `r01_12_01` 报的是下界 0.4932 / 生效中 |
| **elif** | 认得出绿 / 橙 + **一条竖线分格**（实测 3–4 像素宽） | 弹药类；格数 = 总弹药 | **只报亮区比例**（分界模糊 → 下界），**不数格子** | 一致（§2） |
| **elif** | 认得出绿 / 橙 + 有一小截**不是本条的填充色**，但**缝之后还是本条的填充色** | 充能中 / 生效中；条在、读数不可信 | **下界** | 一致（`r01_04_03` = 下界 138/146） |
| **elif** | 认得出绿 / 橙 + **断口之后自证不是本条的轨道**（量出来那个量两个方向都不明显、对照门过得去） | 条在、读数不可信（压在 UI 上的图标） | **下界 + 含义未采样** | 一致（`r01_01_06`：断口 46 列） |
| **elif** | 认得出绿 / 橙 + 边界渐变 | 充能中（绿）/ 生效中（橙） | **区间** | 一致 |
| **elif** | 认得出绿 / 橙 + 边界干净 | 充能中（绿）/ 生效中（橙） | **精确** | 一致 |
| **elif** | **认不出族** + 横向那一端**量不出来**（那一侧没有本条的背景） | — | **未采样**（这一帧没有证据） | 一致（一端量不出 ⇒ 判据给「不是空轨道」） |
| **elif** | **认不出族** + 落差落在半透明该有的一段里（空轨道） | **条在、只是空了**（充能 0 / 弹药 0，人活着） | 填充 **0** + 含义**一律未知** | 一致（`r01_06_04`） |
| **else** | **认不出族** + 落差**过头 / 反过来 / 量不出** | 条在、读数不可信（有东西压在 UI 上）；或者条不在 | **未采样** | 一致（`r01_01_05` 走横向：左缘落差过头） |

**注 1（两条链的关系）**：技力条的**位置**今天仍从血条推，所以血条读不出时技力连自己的状态机都进不去；规矩 1a / 1b 落地后这一条自动消失。

**注 2（技力填 0 时的含义）**：填 0 时那一行透出来的是**背景**，不是这条技能的颜色 —— **含义一律交未知**，不许因为背景恰好是绿 / 橙就读成「充能中 / 生效中」（那是假事实）。

**注 3（极低填充）**：**能数出来就按数出来的算**（数出一列就是 1/146）；**一个填充像素都数不出**才落 **0**。所以「列数不够就报未采样」这条**要放开**（今天 1–3 列落的是未采样）。**「数不出」= 这一列判不出是不是本条的填充色。**

## 7. 条的像素账（量出来的画面事实）

判据参数住代码（括号里给落地用的常量名），这里只记**画面长什么样**：

- **轨道是一层半透明压暗**：灰轨道 **α ≈ 0.35**、色调接近中性；弹药那一档的橙板压得更狠（**α ≈ 0.55**）、色调偏橙。**技能关与技能开是同一套** —— 开不开技能不改变轨道本身。
- **条下有一道阴影**，按「离条顶多少行」递减（活帧 ÷ 干净帧）：**+18 行 0.74–0.88** / +19 0.87–0.93 / +20 0.92–0.97 / +21 0.96–1.00 / +22 0.98–1.03 / **+23 行起回到 1.00**。所以量「条外」要**按相对条顶的偏移修正**，不能直接拿下面的像素当底。
- **两件仪器各管一段，不许互相顶班**：**横向**（量条两条长边的「条内比条外暗」）**只在「看不到填充」时说话** —— 有填充的条上它量的是噪声（真值批 13 块里 12 块量成「过低」）；**纵向**（借条下第 10 行那块地形当底）**只在「认得出族 + 有断口」时说话**。
- **血条只在上方有背景可用**（它下面紧贴技力条），所以那一支**只当二值判据、不给比例**：31 块没填满的血条上实测，整条空的那些块落在 **+0.30…+0.44**、同批自控 **+0.05**，而**一半以上**的块量成**负数**（−0.25…−3.4）—— 条上方那块地形跟条背后那块**不是一块**。

## 8. 未落地与未决

**未落地**：① **黄菱形压在条上 → 未采样**（两张表的第 1 行）；② **规矩 1a（行由记录给）**；③ **1–3 列照报**（注 3）。

**未决**：① 纵向那件仪器要不要认横向的「过头 / 反过来」（要让标签与落法一致就得改判据，得重跑四批看有没有别的块被翻）；② 左缘那道门的阈值 —— 放松能多救回偏 +12 px 的部分填充条，代价是「左邻的尾巴」更容易骗过它（实测间距 138 / 139，还剩余量）。
