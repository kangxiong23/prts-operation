## 这一侧现在负责什么：纠偏，不是提供位置

[状态层/敌方单位.md](../状态层/敌方单位.md) 已把**敌人位置的主通道翻成「推算」**（[路线资产](../资产生成器/地形与关卡资产/路线.md) 的格序列 + 停留点 + 移动速度 + 我们自己造成的减速 / 阻挡 → 任意时刻算得出它在哪）。分工因此变了：

| | 原来 | 现在 |
| --- | --- | --- |
| 位置 | 识别**提供** | 识别**纠偏**：推算的位置对不对得上画面 |
| 差分掩码 | 位置的来源 | "**该有东西的地方有没有东西**"的证据 |

**所以下面那个「主通道」要读成"视觉侧的主通道"，不是"位置的主通道"。** 它仍然管三件事：

1. **纠偏**——推算说"这一带有 N 个"，画面回答对不对。信号稀疏，但它**只需要回答对不对**；
2. **认类型**——推算给不出"这只是哪一种"（路线资产只能把候选缩到几种），这条仍然靠卷积；
3. **画面干净时的逐个体检测**——推不动的场合（机制召唤物、被位移、机制杀）靠它兜底。

**这反而是好事**：原来"位置靠看"要同时面对怪海、特效、满血无血条三件事；现在**"数不清"不再致命**——"有几个"已经被[不变量 I4](../状态层/README.md) 改成了对账问题（见下方「第 8 步」），画面只需要当纠偏。

## 三条正交的轴，别压成一条

「敌人看不清」其实是三件**互不相关**的事：

| 轴 | 影响什么 | 谁管 |
| --- | --- | --- |
| **特效遮挡** | **单个**字段的置信度——**一个怪也能被盖住** | 字段级置信度（已有机制） |
| **怪挤怪重叠** | **可分辨性分档**（这几个能不能分开） | 本文件的分档判据 |
| **满血 / 受伤** | **血条在不在** | 血条法的可用性 |

**第一版把它们压成了一条**（"密集 / 怪海"），结果**所有判据都押在血条上**——而血条是最会消失的那个信号。

**而且重叠不是怪海专属**：永控 / 聚怪是合约里弥补 dps 的常规手段，**两三只重叠就是常态** → 分档判定要**按区域常开**，不能做成"怪海时才启用"的特例。

## 主通道：干净关卡帧差分

**背景是一份「干净关卡帧」资产，不是本局的开局帧。**

- 来源：**零词条合约开局无敌人 → 开局那一帧就是干净帧**；万一某关有初始敌人，由人自己造一个干净环境、以那一帧为准。取法与打戳见[背景帧](../资产生成器/背景帧.md)；
- **它不识别地形语义**，只做减法 → 与 [D-全局-09](../../20-决策记录/全局.md) 排除的"从像素检测地形"**不冲突**；美术换皮也不伤它（背景帧跟着换版本）；
- 打戳：**关卡 × 相机参数（视图）× 游戏版本 × 渲染设置**。**相机在同一个视图内不动**（用户确认：平移只发生在切视图的时候，即进入慢放 / 技能详情）→ 同一个视图内**不用配准**；**但视图有两套**（常速 / 慢放），而识别多数发生在**慢放 + 详情面板**下（[控制层/识别时机](../控制层/识别时机.md) §4）→ **慢放那一套背景帧同样要备一份**。场地美术**没有常驻动画**（用户确认）→ 背景是静的。

```
单位掩码 = |当前帧 − 干净关卡帧| > 阈值
```

**只在战场区域做**（HUD / 备战席排除——它们每帧都在变），**降采样做粗差分 → 候选区再细化**。

**为什么不用本局的开局帧**：部分合约词条会让**初生敌**开局就在场上，它们在背景里 → "看上去没变化" → **有漏检风险**。用干净帧，初生敌照常出现在差分里。

## 剔特效：靠我们自己的账，不靠图像

**特效基本来自技能，而我们知道自己什么时候、给谁、放了什么** → 技能范围是数据库里的形状 → **反投影到格上**，划掉预期的特效区域。这就是 G3 那条「**我们自己造成的，走记 / 算**」。

图像侧再叠一层**时间统计**兜底：**特效帧间闪烁，单位位置稳定** → 按时间看每个像素（中值 / 方差），把"持续的"和"闪的"分开。

**两条都不需要卷积。**

## 再减掉我方干员

**干员位置我们本来就知道**（部署记录）→ 从掩码里减掉。

**但重叠处不强行分开**：那里我们本来就知道有干员，只要回答"**它旁边还有没有别的**" → 聚合 + 区间，见[状态层/快照.md](../状态层/快照.md) 的 ④b。

## 敌条那条链：读法（10-14 定稿）

**先写它服务什么**：它是「血量」那条字段的**画面通道**，用法是**反过来校验我们自己的伤害账**。伤害涉及的因素多，叠加索敌机制之后更容易漏；而画面上的敌条是**唯一**能说出"这笔账错了"的信号 —— 差一点点血那种局，账上是"没漏"，看见条才知道该补一刀，也就是**止损**。它**不提供位置**（位置走算）、**不认类型**（类型走数据库 + 路线资产）。

**读法（要求，不是做法）**：

- **在整张战场上一次筛完** —— 按色相 + 形状，**不做滑窗模板匹配**：敌条是一条纯色水平长条，为它把整张战场滑一遍没有道理（那是我方干员那两条的做法，它们的取区是"已知干员的上方邻域"）；
- 已经量到的画面事实（出处在 `data/probe/敌人血条图源盘点.md`，那是观察、**不是判据里的常量**）：**橙 ≈ `(218,106,53)` · 高 8 行 · 比我方条窄 · 下面压着一条近黑暗轨 · 贴在敌人脚下**；
- **我方的两根条要能排除掉**：它们是蓝的、而且位置是我们自己算的（[场上我方干员.md](场上我方干员.md) 那两条链已经会读）；
- 逐根候选报**填充比例**（0–1；换成血量是[状态层](../状态层/敌方单位.md) 的事），读法与我方血条同源（逐列比色 + 空轨判断），**遮挡时按「下界」降级** —— 与我方条那条链同一套降级纪律，不另立一套；
- **不抄我方条那两条线**：那是蓝条那一套的口径，空档与两条线在这一条上**重新量**。

**三个出口**（与我方条 / 菱形同款）：够高 ⇒ **在** · 够低 ⇒ **不在** · 中间 ⇒ **认不出**。**"认不出"不许并进"不在"** —— 并进去就是把满血谎报成受伤。

**语义边界（用户给的规矩）**：**血条显示 ⟺ 未满血**。所以"看不到条"就是**满血**（读出来的，不是推断，不需要"敌人不回血"这个前提）；反向**读不出**"它到底受没受过伤"（回满之后与从未受伤在画面上一样）。

**这一轮的坎：颜色不够。** 已经抓到两条硬负例 —— `data/precheck/live/shot26.png` 里那根 92 px 红块是**发光地形栏杆**，`screenshots/run-02/S5-0-0.png` 里那一堆红扁条是**土红栈道边**。所以判据**不许只靠"红扁条"**；这两张必须报「不在」，它们是这条链验收的骨头。

**真值口径**：

| 当什么用 | 素材 | 为什么是它 |
| --- | --- | --- |
| **不在**（敌人满血） | `data/precheck/cd/cd01.png` · `cd30.png` | 用户 10-14 裁定画面里那只深红四足的是**敌人**，且它**没有条** —— 这正是最缺的那一类：**有敌人 + 满血 + 没有条** |

**S8-3-4 那一根：真条，但整长量穿**（10-15）：`screenshots/run-02/S8-3-4.png` (756,910) 那 22 列填充是**恒色 (216,103,52) · 8 行 · 两端直边** —— 与夹具真值 `raw_a` 那根**逐列同一种东西** ⇒ **是真条**；而它的空轨那一趟沿**集装箱的橙边**走了 200 列（吃满 `MAX_BAR_COLUMNS`）⇒ **整长量不出来**。先前**「条在、比例认不出」这一档真帧为零**，就是它。

**叠在一起的条不要求数清**（用户裁定 10-14：**尽力而为，而不是一定要全识别出来**）—— 那是**信息本身不在画面上**。要求只有一条：**不许把分不开的报成"精确"** —— 分不开时**条数给「下界」（至少几根）**、**比例给下界或未采样**，分得开才给精确；而且**报出来的数必须真的是下界**（不许高报）。

**红族只有 boss**（用户 10-14）：红条的敌人**只有 boss 那一档** ⇒ 红族做**窄的**。用户同时给了区分手段：**必须认形状** —— "这一根是不是**长方形**"比颜色区分度更强（这样**红衣、红头发、红装饰就不容易混进来**）。落地为：红族 = boss 那种深红 + **矩形 / 内部均匀**那道门；这道门顺手也收掉橙族上那个"颜色从上到下渐变"的**地形木头**假阳性。

**"报出满血条"不许用降级盖住**（用户 10-14；把本节早先那条"报 1.0 ⇒ 未采样"**撤掉**）：满血本来就没有条，所以真读出"精确 1.0"只有两种可能 —— 那**根本不是一条**（假阳性），或者**整长算错了**。用户原话：**设计成未采样只是表面功夫，没意义**。所以：**1.0 照报**（怪只掉了一点点血、像素上确实没缩短时，报 1.0 就是合理的），而"画面上没有满血条却读出满血条"这件事要当**缺陷线索去追根因**。**降级只用来表达"真的不知道"，不能用来盖住"我错了"。**

**整长量得不干净，比例就不许给精确**（10-15 裁定）：一根条的整长 = 填充段 + 空轨，空轨那一趟有四种"不干净" —— **被切断**（缝底下还亮着）⇒ **下界** · **软尾**（边界落在几列渐变里）⇒ **区间** · **跨过回落**（先量到过轨道列、回落、又接上）⇒ **下界** · **量到上限**（走出 `MAX_BAR_COLUMNS` 还没到头）⇒ **未采样**。最后那一支的理由：量到上限说明那一趟**吃进了地形**，真整长**可能更长**（比例更小）也**可能本来就短**（比例更大），两个方向都开着 ⇒ 只报"条在"、比例报未采样。**不许把"量到上限"落成两端相等的区间** —— 那等于把"不知道"报成精确值（这一支现在还是退化区间，已开单）。比例**只在那一趟干净时**才给精确。

**报出来的高按量到的行数**（10-15 裁定）：小怪 8 行 · boss 红条 10 行 · `raw_b` 上那根 9 行；叠在一起那几帧会量到 9 行 —— 那是**量法**留下的不确定，不是判决变了（判决没翻）。

**这一版不做的**（写清边界，免得被读成"还没写完"）：

- **不做归属**（哪一根条属于哪一只敌人）：它要等"候选区 / 位置"那条前端，现在硬做只能靠猜；
- **不做逐个体血量**：没有归属就没有"这一只还剩多少"。

## 敌人血条：加分项，不是主通道

**10-14 补一句**：在"是不是**位置**的主通道"这个问法上它**仍然只是加分项**，但**它的用途已经提到更高一档** —— 它是**唯一**能反过来校验我们自己伤害账的信号（止损）。读法与真值口径见上一节。

敌人血条**确实存在**（用户确认），而且能量化区分：

| | 颜色 | 宽度 |
| --- | --- | --- |
| **我方干员** | 更偏**黄** | 较宽 |
| **小怪** | 更偏**红** | **窄** |
| **boss** | **红** | **宽** |

三者的**位置相近**（都贴在脚下），所以区分**只能靠色相 + 条宽**——方法落在[识别方法.md](识别方法.md) 的 A 族。

**但它只能加分**：**满血怪没有条**，而"一波刚压上来"恰恰是满血、也恰恰是 AI 最需要判断"要不要再加人"的时刻。

## 分档：能不能逐个分开，看「信号」，不看「个数」

| 档 | 判据（**任一条成立**即可，**矛盾时取保守**） | 输出 |
| --- | --- | --- |
| **① 可逐个体** | 每个个体的**轮廓连通区互不相接** | 逐个：位置 + 类型 + 血量 + 状态 |
| **② 可数但难分类** | 轮廓相接，但**仍有分离信号**：距离变换有"腰" / 血条可一一归属 / 连通区可数 | 精确个数 + 各自位置，类型可能未知 |
| **③ 不可数（一堆）** | 以上信号**全都没有** | **区域 + 区间 + "有一堆"** |

**为什么不按个数划**：同样 5 个敌人，站开的能逐个看清，挤在一起的看不出来。**个数的分界值拍不出来**——它依赖站位、体型与特效；而"**分离信号在不在**"是能从画面上判的。

**矛盾时取保守**：只要有一条信号说"分不开"，就报 **③**。"可数"是**精确主张**，而零假事实最怕假精确。

**具体阈值靠难例集标定**，不在这里拍数字。

## ③档给什么：多路下界 + 一条上界

**下界（有几路用几路）：**

1. **面积比**：`敌人色块像素数 ÷ 单怪色块像素数`。**遮挡只会让可见像素变少 → 这个商只会偏低 → 天然是下界**；混类型时用**最大体型**的单怪面积，取最保守；
2. **距离变换峰值数**：找轮廓上的"腰"，间接数个体；
3. **敌条条数**：有则用；满血时为零，**不影响主流程**。

**上界**：`敌人总数 − 已击杀数`（顶部 HUD 的权威读数，见[状态层/全局与HUD.md](../状态层/全局与HUD.md)）。**活着的敌人不可能超过它**，与画面无关。

输出：`区域 + 区间 [下界, 剩余敌人数] + 不可逐个体`。

## 卷积退回到它擅长的地方

| 问题 | 靠什么 | 要卷积吗 |
| --- | --- | --- |
| 有没有东西 / 在哪 | 干净关卡帧差分 + 时间统计 | **不用**（经典 CV） |
| 有几个（下界） | 面积比 / 距离变换 / 条数 | **不用** |
| **是什么（类型）** | **简单卷积** + 特征库 | **用，但只需简单** |

**不指望卷积扛计数**：调一个能力足够强的模型很花时间（用户判断），而"有几个"用差分 + 面积 + 距离变换就能给出**有方向的下界**。

## 单怪色块面积从哪来

它是**资产**：拿难例集里**明确只有一个敌人**的截图量出色块像素数，**按类型 / 体型分档**。大体型怪更大——跟椭圆逻辑范围随体型变大是同一件事。

## 把流程理一遍：从一帧到「一堆敌人」

**每一步都带"失败就怎么办"**——这就是零假事实在流程里的落法。

| 步 | 做什么 | 还要什么输入 | 输出 | 失败就怎么办 |
| --- | --- | --- | --- | --- |
| **0 要不要做** | 看识别时机 | AI 声明的字段 · 时间态 | 做 / 不做 | 不做 → 这一片敌人块沿用上次并标**旧值** |
| **1 取像** | 抓战场区一帧 | — | 一帧 | 取像失败 → 未采样 |
| **2 差分** | `\|当前帧 − 干净关卡帧\|` | **干净关卡帧资产** · 战场 ROI | 变化强度图 | **自检**：拿"本该静止的区域"（地图边缘装饰）看差分是否近零；不近零 → 判定**失配**，**整块放弃** |
| **3 剔特效** | 技能账反投影 + 时间统计 | 我们的技能账 · 数据库的范围形状 · 连续帧 | 单位候选掩码 | 帧数不够（刚进慢放）→ 只用先验剔除，**降置信度** |
| **4 减我方干员** | 已知位置 → 像素占位 | 部署记录 · 投影参数 | 敌人候选掩码 | 干员占位只能估 → 重叠处**不强行分**，记成"**这里有干员**" |
| **5 找区域** | 连通区 + 形态学去噪 | — | 候选区域列表 | 太碎 → 合并 / 丢弃；太大 → 正是③档 |
| **6 分档** | 连通区 / 距离变换峰 / 敌条归属 | — | 每区 ①②③ | **矛盾取保守**：一条说分不开就报③ |
| **7 按档产出** | ①逐个 ②可数 ③区间 | 单怪色块面积 · 血条 | 位置 / 个数 / 下界 | 面积资产还没有 → ③档下界**空转**（现在就是这个状态） |
| **8 与预期对账** | 见下（两件事） | 路线资产 · HUD 的已击杀与生命 | 收敛后的自洽估计 | 残差非零 → **冲突上报** |
| **9 组装 ④b** | 枚举个体 / 聚合兜底 / 阻挡位视图 | — | 快照的一块 | 每字段带三态 / 形态 / 置信度 |

### 第 8 步：两件事，都来自「账」而不是「看」

**（一）分类的候选集可以缩小。** **路线资产** + 游戏时间给出"**这一刻可能在场的那几种**"（**这个游戏没有"波次"这个概念**，所以不按波算、按时刻算）→ **简单卷积不必在全库上分类，只在这几种里挑**。这直接把最弱的一环（类型分类）的难度**降一个量级**。

**（二）"有几个"可以从识别问题变成对账问题**——它现在是不变量 **I4**：

```
总数 = 已击杀 + 漏掉 + 在场 + 未出场 + 残差
```

四项全是**可读或可算**的：

| 项 | 从哪来 |
| --- | --- |
| 总数 | HUD（或路线资产） |
| 已击杀 | HUD |
| **漏掉** | **初始生命 − 当前生命**（两个都是 HUD；初始生命由关卡 / 词条给定） |
| **未出场** | **路线资产 + 游戏时间** |
| **在场** | 上式的**余项**——算出来的 |

**残差就是自检**：它应该 ≈ 0；非零 → **冲突上报**（说明有我们没建模的机制，或某次读数错了）。这条关系**每次快照都能查，一次同时校验四个独立读数**——它已经是**不变量 I4**，编号在[状态层/README](../状态层/README.md) 的 G3。

**四个坑要说清：**

1. **口径不同**：召唤物**不计入**总数与已击杀，但它**在画面上** → 视觉掩码里的个数会**大于**"路线资产语义上的在场数"，差额可能就是召唤物或机制单位；
2. **"漏掉"依赖扣除数**：小怪扣 1，**boss 一次扣完** → 混合漏怪时这一项只能给**区间**；
3. **"未出场"依赖路线资产的准确性**（合约词条**可能多出几个怪**，它的覆盖层要跟上）→ 表不准，这一项就不准；
4. **机制杀 / 位移出图**这类没建模的消失方式，就落在**残差**里。

## 尚未定

- **战场区域的边界**：HUD / 备战席排除掉之后剩什么；
- **初生敌**要不要特殊处理（它的位置本来就可由词条与路线资产给出，未必需要画面）；
- **血条归属**的判据（条 → 个体的匹配规则）：**押后**（10-14），等"候选区 / 位置"那条前端；
- **单怪色块面积的分档口径**（按类型还是按体型）；
- **①②③ 的标定**：需要一小批人工标注的难例（就标"这一片能逐个看清吗"）；

- **③档的区间够不够用**：要真机拿几个怪海局试。
