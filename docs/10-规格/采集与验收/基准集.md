# 基准集

> 状态：讨论中 ｜ **格式 · 离线跑一帧这条路 · 冻结与版本**已定；素材来源与回归基线存哪待定

**采集与验收**的正文之一——职责、三层触发与跨层端口见 [README.md](README.md)；判据与仪表见[离线验收.md](离线验收.md)；难例怎么落盘见[难例采集.md](难例采集.md)。

## 1 它是什么

**一批帧 + 出处。**

它回答的是[开发路线](../../00-总览/开发路线.md) 段一那条判据：「这套识别**不看真机也能跑**，而且对着基准集逐帧对得上」。

**期望值不住这里。** 这一条是硬的：真值住 `tests/spec/`（规划者维护、**执行者不许读**），基准集里只有帧与"它从哪来"。理由与"取材与验收分开"是同一条——真值跟着帧走，「自己写自己测」就没有独立性了（[D-全局-17](../../20-决策记录/全局.md)）。

**难例不是它的唯一来源。** [难例采集](难例采集.md) §3 把基准集列为难例的一种用途，但基准集也可以是**一批顺手抓的常规帧**——费用那第一批就是。它要的是**冻结**，不是"难"。

## 2 一份基准集长什么样

**一个目录 = 一批。** 里面至少两样：

| | 放什么 |
| --- | --- |
| `index.json` | 这一批的清单（下面两张表） |
| `crops[].file` | 每条裁剪的 PNG，**原生像素、一个都不缩** |

`index.json` 的字段：

| 字段 | 必填 | 是什么 |
| --- | --- | --- |
| `version` | 是 | 这一批的版本号，**改了内容就 +1**——[难例采集](难例采集.md) §3 那条冻结纪律要能回答"基准是第几版" |
| `canvas` | 是 | 画布口径 `[宽, 高]`（[设备层](../设备层.md) §4） |
| `device` | 是 | 机型。**它是出处，不进任何判据** |
| `facts` | 否 | 录制的前提头，**现在只有一项 `orientation`**（字面值见[设备层](../设备层.md) §5）。**没有就是没有**——加载器不许补一个默认值。折成 `DeviceFacts` 是加载器的事，见下面那段 |
| `crops` | 是 | 每条的清单，见下表 |

`crops` 每条的字段：

| 字段 | 必填 | 是什么 |
| --- | --- | --- |
| `file` | 是 | 裁剪的 PNG，相对这一批的目录。**它的名字去掉扩展名就是这条的帧名**（`shot01.png` → `shot01`），**批内唯一** |
| `origin` | 是 | 裁剪左上角在画布上的 `[x, y]` |
| `size` | 是 | 裁剪的 `[宽, 高]` |
| `source` | 是 | 这份裁剪出自哪一帧（出处） |
| `source_sha256` | 是 | 那一帧的 sha256（出处，用来钉住"出自哪一帧"） |

**原点 + 尺寸必须落在画布内，含两端口径**：右缘 ≤ 宽 − 1、下缘 ≤ 高 − 1。写超了就是"含了一个不存在的像素"——这个坑规格自己踩过（[顶部HUD与数字](../视觉层/顶部HUD与数字.md) 的 `cost_panel` 右缘写到 2800）。

**前提头在清单里只记「画布装不下的那一项」**（T6 补）：清单的 `canvas` 就是录制时的分辨率，所以 `facts` 里只剩 `orientation`。**折成 `DeviceFacts` 是加载器的事**——`resolution` 取 `canvas`、`orientation` 取 `facts.orientation`，没有 `facts` 块就是 `None`。**设备层不许自己折**：让重放适配器去认"清单里那个键叫 `orientation`"，等于把离线那套文件格式塞进引擎（[代码结构](../代码结构.md) 规则三：引擎对外只认自己的语义）。所以 `BenchBatch.facts` 的类型是 **`DeviceFacts | None`**，不是那个映射。

**`orientation` 写字符串或整数都收，折成那个整数的十进制文本**（T6 补）：[设备层](../设备层.md) §5 说字面值是 `"0" "1" "2" "3"`（字符串），而设备报出来的本来就是整数，JSON 里写成 `1` 很自然——两种写法指向同一个字面值，没有歧义。**但值域不校验**：词表归设备（设备层 §5），将来报出别的值，记下来就是。

**`source` 与 `source_sha256` 只记不验**（T6 补）：它们是出处，而原帧住在 gitignored 的 `data/` 里、**可能早就不在本机了**，加载器无从校验。**写着一个哈希不等于核过它**——将来真要用它做核对，得先把原帧请进版本库，那是另一件事。

**批自己的额外字段可以有**（费用那一批多一个 `box`，是它裁剪窗口的公共范围），加载器不读它们。

**清单坏了就报错，不许就地修补**（T6 补）：缺必填字段 · 原点或尺寸越出画布 · 帧名重复 · 裁剪的实际尺寸与 `size` 不符 · 裁剪文件不在——**五条都是加载时拒绝**。理由就是上面那句"没有就是没有"：补一个默认值、把越出的那块裁到边上、按 PNG 的实际尺寸来，三种都是**替调用方编了一个它没读到的值**，而下游会拿那个值去取 ROI。**报什么错不管**（`ValueError` / `KeyError` / `FileNotFoundError` / 自己的异常都行），**只要不是"照样加载成功"**。

## 3 离线跑一帧这条路

```
基准集目录 → 加载器 → 一帧一帧的原始帧 → 重放适配器 → 识别链
```

- **裁剪要贴回画布，不许直接把裁剪当帧。** 理由只有一条：**ROI 的取法仍然是真的在被测**。把 ROI 预先替识别链做好，测的就不是同一条路了；
- **PNG 解码住离线侧**（`offline/bench/`）。`engine` **不装 pillow 也得能跑**——`pyproject.toml` 里 pillow 挂在 `offline` 那组额外依赖上。所以**重放适配器收到的已经是原始帧字节**，它自己不解图；
- **重放适配器是[设备层](../设备层.md) §5 那张表里 `replay` 那一列**，契约（收什么 · 吐帧 · 只记一笔 · 没前提头怎么办）写在那一节，**这里不重述**；
- **"跑过一遍"是一次性的**：帧依次吐、吐完再要就报错，**不许回卷**。[离线验收](离线验收.md) §1 要的正是"这一批跑过了"这句话，回卷会让它变成假的。

## 4 冻结与版本

- **基准集冻结**：拿它调过参，它就不再是干净基准（[难例采集](难例采集.md) §3）。要调参就换一份，并把 `version` +1；
- **按批冻一份**，不是按方法各冻一份。一批帧常常同时喂好几个读数器（费用那批就同时喂数字与填充），按方法拆会让人分不清"这一版改的是哪一批"；
- **回归比对的口径**在[离线验收](离线验收.md) §3，这里不重述。

## 5 已有的三批

**第一批：费用。** `tests/帧样本/费用/`，**v1**，31 张原生裁剪。它本来是费用读数链的测试夹具，现在**同时是第一批基准集**——真值在 `tests/spec/cost_spec.py`。

那一批**没有 `facts`**（抓那批帧的时候没记前提头），所以它**不能用来验设备事实那条路**。这不影响它的用途：费用读数不依赖方向。

**第二批：顶部两个数。** `tests/帧样本/顶部两个数/`，**v1**，35 张原生裁剪（`shot01`–`shot09` · `shot16`–`shot37` 加 4 张另一局的静帧）。一个裁剪**同时装得下** `enemy_count` 与 `life_digits`——两个数在游戏里本来就是同一次取像里的东西，所以也一起给。真值在 `tests/spec/topbar_spec.py`。

它**也没有 `facts`**（同样没记前提头），而且**35 帧全是静帧通道**：生命那个粉是平的 `(255,120,120)`，35/35 一致。**混进录像帧会坏掉这一批**——录像通道把颜色整体抬几格（[D-全局-20](../../20-决策记录/全局.md)），"同一个粉"就变成两种。

它覆盖到的与**没**覆盖到的（[顶部两个数](../视觉层/顶部两个数.md) §尚未定）：敌数一侧 1 位与 2 位、`1` 这个窄字形在首位与末位、生命 `1` 与 `3`；**两位数的生命与 3 位数的敌数一张帧都没有**。

**第三批：备战席。** `tests/帧样本/备战席/`，**v2**（第二批并进来时 +1），10 张原生裁剪，两个来源共用同一个窗口 `(300, 1040)–(2799, 1259)`。

- 6 张 `shotNN`（`data/precheck/live/` 那 40 帧扫描里挑的）；
- 4 张 `cdNN`（**一局真机战斗里每 3 秒截一张、连截 61 张**里挑的）。

**选帧是按覆盖选的，不是顺手抓的**：卡数各不相同（12 · 11 · 10 · 9 · 8 · 6），费用一位数与两位数、装置卡、再部署中那一档都在里面；`cdNN` 那 4 帧补的是**再部署那一档的另外三副面孔** —— 刚撤退（白弧 31°）、真环落进"判不了"、**亮卡面被误判成在再部署**。真值在 `tests/spec/bench_row_spec.py`。

**那 4 帧不写费用真值**：上面有几张卡的费用读数链读不出来（同一张卡上了红罩就读得出、没上就读不出），而那是**另一条链的欠账**，不该让"再部署那一列"的验收替它背。所以这一批的**费用那一列只覆盖 6 帧**。

它**也没有 `facts`**，而且**没覆盖到**灰掉那一档（费用不足）、空席、3 位数费用。

**这一批比前两批重得多**（10 张 7.2 MB，前两批各不到 1 MB）：备战席那一条横带**宽 2500 px**，而 PNG 对连续色调的立绘压不动（约 1.4 B/px）。这是**裁剪窗口的选择**，不是格式的问题 —— 换更窄的窗口就得逐帧换原点，见 §尚未定。

**`cdNN` 那 4 帧里 3 帧是取材帧**（`cd01` · `cd08` · `cd60`，判据就是拿它们调的），**只有 `cd20` 是留出来的**。所以按 §4 那条，将来要重开"再部署那一列"的干净基线时，得再冻一批新的。

## 尚未定

- **素材从哪来。** 现在只有"从既有帧样本里裁"，而段一 3 的备战席 / 场上我方干员 / 敌方单位都要自己的批——是接着裁，还是整帧存（整帧 14 MB，**进不了版本库**）；
- **回归基线存哪。** 跑基准集的脚本落的报告进 `data/`（不进版本库），所以"上次的输出"跨不了机器——它现在只是同一台机器上的一次比对；
- **批要不要带一句"这一批测什么"**：现在只有目录名（`费用` / `顶部两个数`），而一个批可能同时测好几样；
- **裁剪窗口要不要逐帧收紧。** 备战席那一批用了一个**公共窗口**（2500×220）—— 理由是那条栏**右对齐、左缘随卡数变**，公共窗口省掉"每帧一个原点"这件事。代价是**空的那半边也进了版本库**（6 张 4.5 MB）。换成"每帧从最左那张卡再往左一点"能省掉一半左右，格式也支持（`origin` 本来就是逐条的）—— **要不要这么做未定**；
- **报告里 `facts` 那一栏要不要带上 `resolution`**（T6 补丁提出）：它和同一份报告里的 `canvas` 是**同一个事实**（加载器就是从 `canvas` 折出来的），落两遍是漂移的入口；但丢掉它，读报告的人就少一个"这一批是按哪张画布跑的"的线索（而那件事 `canvas` 已经说了）。**三批都没有 `facts`**，所以两条路落出来都是 `null`——这一问**仍然验不出来**，等哪一批真带上前提头时再定。
