# 时序层

> 状态：讨论中 ｜ 正文已成形；§5 观测迹的**形状**已由[契约层](契约层.md) 定下（三元组），**里面有哪些字段**仍等 `状态层/` 定稿

对应代码：`src/ark/engine/timeline/`。这个概念在《概念设计共识》里叫「时序存储」。

## 这份文件负责什么

带时序的时间片记录格式、动作流、以及"轴"的格式。轴必须携带环境前提（分辨率、帧率、练度指纹、游戏版本、合约词条、队伍）和格式版本——否则"审批后重放等于复现"是假的。前提对不上时要报错拒绝执行，不能静默跳过。

## 不在这里

- 什么时候暂停、什么时候慢放 → `控制层/`
- AI 怎么读写这些记录 → `接口层/`
- 游戏时间怎么计量 → [`../30-专题/时间基.md`](../30-专题/时间基.md)

## 1. 两个产物，一套格式

```
轴   = 前提头 + 动作表                ← 计划。AI 编辑它，工具执行它。
记录 = 前提头 + 实际动作表 + 观测迹    ← 事实。工具产出，AI 查阅。
```

**记录 ⊃ 轴**：人首轮跑出来的那条记录，它的"实际动作表"本身就是一条轴，AI 直接在它上面改。

**轴里只有操作，没有识别内容。** 这是硬边界：AI 编辑轴的界面里不该混进它改不了的东西；识别内容只归记录。

**而且轴里也没有"条件"。** 暂停条件**只活在 `继续到` 的参数里，不进轴**（用户裁定）——轴是一本**岁月史书**：**只记历史（何时做了什么），不记未来**。它的用途是 **AI 想重开时不用背一遍所有操作**，把上几局录入的操作自动执行一遍。完整理由与代价见[控制层/暂停条件](控制层/暂停条件.md) §1。

## 2. 时间坐标

时间坐标就是**逻辑帧号**，定义见 [时间基.md](../30-专题/时间基.md)。

轴上**不使用墙钟，也不使用"第几秒"**。慢放与常速共用同一条轴，因为两者只在游戏时间上快慢不同。

## 3. 前提头

轴成立的环境前提。运行前**逐项校验，不吻合即拒绝执行**（§2.2 第 13 条）——不降级、不"尽力执行"。

| 项 | 为什么要它 |
| --- | --- |
| 分辨率 / 帧率 | 识别全部压到归一化画布上；不吻合则所有 ROI 失效 |
| 游戏版本 | 数值与 UI 都会随版本变 |
| 格式版本 | 轴本身的写法会变 |
| 关卡 | 地形与**路线（含出怪）**按关卡取 |
| 合约词条 | 改初始费、改回费速率、改可部署格，**还可能多出几个怪** |
| 初始费用 / 自然回费速率 | 游戏时间反推的两个系数（见时间基 §3.2） |
| 队伍 | 动作里的对象必须落在这个集合内 |
| **装备的技能** | **逐干员一条**——技能的"**手动 / 自动**"靠它查表（[首轮探索/录轴](首轮探索/录轴.md) §2）。缺它，工具分不出"人开的技能"和"自己触发的技能" |
| 练度指纹 | **逐干员一条标识**（干员 / 精英化 / 等级 / 技能等级 / 模组 / 潜能 / **皮肤**），值由[指纹库](资产生成器/README.md) 取 |

**练度指纹存标识，不存值**（用户裁定）：卡面与数值都跟着它变，而它本身随账号成长而改（[特征库](资产生成器/特征库.md) §1）。存标识的好处是**改一次指纹库全局生效**、轴保持小；代价是"审批后重放等于复现"多依赖一份库。

## 4. 动作表

```
动作 = (帧号, 动词, 参数…)
```

| 动词 | 参数 | 备注 |
| --- | --- | --- |
| `部署` | 对象、位置、**朝向（必填）** | 对象与"朝向是否有意义"都查数据库。**朝向不是可选项**：不选朝向 = 一次**未完成的放置**——干员放上去了但**不攻击**，点别处还会被**撤销**（用户确认）。所以「朝哪」不是一个可以省掉的独立决策 |
| `撤退` | 对象 | |
| `开技能` | 对象 | 仅对**手动触发**的技能成立 |
| `关技能` | 对象 | 仅对**可关**的技能成立 |

**轴上不出现的东西**：

- 点卡 / 拖拽 / 松手 / 选朝向这些**手势原语**——它们沉在设备层，AI 和轴都看不见；
- **`启动`**（开始这一局）——它在**战斗之前**，不在一局的计划之内（[接口层/算子清单](接口层/算子清单.md)）；
- **暂停与慢放**——工具侧调度，见 §6；
- **自动触发与被动技能**——它们自己会触发，轴上记了也没有执行的意义。被动技能在部署那一刻触发，因此它属于**部署动作的生效反馈**，不是独立动作。

> **「原语」这个词在本项目有两个意思，别混**：**视觉原语** = 识别问题（[视觉层/原语.md](视觉层/原语.md)，形状见[契约层](契约层.md) §1）；**手势原语** = 注入的手指动作（点 / 按 / 拖 / 抬）。这一节说的是后者。那个更吃重的名字留给视觉侧。

**动作之间有一个最小间隔。** 部署落地之后**还要几帧**才能选中该干员（用户确认）→ **同一干员的两个动作（部署 → 开技能 / 撤退）不能贴着排**，否则第二个动作点不到人。具体几帧要实测。

**动作必须带生效反馈**（§2.2 第 14 条）。工具不得"发完指令就当成功"，确认不了要降级上报。反馈的具体形态由 `接口层/执行与失败.md` 定义；这里只要求它在数据结构里有一席之地。

## 5. 记录：稀疏，变化驱动

记录**不是**逐帧表。

```
观测迹 = [(帧号, 字段, 槽)]                 ← 只在变的那一刻插一条
任意帧 f 的状态 = 取 ≤ f 的最后一条（按字段各查各的）
```

**槽**是[契约层](契约层.md) §1 那个类型（三态 × 载荷 × 置信度）。**不单列一栏"取值形态"**——形态长在值上，写成并列字段就能构造出自相矛盾的东西（契约层 §1）。同理**也不单列"三态"与"置信度"**：它们是槽的一部分。

**这在最初是写成四元的**（`帧号, 字段, 新值, 取值形态`），那份写法预设了"形态可以脱离值单独存"——不成立。改由契约层定形状之后它自然塌成三元组。

为什么不逐帧：**逐帧表的问题不是它大，是它假装每一格都知道。** 大部分格是上一格的重复，剩下的格是根本没采样的地方，填进去就是假精度——这跟"零假事实"直接冲突。

**代价要说清**：观测迹是**采样**出来的。若某字段在两次采样之间变了又变回来，我们会漏掉中间值，把 A→C 记成一次干净跳变。诚实的做法是把这段区间标成"可能存在未观测到的变化"，而不是假装它干净。

**原始帧就留"被识别过的那几帧"**，不做全程录制。**没有常驻取像**——每次识别都要现抓一帧，所以能留下的只有识别发生的那几帧本身（以及同一个暂停点内连续识别的那几帧）。留它的三个理由：

1. 遮挡掩码必须**取自原图**（§5.4 第 2 条）；
2. 难例采集要落原帧（§5.5）；
3. AI 事后想亲眼看一眼。

**代价**：关键帧**之前**的像素不存在，事后拿不到。任何"看看它前一秒发生了什么"的需求都做不了——要找原因，只能靠那几次识别已经算出来的字段。

**关键帧 = 动作时刻 ∪ 变化时刻 ∪ 工具当时不确定而主动落盘的时刻。**

### 派生视图

给 AI 看的不是上面那张表，是从它派生的**关键操作点视图**：只含有动作的帧与状态显著变化的帧，一场战斗几十行。要看细节时再展开某一段——展开时**按需现算字段**，用的正是那条离线识别链路。

## 6. 什么进轴、什么不进轴

| | 进哪 | 为什么 |
| --- | --- | --- |
| 暂停 | **只进记录**，不进轴 | 轴上只有游戏时间；暂停不改变游戏时间，写进轴等于把墙钟混进来 |
| 慢放 | 哪都不进 | 纯工具侧调度 |
| 时间态切换 | 记录里可标一笔 | 只为解释"为什么这一段墙钟很长" |
| **`启动`**（开始这一局） | 记录里可标一笔 | 它在战斗之前，不在一局的计划之内 |

## 7. 校验与拒绝

版本不认识、动作认不出、前提不吻合 → **报错并拒绝执行**，不跳过、不降级、不猜。

静默跳过会让"已批准"变成假的：AI 批的是它看到的那条轴，工具少执行一段却报告成功，等于骗它。

## 尚未定

- **观测迹的字段表**：由 `状态层/` 声明。**形状已定**（§5 的三元组），缺的只是"有哪些字段名"。
- **关键操作点视图的切法**：暂定"有动作的帧 ∪ 状态显著变化的帧"，等 [AI侧](AI侧/README.md) 成形后再定。
- **重放的时间对齐（一笔已知的账）**：重放**照帧号走**，所以它会**无视那些概率触发的效果**——同一条件在不同局落在不同帧，重放不会跟着变，于是**时间轴不完全对齐**。用户裁定**先接受它**，以后打补丁；理由是**"补对齐"比"补条件"容易写**。见[控制层/暂停条件](控制层/暂停条件.md) §1。
