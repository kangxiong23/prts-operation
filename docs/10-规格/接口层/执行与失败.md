## 1. 为什么"排"与"继续"必须分开

"排动作"那五个算子只写轴，`继续到` 才让游戏跑。前两条理由是硬的。

1. **契约要的就是分开。** §2.2 第 3 条说工具收到指令会"**暂存而不执行**，直到暂停条件成立"——**排进轴的动作就是那个暂存**。合成一个算子，"暂存"这个状态反而无处安放。
2. **"我排了"与"它生效了"是两件事。** §5.4 第 4 条写明动作在**入口**校验，§2.2 第 14 条要求**生效**反馈可观测——入口校验的结果立刻可得，生效要等游戏跑过那一帧。而且两者失败的含义完全不同（"这一格不能部署" vs "部署发出去了但没看到干员"），合成一个返回值就只能混着说。
3. **纸面推演不能被打断。** 排轴是"写计划"，推进是"执行计划"。AI 在推演阶段要连排十几个动作而一次都不跑——合并的算子做不到，除非再给它一个"不要跑"的开关，那就是隐式分支。

### 一处对基线的读法

§2.2 第 2 条写的是"每次**下达指令**时必须同时给出下一次暂停条件"。本目录把它读成**"每一次让游戏继续的指令"**（**用户确认**）——条件之所以必需，是因为游戏一恢复就必须知道什么时候回来；而只写轴的调用根本不会让游戏恢复，也就没有条件可违反。

**这处读法已经生效，但字面还留在基线里**：搬空 §2.2 时把措辞收紧（[README.md](README.md)「待回改」）。漏掉这一步的后果不小——**照字面实现会长出一个"五个动作算子各带一个条件"的设计**，它能跑，但把纸面推演堵死了（连排十几个动作而一次都不跑，就做不到了）。

## 2. `继续到` 里发生什么

```
校验前提头 → 执行落在当前帧、且暂停态做得了的动作 → 恢复 → 执行落在后面的动作 ‖ 判暂停条件
  → 停下 → 抓帧 → 按暂停 → 识别 → 组快照
```

- **前提头在恢复之前校验**：不吻合、版本不认识、动作认不出 → **整段拒绝执行**，不部分执行（§2.2 第 12、13 条）。部分执行比不执行更坏——AI 以为跑过了。
- **有一类动作要在恢复之前就做掉**（用户裁定）。**部署可以在暂停态做；撤退 / 开技能 / 关技能不能**——它们必须先选中该干员，而暂停态选不中已上场的干员（[控制层](../控制层/时间态.md)）。于是规则很干净：

  > **落在当前暂停帧的动作是精确的（±0 帧）；落在未来帧的动作要等跑到才注入，误差约 1 帧。**

  顺带解释了那句直觉：**"停下来一个一个下"比"一次排一串"更安全**，不是为了保守，是**精度真的差一帧**。**执行路径只有这一条**——`部署` 的返回值语义不必分叉，离线重放也不用特判。
- **识别范围由暂停条件决定**：条件没引用生命，这一段就不读生命。**这是"工具常驻判定条件"在算力上可行的前提**（§5.4 第 4 条）。
- **抓帧在按下暂停之前**：暂停会蒙上灰罩与字样，给识别添障碍（[控制层](../控制层/识别时机.md)）。
- **AI 不调 `继续到`，游戏就一直暂停**。这是契约第 1 条的正面表述：AI 的思考时间不计入游戏时间。

## 3. 一段必然以四种之一结束

| 结束原因 | 含义 |
| --- | --- |
| **暂停条件命中** | 正常 |
| **上限到达** | 条件在这一段里没成立。返回"未命中"+ 快照，**不是成功**。**要说清是哪一种**：条件**确定不成立** ／ 条件**从未确定成立**（全程判不了）——见[控制层/暂停条件](../控制层/暂停条件.md) §4 |
| **画面已不是战斗界面** | 结算或退出。每次识别顺带检查（[控制层](../控制层/结束.md)），不另设常驻监控 |
| **执行中止** | 拒绝执行 / 设备断连 / 脱同步 |

**上限是安全网，不是轮询机制。** 它防止条件写错时挂死；**每一个条件都必须带时限（由 AI 给、必填）**，见[控制层/暂停条件](../控制层/暂停条件.md) §3。**AI 应当把它给得足够长**，长到不会靠它来分段取态——那是"过度验证"的一条捷径，见 [AI侧](../AI侧/README.md) §3。

### 生效反馈随 `继续到` 回来

§2.2 第 14 条要求每个动作都有可观测的生效反馈，**不得"发完指令就当成功"**；[时序层](../时序层.md) §4 只要求它在数据结构里有一席之地，形态归这里定：

**生效反馈 = 一个三态 + 一句"靠什么确认的"。**

| 态 | 含义 |
| --- | --- |
| **已确认** | 动作的效果已经出现（靠哪条通道确认，一并记下） |
| **未确认** | 发过指令，但没看到效果——**这就是失败**，不是"大概成了" |
| **不适用** | 被动技能在部署那一刻触发，没有独立的生效反馈（[时序层](../时序层.md) §4） |

**它跟着 `继续到` 的返回走，不跟着 `部署` 的返回走**——生效是"跑过那一帧"之后才有的信息。事后也能用 `看轴` / `看快照` 取。**"靠什么确认"属于状态层**（部署靠"该格出现我方单位"，也可靠"**备战席的技能详情页退出**"——未选朝向的未完成放置不会退页，用户确认；开技能靠"黄菱形 / 技条变化"），这里只规定这个席位存在。**超时多久、要不要重试属于落地的事**（[控制层](../控制层/识别时机.md) 已注明推迟）。

## 4. 失败语义：三种不正常，加一条铁律

| 情形 | 什么时候 | 工具怎么答 |
| --- | --- | --- |
| **拒绝** | 排动作：对象 / 格子 / 技能不合法 → **不写轴**；`继续到`：前提不吻合 / 不是战斗界面 / 版本认不出 → **整段拒绝** | 附具体哪一项不吻合。不降级、不"尽力执行" |
| **降级上报** | 动作没生效 · 时间不可信 · 字段识别降级或通道冲突 · 位置自检失败（脱同步） | **照常返回**，但降级进快照页眉的[存疑清单](../状态层/快照.md)，字段自身带三态与形态 |
| **异常中止** | 设备断连 · 跑到一半画面变了 | 返回**跑到哪一帧** + **哪些动作已确认生效**（取**轴上的动作**；"靠什么确认"不随中止走，事后用 `看轴` / `看快照` 取），**不假装跑完了** |

**铁律：工具不报"我尽力了"，只报三态。** 数不清就说数不清，读不到就说未采样，不确定就给区间。这是"零假事实"在接口上的样子——**AI 能处理不确定，不能处理假事实。**

### 不变量由工具算，不由 AI 抽查

I1–I4（[状态层](../状态层/README.md) G3）**每片对一次账，违反就进上面那张存疑清单**（它是其中的「账目」一类）。

**为什么这属于接口层**：它把"AI 自己去核对注入的事实"从一条常规动作，变成一条**只在被通知时才发生的动作**——§5.3 要防的正是那个 token 黑洞。**算账不需要判断力，解释残差为什么非零才需要**——后者留给 AI，见 [AI侧](../AI侧/README.md) §3。
