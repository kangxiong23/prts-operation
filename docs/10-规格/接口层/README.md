## 1. 契约锁死的四条形状

先列这四条，是因为它们不是设计选择，是契约的直接后果——不照做就等于违反基线。

| # | 契约 | 对算子形状的后果 |
| --- | --- | --- |
| 1 | §2.2 第 2 条：**每次下达指令必须同时给出下一次暂停条件** | **"让游戏继续"是唯一必须带条件的那件事，所以它单独成一条算子**；动作算子只写轴、不带条件（读法见[执行与失败.md](执行与失败.md) §1） |
| 2 | §2.2 第 1、3 条：思考期间保持暂停；未暂停时收到的指令**暂存而不执行** | **阻塞式等待**（[开题状态](../../00-总览/开题状态.md) B3）；而"排进轴的动作"**正是那个暂存** |
| 3 | §5.4 第 4 条：**按需声明识别字段**；同条还写"部署一类动作**只在入口校验**它自己需要的那一格/那一项" | 识别范围**由暂停条件引用了哪些字段决定**，不另开开关；**动作算子就是那个入口** |
| 4 | §2.2 第 11 条：不提供"回到某个时刻" | 没有回滚、没有"重试某一段"。要回头只能是**改轴 + 重跑** |

**第 2 条顺带保证了一件事**：AI 只可能在暂停态下达指令——它在跑的时候正阻塞在那个调用里，没有手可以伸出来。所以"AI 在常速下乱发指令"这个状态在结构上不存在，不需要额外校验。

## 2. 粒度线：两条，管两个方向

### ① 封装的边界：算子里不许有"看战场情况选做法"的分支

- **算"分支"的只有一种**：**依参数走的不算**（展开或不展开是调用方给的），**依战局状态做选择**的才算。
- **正例**：[时序层](../时序层.md) §4 已经规定了——"点卡 / 拖拽 / 松手 / 选朝向"这些**原语沉在设备层，AI 和轴都看不见**。轴的动词 `部署` 就是把一串"不需要判断力"的动作收进一个算子。
- **反例**：一个"自动开技能"的算子。它要在"什么时候开"上做选择 = 判断力 → **拒绝**。时机由 AI 给，不由算子猜。

### ② 拆分的边界：一次调用只做一件事，而且那件事在**算子名**上看得见

这条是第 ① 条的反面，也是它不够用的地方：**一个"什么都能干"的算子同样没有分支**，但它把 AI 的能力**藏进了参数 schema**——AI 读工具列表时看不出"我能部署、能开技能、能撤退"，得先读一遍参数说明才知道自己会什么。

于是动作面**直接采用轴的动词表**，一一对应：**轴上有几个动词，AI 就有几个算子。** 好处是**不存在第二套词汇**——轴的动词表变了，工具列表跟着变，反过来也一样。

**合起来一句话**：需要判断力的拆出来给 AI，不需要判断力的收进一个算子，**而收进去的那件事要说得出口**。

## 尚未定

- **`删动作` 要不要独立**：同帧同对象重写可以覆盖"改"，但"这一段的规划作废"覆盖不了。也还没定"删一段"与"重排尾部"是不是同一件事。
- **`查资料` 要不要拆成两条**（游戏事实 / 接口事实）。
- **`看原帧` 到底是不是我们的算子**：[算子清单.md](算子清单.md) §4 说抽象层不为它做准备，那它可以是引擎的算子，也可以是 DSH 侧的一个附件通道。倾向算子——裁剪与"哪几帧算关键帧"的口径归引擎。
- **`看记录` 的"与上一轮对比"形态**：它是"只审有问题的操作"这条诉求的直接支撑，但差异怎么表达（逐动作 diff / 只列变化点）没定。
- **上限的默认值**，以及一局最多几段。
- **`注册字段` 的成本反馈**：**机制已定**——受理返回一条**代价**（这条编排每片跑几个环、几个要取像，[字段编排.md](../状态层/字段编排.md) §8）。剩下的只是**量级**，方案层给不出（与 G4 同一条理由）。
