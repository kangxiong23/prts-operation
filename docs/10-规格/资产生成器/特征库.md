# 特征库

> 状态：讨论中 ｜ 流水线七步已立；**倒计时卡面的反解**（要实测）与**效果外观的按需长**是两条要单独盯的线

对应代码：`src/ark/offline/assets_gen/`。落到 `assets/features/`，**进版本库**（见[README](README.md)）。

**它是五样产物之一**，管的是**识别用的特征资产从哪来**——不是"图像怎么处理"。裁剪、归一化、打包是纯工程；决定这条流水线能不能转起来的，是**每一份资产的标签是谁给的、要不要人**。

## 0 标签的四个来源，成本差几个数量级

| 标签从哪来 | 例 | 成本 | 随什么长 |
| --- | --- | --- | --- |
| **我们的动作** | 每次部署 = 一次卡位标注 | **免费** | 不随关卡长 |
| **算出来** | 路线资产（含出怪）+ 移动速度 → 敌人的类型 | **免费** | 不随关卡长 |
| **游戏自己标了** | 卡面与图标（官方素材）· 技能的原生标签 | 便宜 | 随 **UI 元素种类数**长 |
| **只能人工** | **开局第一眼点名**（兼注册）· 效果外观样本 | **贵** | **效果外观是开放集** |

**设计目标一句话**：把前两类吃满，把第三类压到最小、**并且不让它随关卡数长**。

## 1 干员侧：要认，但首要理由不是"谁死了"

### 为什么必须认

**因为部署动作要知道"点第几张卡"。** [设备层](../设备层.md) §2 的部署手势，起点就是那张卡。而卡位是**读出来的、记不出来的**，依据是这几条机制（用户确认）：

| 机制 | 后果 |
| --- | --- |
| **开局按费用从小到大排列** | 初始顺序可算，但它会变 |
| 死亡 / 撤退后**回到自己的相对位置**，而**再部署费用会提高** | 位置回来了，身份没回来 |
| **卡片紧密排列** | **没有空位可以利用** |
| 有些装置可以**动态获得**、有些干员开技能后**冒出召唤物卡片** | 台上会**多出**卡片 |
| **异格银灰的天赋可以把卡片按费用重排** | 顺序会被**不是我们的动作**改掉 |

**最关键的是"紧密排列 + 保持相对位置"**——它让"靠位置或费用反推身份"彻底不可行：

> 四张卡从左到右是 `7 / 10 / 10 / 14`。下了第 2、3 张，然后死了一个，备战席变成 `7 / 15 / 14`。
> **回来的那张是原来两个 10 里的哪一个？推不出来**——两个 10 都会变成 15，而相对位置把最后的线索抹平了。

**于是"谁死了"是顺带解决的**，不是首要目的。而战死这条路**没有原生视觉提示**（只有音效，而我们只有截图、没有音频通道），所以它也**不能降级成一次存在性搜索**。

### 卡面本身也会变：精英化与皮肤（用户确认）

**备战席上的卡面随【精英化阶段】与【皮肤】变。** 所以候选集里每个干员的"外观"是一个三元组：

> **干员 × 精英化阶段 × 皮肤**

这不破坏"规模是十几个"这个结论——**一局里这三样都是定的**，所以候选集仍然只有十几个，只是每个的长相比以前多一个键。但它有两个连带后果：

- **卡面资产的键要带上它**（§3 干员那一行），不能只按干员存；
- **练度指纹也要带上它**——它在[时序层](../时序层.md) §3 的前提头里，与[卡面与指纹.md](卡面与指纹.md) 是同一个来源。

### 标签从哪来

- **每次部署动作 = 一次免费标注**：点了第 N 张卡部署了能天使 → **那一刻第 N 张卡就是能天使**。位置变化（撤退、费用变化、天赋重排）**大部分也是我们的动作触发的**，所以每次部署都在**重新确认**；
- **卡面库由 `启动` 采，本局映射由点名给**：`启动` 在编队页顺手截一帧，得到**本局队伍的卡面**；**开局第一眼人点一次名**，建立**这一局的「第几张卡 ↔ 谁」**——两者是同一次机会，见[卡面与指纹.md](卡面与指纹.md) §1；
- **卡面按"遇到过就留一张"累积**，不要求全社会所有干员；
- **战场上的位置**来自部署记录（我们点了哪一格）——标签同样免费，它的问题只有**失同步**（[场上我方干员](../视觉层/场上我方干员.md) §4 那条自检管的是它）。

**而"靠位置与费用反推身份"这条路是封死的**：上面那个 `7/10/10/14` 的例子在这里咬第二次——**同费用并列时，"第几张卡是谁"从位置与费用都推不出来**；而且**备战席的顺序本来就不按编队界面的顺序**（用户确认）。所以**开局第一眼那次人工点名仍然需要**：它建立**这一局的「第几张卡 ↔ 谁」**，并顺手注册没见过的新组合（[卡面与指纹.md](卡面与指纹.md) §1）。

### 规模：候选集开工前枚举得出来

干员数很多，但**一局只用一个队伍**：

> **候选集 = 本局队伍 ∪ 这些干员的召唤物与装置 ∪ 本关自带的装置**

三者都在数据库 / 关卡资产里列得出，规模是**十几个**，不是几百个。于是干员识别和敌人识别是**同一个形状：在一个已知的小集合里分类**。

**备战席会变，但不会变得超出开工前能枚举的范围。**

### 倒计时那张卡（待实测）

干员进入再部署倒计时时，卡面被**红罩 + 灰圆环 + 白色环形进度 + 中央数字**盖住，而**红罩的不透明度有点高**（用户确认）。

它其实是**两种覆盖物**，要用**两种手段**分别处理：

| 覆盖物 | 性质 | 怎么办 |
| --- | --- | --- |
| **红罩** | **静态**（位置固定、参数固定） | **还原**：标定一次它的 α / 颜色 / 叠加方式，反解出原卡面 |
| **圆环进度 + 中央数字** | **逐帧在变** | **掩码**：只匹配没被它们盖住的部分——§5.4 第 2 条那套「取自原图的掩码」 |

**所以资产是"红罩的参数"（标定一次），不是"每个干员采两遍"**——后者是**干员数 × 精英化档 × 皮肤**，而且每版本要重采。

**但有一条只能实测回答的分界线**：反解之后剩下的信息够不够匹配？

| | |
| --- | --- |
| **够** | 走还原 + 掩码，成本压到一次标定 → **红罩参数进 §3 的清单** |
| **不够** | 退回"每个干员存一张倒计时卡面"，**成本变成干员数 × 精英化档 × 皮肤、且每版本重采** |

## 2 敌人侧：标签来自"算"，不来自"看"

### 配对是怎么来的

> [路线资产](地形与关卡资产/路线.md) 说"**第 N 个出场的敌人是类型 X，从门 D 进**" → 位置由[推算主通道](../状态层/敌方单位.md)（**那条格序列** + 移动速度 + **停留点** + 我们造成的减速 / 阻挡）给出 → **那个位置上的像素剪裁，标签就是 X**。

**关键在于标签来自一条与视觉无关的来源。** 若拿识别结果当标签，就是**分类器拿自己的输出训练自己**——错误会固化，而且**没有任何东西能发现**。

> **注意**：路线资产是**格级的名义路径**（怪不走正中、弯不直角，见[状态层/敌方单位.md](../状态层/敌方单位.md)）。所以配对时**要用容差去对**，不能当它是真值。

### 取样的筛子

| 要筛掉 | 为什么 |
| --- | --- |
| **与别的敌人粘连** | 裁出来是两三个的混合，标签只有一个 → **错配** |
| **被特效盖住** | 像素不是那个怪的 |
| **与干员叠着** | 同上，而且这正是"减法不干净"那个坑 |
| **离推算位置太远** | 裁到的根本不是它——**最危险的一种** |

**所以最佳取样时刻有一个明确的首选：敌人刚出红门的那几帧。**

- 位置**确定**（门的位置是[地形资产](地形与关卡资产/README.md) 里的 R 门，**不靠推算**）；
- **不可能粘连**（刚出来，身边没人）；
- 与干员重叠的概率最低；
- 类型**确定**（就是路线资产那条记录）。

**取样按优先级排队**：① 刚出红门 → ② 独立行走、周围空的 → 其余不取。多帧累积，每种怪攒够几十张即可。

**一个必须写下来的自举顺序**：先用①类样本建**初版体型标定**（单怪色块面积 / 占位面积），再用它去筛②类——**不写清顺序，第一版就没有可信的筛子**。

### ①类样本是首轮探索白拿的

**出怪帧的裁图 = 临时资产**：人标路线时**顺手把名字标了**，它就成了正式资产（[首轮探索/出怪与路线](../首轮探索/出怪与路线.md) §2）。**采集不单独占动作**——与卡面挂 `启动`、难例挂识别是同一个模式。

**左右朝向互为镜像**（用户确认）→ **资产只存一个朝向，运行时翻转**，省一半条目。**"严格镜像"要验一次**（不对称设计、带光效的怪可能不成立）。

**它处理不了怪本身的特效** → 所以它是**未命中资产库时的后路**：它给的是"**这是一只我没见过的怪**"（聚类分组），人给名字之后**仍需要一次干净采集才算正式资产**。

## 4 流水线七步

```
取源 → 定位 → 打包 → 贴标签 → 打戳 → 验收 → 回流
```

只有两步有真正的分叉：**贴标签**（走哪条路决定这一步要不要人，§0 那四个来源）与**打戳**（决定失效时怎么办）。

**五样产物，戳各有各的写法**——它们失效的原因不一样：

| 产物 | 戳 |
| --- | --- |
| **游戏数据库** | **上游数据版本**（官方 gamedata 的版本 / commit）。它**不进版本库**，所以戳必须写进生成物里，否则"这份表对应哪个版本"无从回答 |
| **地形与路线 · 形状** | **游戏版本 × 关卡**（它不随词条变） |
| **地形与路线 · 出怪记录** | **游戏版本 × 关卡 × 词条组合** |
| **特征库** | **游戏版本 × UI 布局** —— **不含语言**（数字走字形模板、不做 OCR，这条红利是[已定的](../视觉层/识别方法.md)），**也不含分辨率** |
| **干净关卡背景帧** | **关卡 × 相机参数（视图）× 游戏版本 × 渲染设置** |
| **卡面与指纹** | **它没有戳**——键本身就是标识（卡面键 = 干员 × 精英化 × 皮肤；指纹键再加上等级 / 技能等级 / 模组 / 潜能）。游戏改数值时靠**冲突上报**发现，不靠版本比对 |

**分辨率为什么不进戳**：已定"**定死运行环境，不做分辨率适配**"，不合规直接报错（[概念设计共识](../../概念设计共识.md) §5.4 第 1 条；[MAA借鉴清单](../../50-外部借鉴/MAA借鉴清单.md) §1）。它是**前提头里的一条环境前提**（[时序层](../时序层.md) §3），不是资产的一个维度——写成维度就等于把那条决定作废。

**验收要的是"可比较的结果"**（[README](README.md) 自己写的：派生出来的东西要能全量重跑并给出可比较的结果，否则没人敢动它）→ 产出一份**可 diff 的清单**（每种资产的缩略图 + 计数 + 指纹），**不是一个"跑成功了"**。

**回流有三个来源**：难例集（[采集与验收](../采集与验收/难例采集.md)）· **注册字段被拒的记录**（它 = 缺一种方法 = 缺一份资产）· **首轮探索**（[首轮探索](../首轮探索/README.md)）——出怪帧的裁图（§2 末）不是难例，是**正常样本**，而且它顺带把类型标签也带上了。

## 5 两条要单独盯的线

**① 效果外观是唯一会随版本长大的人工资产。** 它和"人工规模不随版本线性增长"那句承诺冲突。唯一的缓解是**按需长**（AI 注册被拒才去采），**不许预先穷举**。所以它不是"资产库健康"，而是**一条永远会有缺口的资产线**——和[敌方单位](../状态层/敌方单位.md) 那条"覆盖不了的场景要显式承认"是同一类诚实。

**② 判定点不进资产，而且要说清为什么。** 游戏里标识路线靠给怪一串**判定点**（怪持续以最短路径走向当前那个，到了切下一个，终点必是蓝门）。但判定点**坐标未知、且不是整数**，而**测它只能靠"不断造成很明显的位移"**——方法论上就很贵（危机合约攻略组曾为标定一个判定点，画下一百多条辅助线的尺规作图草稿）。**怪怎么走好测得多，所以资产是路线，不是判定点。** 位置精度因此是**格级**，用途也分级——见[状态层/敌方单位.md](../状态层/敌方单位.md)。

## 尚未定

- **倒计时卡面反解后剩多少信息**（§1 那条分界线）——要真机试；**判完要回填 §3 那一行**；
- **敌人的左右朝向是不是严格镜像**（§2 末）：若某些怪不成立，就得退回"两个朝向各存一份"，条目翻倍——**要真机比对一次**；
- **"刚出红门"这几帧够不够攒样本**：出怪频率低的关卡，单靠红门可能攒不齐某些怪种；
- **候选集里"本关自带的装置"怎么枚举**（来自关卡资产还是数据库）；
- **热更新会不会动 UI 而不动版本号**——若会，"版本变了就重跑"这条会**静默失效**，得另加一条**资产健康自检**（开工时先拿已知场景验一遍资产还在不在）。这条**现在完全没有**；
- **在场干员像素：现在不采**（用户裁定）。按现有设计它**零处需要**——身份 / 位置 / 朝向靠**记**，条与黄菱形靠**颜色与存在性搜索**，从敌人掩码里减我方走的是**格级占位**（[视觉层/敌方单位](../视觉层/敌方单位.md) 第 4 步"重叠处不强行分"）。**配方留着**：真需要精确轮廓时，挑一关**出怪晚**的、**不带词条**跑一次，把每个干员分别下场并**四个朝向各截一张**（几十张），当像素照片用——注意**"不带词条"不解决"没有敌人"**，所以时机得挑。**先拿 1 个干员 × 4 朝向验**"立绘模板做减法是否真比格级占位准"；不准就连配方也不必留。
