# 地形

> 状态：讨论中 ｜ 已成形；可视化编辑器属目标形态

**「地形与关卡资产」的正文之一**——概览、四个文件与词条覆盖的三类见 [README.md](README.md)。

本文件管**那张字符图**：它怎么被做出来、怎么被机器校验、怎么被人验收，以及**禁用格**怎么填。

## 1. 它怎么被做出来

**永不从像素检测。** 理由见 [D-全局-09](../../../20-决策记录/全局.md)。

| 阶段 | 谁 | 做什么 |
| --- | --- | --- |
| 编辑器可用前（测试期） | 开发者 | 直接手写 `.map` 字符 |
| 目标形态 | **可视化编辑器** | 点格子刷类别、刷标签区域（**含机制挂载点**）、放门 |
| 每版 | 机器 | 校验（见 §2） |
| 每版 | **人** | 验收（见 §3） |

### 可视化编辑器

**目标形态，不是第一版。** 它属于 `offline/`，不参与在线链路；形态待定。

它至少要能干这些：刷格子类别、刷标签区域（机制挂载点）、放门与改门、改投影参数、跑校验、渲染对照图。

为什么它迟早要做：手写字符在关卡变多之后会成为瓶颈，而且**手写看不出空间错误**——一列少一个字符，人眼很难发现，校验器也不会报。

## 2. 校验器（机器，必做）

把不变量写成检查。目前确定的有：

- 图是矩形，每个字符都在图例里；
- 标签坐标在界内，且落在有地块的格子上；
- **门格必定是不可部署地面**（[地形模型](../../../30-专题/地形模型.md) §4）；
- 投影参数能算出一个落在画面范围内的像素（见 [投影.md](投影.md)）；
- **路线**那几条（格序列、停留点、出现帧、序号、形状引用）在 [路线.md](路线.md) §2。

## 3. 验收（人，必做）

把字符图渲染回原截图叠加，人扫一眼。这是"零假事实"落在**资产**上的形态——**资产本身也不能是猜的**。

## 4. 禁用格怎么填

合约只把**部分**地面 / 高台变为不可部署，所以这一类的覆盖就是**一小串禁用格**，写在 `.json` 的 `synergyOverrides` 里（复用 `.map` 的坐标系统）。

**默认做法：人工填。**

**可选加速器（未定）**：同一个干员、同一个视角，有词条和没词条各截一张部署模式图，**差集就是被禁用的格**。

但这条要说清楚性质：**它是像素检测**，只不过读的是**部署高亮**这个 UI 叠加层，而不是地形美术。它落在"UI 稳定、美术多变"这条线的 UI 那一侧，所以不受换皮影响——但它仍然是像素检测，**要不要留由你定**（见 [README.md](README.md) 的「尚未定」）。
