## 1. 四个文件

```
assets/terrain/<关卡>.map           ← 字符图，正本
assets/terrain/<关卡>.json          ← 元数据：关卡、投影、标签、禁用格覆盖
assets/terrain/<关卡>.shapes.json   ← 路线形状：格序列 + 停留点，见路线.md §1
assets/terrain/<关卡>.spawns.json   ← 出怪记录：逐敌人的出场记录，见路线.md §1
```

**为什么路线拆成两个文件**：两层**随不同的东西失效**——形状只随关卡变，出怪记录随词条组合变（§3）。而拆开还有第二个理由：出怪记录是一条一条的**长表**（一关几十到上百条），塞进元数据会让那个文件既难看 diff、也不是人编辑的对象——它更像记录，不像参数。

**为什么字符图是正本，而不是导出格式**，三条：

1. **编辑形态 = 阅读形态**。补漏时人要看的就是这张图，不该让他在两种表示之间翻译；
2. **它和 AI 看到的图长得一样**——少一层转换，就少一处可能不一致的地方；
3. 行列对齐错误一眼可见，`git diff` 也干净。

**尺寸不写进元数据**，从图推导，免得两处不一致。

标签（热泉通道这类）不进主图，用坐标/矩形列表放元数据——标签地形通常成片，不值得为了塞它把主图搞脏：

```jsonc
{
  "stage": "7-18",
  "projection": { "origin": [x, y], "col": [dx, dy], "row": [dx, dy] },
  "labels":           { "热泉通道": [[3,4],[3,5],[4,4],[4,5]] },
  "synergyOverrides": { "词条甲|词条乙": [[2,3],[2,4]] }
}
```

**标签同时是场地机制的挂载点**（机制名 → 坐标列表）。它不进主图，但**要进快照给 AI 看**——因为机制的规则**不由我们描述**，而是 **AI 过目地形之后走[注册字段](../../状态层/注册字段.md)**（理由见[地形模型](../../../30-专题/地形模型.md) §3）。

## 2. 词条覆盖：三类

合约会做**三件事**，所以覆盖也是**三类**——**三类都默认人工填，都复用 `.map` 的坐标系统**：

| 类 | 改什么 | 写在哪 | 怎么填 |
| --- | --- | --- | --- |
| **禁用格** | 把部分地面 / 高台变为不可部署 | `.json` 的 `synergyOverrides` | [地形.md](地形.md) §4 |
| **加怪** | 多出几个怪 | `.spawns.json`：追加条目 | [路线.md](路线.md) §4 |
| **改出现帧** | "xx怪更早出现" / "初始存在xx怪" / "较早或较晚时刻出现" | `.spawns.json`：替换某条的 `出现帧` | [路线.md](路线.md) §4 |

**后两类同样算"改出怪"**（用户确认）：它们一次动三个消费者——敌人总数、未出场、类型候选集。

**词条本身不说具体时刻、位置**（用户确认）→ 覆盖**只能观测**，不能从词条文本推。而**格序列不受词条影响**（这正是路线拆两层的原因）→ **改词条不重画形状**。

## 3. 随版本更新

**美术换皮不伤这个资产**，因为它存的是**语义而不是图像**。这正是"从不检测"换来的收益。

真正需要重做的只有三件事：

- 游戏版本改了可部署性、加了新地形 → 重新校验 + 人工改图；
- 合约加了新词条 → 加一条 `synergyOverrides`，再按它改哪一类补 `.spawns.json` 的覆盖；
- **游戏版本 / 关卡改了路线 → 重画那几条形状**——**这是三条里最贵的一条**（要重新对着画面画）。

**出怪那一侧不是版本触发的，是词条触发的**（用户纠正：**游戏版本不会改出怪和路线**）。所以还有一条，它比上面三条都便宜：

- **新词条组合 → 重观测出现帧**：形状一个字不用动（§2），只补 `.spawns.json`。

**戳因此是两个**（[特征库](../特征库.md) §4）：

| 层 | 戳 |
| --- | --- |
| **形状** | `游戏版本 × 关卡` |
| **出怪记录** | `游戏版本 × 关卡 × 词条组合` |

## 已定

- **不采用任何外部逐关格数据。** 理由：我们做的是**合约**，别人整理的是常规关卡的格子，用不上；而人工填的投入产出比很好——合约难度极高、要反复打反复摸轴，**地形一次填好、反复用**。见 [D-全局-09](../../../20-决策记录/全局.md)。
  - **提醒**：这条目前只写在规格里，**将来应补一条决策记录**。工作区里就摆着 4256 关的格数据，半年后没人记得当初为什么不用——**它会被人再提一次。**
- **路线（含出怪）住在这里，一个敌人一条**（用户裁定）：它逐关、与地形同戳同验收，所以不拆去数据库。
- **路线拆成「形状」与「出怪记录」两层**（用户裁定；§1）：两层的**失效条件不同**——形状随关卡变、出怪记录随词条组合变。见 [D-全局-12](../../../20-决策记录/全局.md)。
- **路线与地形分开表述**：地形只管"这格能不能待"，不算"敌人该往哪走"（[地形模型](../../../30-专题/地形模型.md) §7）。
