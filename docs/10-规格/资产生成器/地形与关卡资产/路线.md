## 1 两层：形状与出怪记录

**它们的失效条件不同，所以必须分开**：

| 层 | 内容 | 戳 |
| --- | --- | --- |
| **形状** | 一条**格序列** + 它自己的**停留点** | **游戏版本 × 关卡** |
| **出怪记录** | 序号 · 敌人类型 · **出现帧** · **形状引用** | **游戏版本 × 关卡 × 词条组合** |

**为什么必须拆**：词条会改**出现帧**（"xx怪更早出现" / "初始存在xx怪" / "较早或较晚时刻出现"），**不改格序列**。而格序列是**最贵**的人工产出。若不拆，**每来一个词条组合就要重画一遍格序列**。

**绝对恢复时刻不存**：`绝对 = 出现帧 + 相对恢复时刻`——**能推出来的，不给它第二处写错的机会**（与"出场位置不单列""尺寸不写进元数据"同一条纪律）。

### 形状

| 字段 | 内容 | 说明 |
| --- | --- | --- |
| **格序列** | 一串格坐标 | **格级的名义路径**，见 §3。**每一格带来源：观测 / 推断**——二值，**不带局标识**（跨局累积的规则见[首轮探索/出怪与路线](../../首轮探索/出怪与路线.md) §3） |
| **停留点** | （格序列第几格, **相对恢复时刻**）的列表，可空 | 相对**引用它的那条记录的出现帧**；见 §1.1 |
| **路线类型** | 地面 / 飞行 / 近地悬浮 | 与[地形模型](../../../30-专题/地形模型.md) §8 那条独立数据对上 |

**出场位置不单列**——它就是格序列的第一个格。**但它不一定是门**："初始存在xx怪"出现在**非门上**（词条效果），那种怪的形状起点就不是门。

### 出怪记录

| 字段 | 内容 | 说明 |
| --- | --- | --- |
| **序号** | 这一关第几个出场的单位 | 连续，且与**出现帧**同序 |
| **敌人** | 类型键（查[游戏数据库](../游戏数据库.md) 的敌人表） | 候选集、[快照](../../状态层/快照.md) ④a 的类型表、[一档](../../状态层/基础数值.md) 的 11 项，全挂在这上面 |
| **出现帧** | **逻辑帧**（相对开局帧 0） | 初生敌记 0；**取窗口下界**，见[首轮探索/时间对齐](../../首轮探索/时间对齐.md) §4 |
| **形状** | 引用一条形状 | |

**两层合起来同时就是出怪表**（用户裁定：并进来）。三个后果都要跟着改：

- **敌人总数、未出场**由它算（[不变量 I4](../../状态层/README.md)）→ 数据库里不再单独存出怪；
- **类型分类的候选集**由它缩（[视觉层/敌方单位.md](../../视觉层/敌方单位.md) 第 8 步）；
- **敌人位置的推算主通道**以它为基础（[状态层/敌方单位.md](../../状态层/敌方单位.md)）：格序列 + 移动速度（一档）+ **停留点** + 我们造成的减速 / 阻挡。

### 1.1 停留点为什么是「恢复时刻」

> **怪停留 = 系统还没给它设下一个判定点，而"设"发生在游戏内某个绝对时刻。**

| | 是什么 | 记不记 |
| --- | --- | --- |
| **恢复时刻 T** | 系统设下一个判定点的绝对时刻，**关卡属性** | **记** |
| **到达时刻** | 怪走到那一格的时刻，**算出来的**，受我们干扰 | 不记 |
| **时长 = T − 到达** | **导出量** | 不记 |

**曾写成「停留帧数」，改过一次。** 理由：我们在停留点之前造成的延误 δ 会让到达时刻后移 δ，于是时长**短了 δ**；**真正不动的是 T**。

**恢复判据**：`实际恢复时刻 = max(到达时刻, T)`。到达晚于 T → **根本不停**（判定点早就设好了）→ **所以观测到"从不停"不能推出"没有停留点"**。

**单边**：我们的控制只会推迟恢复 → `T_观测 ≥ T_真值` → **跨样本取最小值 = 真值**，全都偏大就报。机制与自洽检查见[首轮探索/出怪与路线](../../首轮探索/出怪与路线.md) §4。

## 2 它怎么被做出来

**人工创作，不从像素检测**——理由与地形同一条（[D-全局-09](../../../20-决策记录/全局.md)）：怪怎么走**好测得多**，但"好测"不等于"该让机器猜"。

**做它的工具见[首轮探索](../../首轮探索/README.md)**：人边打边画，工具负责找出怪事件、跟轨迹、吸附格、算帧号。

| 阶段 | 谁 | 做什么 |
| --- | --- | --- |
| 首轮探索时 | 人 | 边打边画（与画地形同一个时机）——游戏暂停时凭记忆点几只怪的路线，继续打，再补 |
| 每版 | 机器 | 校验：格序列每格都在图内、且落在可走的地块上；停留点的下标在序列之内；出现帧单调不减；序号连续；形状引用存在 |
| 每版 | **人** | 验收：把格序列**渲染回截图叠加**，看它是否贴着怪走 |

**怪几乎走不到蓝门**（人要摆干员击杀）→ **格序列 = 多个个体的观测段的并集 + 人补全的尾部**，**每一格带来源（观测 / 推断）**。

## 3 关于"格级"这件事

**精度起码到格，而且它是名义路径**：敌人不一定走路的正中间，拐弯不一定走直角。所以：

- **拿它算"敌人在哪"不行，拿它给 AI 下干员做参考可以**（[状态层/敌方单位.md](../../状态层/敌方单位.md) 那三条限定）；
- 拿它给样本配对时**要用容差去对**（[特征库](../特征库.md) §2）。

**判定点不进资产**，理由单列在[特征库](../特征库.md) §5②——那是这条路线上唯一贵到不值得做的量。

## 4 词条覆盖：加怪与改出现帧

合约会做**两件事**，都写在**出怪记录**那一层上：

| 类 | 改什么 | 写在哪 |
| --- | --- | --- |
| **加怪** | 多出几个怪 | 追加条目（引用已有形状） |
| **改出现帧** | "更早出现" / "初始存在" / "较早或较晚时刻出现" | 替换某条的 `出现帧` |

**词条本身不说具体时刻、位置**（用户确认）→ 所以**只能观测**，不能从词条文本推。

**"这同样算改出怪"**，因为它一次动了三个消费者：敌人总数、未出场、类型候选集。

**默认人工填**：词条由人选，所以人知道这一局多了什么——首轮探索时顺手补上即可。**它没有加速器**（不像禁用格那样能靠高亮差分）。

**格序列不受词条影响**（这是拆两层的理由）→ **改词条不重画形状**。
