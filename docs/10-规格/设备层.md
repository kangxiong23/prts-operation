# 设备层

> 状态：讨论中 ｜ 三层与部署路径已走通、时钟校准与取像已写；**朝向取法与 `r` 等真机项已列出**

对应代码：`src/ark/engine/device/`。

## 这份文件负责什么

**把"一个游戏动作"变成"手指落在正确的地方"，再从屏幕上取回一帧。** 整个项目里唯一接触真机的地方。

它是「端口 + 适配器」结构：端口定义在[契约层](契约层/README.md) §5，这里只放适配器。

| 适配器 | 用途 | 什么时候做 |
| --- | --- | --- |
| `adb/` | 真机：`screencap` 取像、`input` 注入 | 第一个做 |
| `replay/` | 离线重放：读录制的帧、只记动作不真的点 | 随[采集与验收/离线验收.md](采集与验收/离线验收.md) 一起来 |

**它的正确性判据只有一条**：给一个动作，我把手指放对地方。**它不知道动作有没有生效**——那是视觉层与生效反馈的事（[接口层/执行与失败](接口层/执行与失败.md) §3）。这条边界不能糊。

## 1 三层，共用一条词汇表

```
adb 基础操作        screencap ｜ input tap ｜ input swipe ｜ input keyevent ｜ wm size
      ↓ 封装
手势原语            按 ｜ 拖 ｜ 抬 ｜ 点 ｜ 键            ← 对设备负责：手指真的动了
      ↓ 组合
游戏动作            部署 ｜ 撤退 ｜ 开技能 ｜ 关技能        ← 对游戏负责：点对了地方
      ↓
轴的动词            [时序层](时序层.md) §4                ← 一模一样，不翻译
```

- **对外面就是轴的动词表**：轴上有什么动词，这里就有什么入口。[接口层](接口层/README.md) §2② 那条"不存在第二套词汇"因此从 AI 一路贯通到手指；
- **这里的叫「手势原语」**：「原语」那个名字留给**视觉原语**（[视觉层/原语.md](视觉层/原语.md)），别混（[时序层](时序层.md) §4）；
- **动作面之外只剩"设备管理"**：连接状态、分辨率与方向、取一帧。它们**不是动作**，不占动词表。

**手势原语的参数是格坐标与朝向，不是像素。** 像素在这个入口内部由 `格坐标 ↔ 像素` 投影算出。两条理由：

- **慢放是另一套投影**（地图右移倾斜，[控制层](控制层/时间态.md)）——让每个调用方自己换算，等于把"慢放下必须换一套"这条纪律复制到每个调用点；
- 调用方本来只有格坐标，没有理由让它碰像素。

## 2 部署（样板）

| 级 | 长什么样 |
| --- | --- |
| 轴 / 算子 | `部署(能天使, (5,4), 右)` |
| 游戏动作 | 按住备战席那张卡 → 拖到目标格 → 选朝向 → 松手 |
| 手势原语 | **一次拖动**：`拖到(格心 + 朝向向量 × r)`——按下与抬起是它的两端 |
| adb | 一次 `input swipe x0 y0 x1 y1 <duration>`：起点 = 那张卡，终点 = 上一步那个点 |

**两件事让它塌成一次直线 swipe**：

1. **朝向取的是"手指相对格心"的方向** → 同一个终点 `格心 + r·û` **同时编码了格与朝向**；
2. **`input swipe` 是原子的**——手指**无法跨越两条 adb 命令保持按下**。所以部署**必须是一次性手势**，不能"先拖到格、停一下看清预览、再选方向"。代价可以接受：**设备层本来就不该在途中做判断**。

**朝向是必填**（[时序层](时序层.md) §4）：不选朝向 = 一次未完成的放置。所以这个终点**永远带朝向**，没有"只给格"的形态。

**`r` 被两边夹住**，这是这条路唯一的未知数：

| | 约束 | 违反的后果 |
| --- | --- | --- |
| **上界** | 终点必须落在**可部署区域**内 | 松手位置不可部署 → **整次部署被撤销**（用户确认） |
| **下界** | **4 个朝向**（上下左右，**不含斜向**）要分得开 | 朝向定不下来 |

估 `r ≈ 0.3 格`，**格越小越紧**，实测。

**4 个朝向让下界松了不少**：四个终点都落在**本格之内**（`r ≈ 0.3 < 0.5`），所以上界（终点落在可部署区域内）也更容易满足。**曾写作"8 个朝向"——已改**（用户确认不含斜向）。

**拖动途中离开有效区域不会取消**（用户确认）——取消只看**松手位置**。

### 一条只能真机回答的风险（未验）

上面第 1 条假定游戏取的是**"松手位置相对格心"**。若它取的是**"最后一段拖动方向"**，那么从卡片直拉到 `格心 + r·û` 时，末段方向是"卡片 → 终点"的方向，**不等于 `û`，朝向会错**。

修法是让路径末段沿 `û`——而 `input swipe` **只能画直线**，那就必须换 **`input motionevent`**（DOWN / MOVE / UP 分三条命令，**它的可用性也要验**）。

> **这条不只是个数值问题**：它决定**设备层要不要支持多命令手势**。真机一验就知道。

### 另外三个动作

`撤退` / `开技能` / `关技能` 是同一个形状：**点已上场干员 → （面板出现）→ 点面板上的按钮**。

- 两条命令 + 一个**等待面板出现**；
- 那个等待**不是判断**（等的是一件确定会发生的事），但**也不能盲等**——见 §5 的"节奏"；
- **它们都不能在暂停态做**（暂停态选不中已上场的干员，[控制层](控制层/时间态.md)）→ 都由 `继续到` 在跑到那一帧时注入。

## 3 时钟校准

**要校准的不是"时钟"，是"注入落在哪一刻"。** 逻辑帧**不从时钟来**（[时间基](../30-专题/时间基.md)：由费用反推），所以这里**只产出墙钟耗时**；折成帧是控制层的事——[契约层](契约层/README.md) §3 已经把这两种刻度在类型上分开了。

三样，产出**区间**而不是一个数：

| 量 | 怎么测 | 用在哪 |
| --- | --- | --- |
| **取像往返** | `screencap` 发起到拿到完整帧 | 判定节拍的预算（[控制层](控制层/识别时机.md) §7 那条"跟不上要上报"） |
| **注入往返** | `input` 发起到命令返回 | "这个动作落在哪一逻辑帧"的误差 |
| **手势耗时** | `swipe` 的 `duration` 参数 vs 实际墙钟 | 部署的稳定性预算 |

**一个容易搞反的点**：**墙钟延迟本身不随慢放改变**——慢放改变的是"同一条墙钟折成多少游戏帧"（[契约层](契约层/README.md) §3：200 ms 在常速是 6 帧、慢放是 0.6 帧）。所以**校准的产物存成墙钟**，折算留给控制层。

**慢放倍率借这里的手测**（预期 10 倍，未实测）：用费用读数测（[时间基](../30-专题/时间基.md) §4），而**测量动作本身走的就是这一层的取像与注入**。设备层出**工具**，倍率值归时间基。

**部署的慢放不建模**（用户确认）：按下卡片即进慢放、松手即退，而 adb 一次注入**不跨帧**——所以部署本身没有"慢放窗口"可供利用。**慢放的两条来源里，只有"点开详情面板"那条是给 AI 读值用的。**

## 4 取像

- **通道先用纯 adb**，不装 `scrcpy`（[D-全局-05](../20-决策记录/全局.md)）；
- **取像端口返回原始帧，不返回归一化帧**（用户裁定）：这一层只管"帧到手"，不该知道画布；归一化是[视觉层](视觉层/README.md) 的入口，画布的定义在[契约层](契约层/README.md) §2；
- **只有"取一帧"，没有"取像流"**：一次识别现抓一帧，**没有常驻取像**（[控制层](控制层/识别时机.md)）。所以这一层不需要缓冲、不需要后台采集；
- **"抓帧在按暂停之前"是调用方的顺序**（[控制层](控制层/识别时机.md)），不是这一层的职责；这一层要保证的是"帧到手"足够快——那是判定节拍预算的一部分；
- **分辨率与方向**查出来喂**前提头**校验（[时序层](时序层.md) §3）：不吻合则所有 ROI 与投影一起失效，**报错拒绝执行，不降级**。

## 5 端口、节奏与重放

**端口必须"纯"到 replay 适配器能满足**（[契约层](契约层/README.md) §5）——"离线重放不是特例代码"的落地条件就是换一个适配器：

| 端口方法 | `adb` 适配器 | `replay` 适配器 |
| --- | --- | --- |
| 取一帧 | 真抓 | 返回该帧号对应的录制帧 |
| 注入手势 | 真点 | **只记一笔，不点** |
| 设备事实（分辨率 / 方向） | 查真机 | 从录制的前提头里回放 |

**"节奏"是这一层的内部事，而且它不是判断力**：面板要等它滑出来、点击要等上一次手势的基础间隔过去。判据是"**确定会发生的等待**"，**不是"看情况决定"**——后者违反[接口层](接口层/README.md) §2① 的粒度线。**等多久、要不要重试属于落地的事**，[控制层](控制层/识别时机.md) 已注明推迟。

**墙钟超时属于这一层**：命令没返回要报**中止**（[契约层](契约层/README.md) §5 的第三种错误），而不是无限等。
