# 暂停条件

> 状态：讨论中 ｜ **已立**：不进轴 · 一套文法两个 kind · 时限必填 · 三值结果 · 与或非；游戏时间钟的速率切换待实测

**控制层**的正文之一——概览与文件表见 [README.md](README.md)。

## 它为什么非有不可

§2.2 第 2 条：**每次让游戏继续，必须同时给出下一次暂停条件。** 强制，没有例外。

因为游戏一恢复，**工具就失去了"什么时候回来"的依据**。做不到这一点只有两个下场：

- **挂死**——AI 永远等不到唤醒；
- **轮询**——工具自己去猜什么时候该停。而"猜什么时候停"是**判断力**，正是[粒度线①](../接口层/README.md) 划在 AI 那边的东西。

所以这条条件的本质是：**把"什么时候回来"的判断，从工具手里交回给 AI**。它和"AI 的思考时间不计入游戏时间"是同一件事的两面。

## 1 住哪：只活在 `继续到` 的参数里，**不进轴**（用户裁定）

**轴是一本"岁月史书"。**

| | |
| --- | --- |
| **轴记什么** | **何时做了什么**——游戏绝对时间下的操作（帧号 + 动词 + 参数）。**只记历史，不记未来** |
| **它的用途** | AI 想重开时**不用背一遍所有操作**——把上几局录入的操作**自动执行**一遍 |
| **条件住哪** | **只活在 `继续到` 的调用参数里**，是运行期参数 |

**两条理由，第二条是决定性的：**

1. 轴里没有条件，**更干净**——[时序层](../时序层.md) §1 那条"轴里只有操作，没有识别内容"因此**没被破坏，反而被强化**；
2. **条件判断本身可靠性不高。** 万一被一个**概率触发的特效**干扰了识别，条件就会在错误的时刻成立或落空——而轴是**要被复现的**。**条件进轴 = 把不可靠的东西写进史书。**

### 代价要说清（已知，不是意外）

**重放会无视那些概率触发的效果，于是时间轴不完全对齐。** 同一条件在不同局可能落在不同帧，而"照帧号重放"不会跟着变。

**这是一笔明账**：用户裁定**先接受它**，以后再对此打补丁——而**"补对齐"比"补条件"容易写**。记在[时序层](../时序层.md) 的「尚未定」里。

## 2 表达式：一套文法，两个 kind

**时间是刻度，不是字段**——所以时间判定**写不成字段表达式**。它俩是**同一套文法下的两个 kind**，而不是两套文法（两套就会长出第二套词表）。

| kind | 长什么样 | 例 | 读字段吗 |
| --- | --- | --- | --- |
| **时间** | **游戏时间（秒）**，或逻辑帧号 | "再过 8.5 秒" · "到第 255 帧" | **完全不读** |
| **表达式** | 字段 + 比较 + 阈值，可用 **与 / 或 / 非** 组合 | "费用 ≥ 20 **且** 敌人到第 3 格" | 读表达式里出现的字段 |

- **一个条件只能是一个 kind，不许混**——"费用 ≥ 20 **或** 过了 8.5 秒"会同时逼出"要识别"与"不识别"两种节拍，工具没法给自己定档；
- **时间用游戏时间秒说话**：AI 想的就是"再过 8.5 秒"，而 1 游戏秒 = 30 帧（[时间基](../../30-专题/时间基.md)），换算免费；
- **两种 kind 共用同一套时限与结束语义**（§3、§4）。

> **为什么这次可以用"秒"**：[时序层](../时序层.md) §2 禁止**轴上**出现"第几秒"。但条件**不进轴**（§1），所以它不受那条约束——AI 用秒说话更自然，而**轴上仍然只有帧**。

### 一套文法带来的两条硬约束

**① 表达式必须让"它引用了哪些字段"能被静态算出来。**

这条是**推出来的、不是可选的**：条件是识别范围的**唯一来源**（§5.4 第 4 条 · [状态层](../状态层/README.md) G3），那就必须能在**跑之前**枚举出字段清单。于是有一类构造**天然不许**——动态引用（"读所有注册字段"）。

**② 能用时间就必须用时间。**

时间判定**完全不读字段**：免费、不受卡顿影响、不占识别预算。**凡是能算出来的时刻，就不该写成条件判定**——反过来，拿条件判定去等一个本来算得出的时刻，正是[AI侧](../AI侧/README.md) §3 说的那种浪费。

### 入口校验

`继续到` 在**入口**校验两件事。引用了**没被声明要取的字段**，条件就**永远判不了**，那是个静默的坑：

1. 表达式里的字段名**存在**；
2. 这些字段**本片会取**（[状态层](../状态层/README.md) G3 的「AI 要才取」由条件声明决定）。

这与[接口层/README](../接口层/README.md) §2① 那条"动作算子在入口校验它自己那一格"是同一个手法。

## 3 时限：**必填**，而且每一段都有（用户裁定）

**所有条件判断都必须带最大时限**；到点**立即暂停**，不管条件成没成立。

- **由 AI 给，必填**——"这一段该等多长"随战局变，**没有合理的默认值**（用户裁定）；
- **时间判定也要给**（看起来冗余：它的目标时刻本身就是界）——**但逻辑帧是从费用读数推算出来的**（[时间基](../../30-专题/时间基.md)），读数一旦失准，那个时刻可能永远不来。**兜底就是给这种情况的。**

### 时限用哪个刻度：游戏时间，**计时器与游戏时间对齐**（用户裁定）

工具内部维持一个**游戏时间钟**：由墙钟积分、速率随[时间态](时间态.md) 切换，倍率来自[设备层](../设备层.md) §3 的校准（未实测）。

| | 常速 | 慢放（10 倍） |
| --- | --- | --- |
| 1 游戏秒 = | 1 秒墙钟 | **10 秒墙钟** |

**别拿 `time` 直接当时限**——那是墙钟，在慢放下会把"8.5 秒"变成"0.85 秒"的量。

## 4 结果：三值，加一句"为什么停"

**条件是三值的**（[契约层](../契约层.md) §2 定）：

| 结果 | 什么意思 |
| --- | --- |
| **一定真** | 区间字段与阈值的关系已经确定成立 |
| **一定假** | ……确定不成立 |
| **判不了** | 字段是未知 / 未采样，或区间跨在阈值两边 |

**这三值不写进字段**（用户裁定）：字段那一侧已经有**三态 / 形态 / 置信度**三个轴在表达不确定性了，再加一个就是**第四种重复**。**只把它做进给 AI 看的形式**——`继续到` 的返回，和[快照](../状态层/快照.md) ⓪ 的「本段结束原因」。

### 一段怎么结束（与[执行与失败](../接口层/执行与失败.md) §3 对齐）

| 结束 | 报什么 |
| --- | --- |
| 条件**一定真**命中 | 正常 |
| **时限到达** | **"未命中"，而且要分清是哪一种**：条件**确定不成立** ／ 条件**从未确定成立**（全程判不了）。**两者对 AI 的意义完全不同**——后者意味着判据或字段该换，前者意味着计划该改 |
| 画面已不是战斗界面 | 结算或退出（[结束.md](结束.md)） |
| 执行中止 | 拒绝 / 断连 / 脱同步 |

> **时限到达不是成功**，而且**不许被当成"条件成立了"**——这是零假事实在条件侧的落点。

## 5 两段式：一对条件，共用这套文法

AI 觉得时机重要，就给出**一对**：

- **粗条件**（容差大，常速下判）→ 命中则**进慢放**；
- **细条件**（要卡准的那一下，慢放下高频判）→ 命中则**暂停**。

- **两个都用本节这套文法**（含时限、含三值）；
- **"要卡帧"不需要另开开关**——给出这一对就等于说了这一段要卡帧（[识别时机.md](识别时机.md) §3）；
- **细条件的"判不了"同样由时限兜住**。

## 6 频率：机制在这里，数值不在这里

- **谁控制它** → 已经定了：**AI 可传**（[识别时机.md](识别时机.md) §2 的三档强度）；
- **默认值是多少、可调范围多宽** → **落地的事**，现在写就是假精度（与[状态层](../状态层/README.md) G4 同一条理由）。

## 尚未定

- **游戏时间钟的速率怎么切**：慢放的进出是工具侧知道的，但**切换点与游戏帧的对齐**有误差（按哪一帧算），要实测；
- **"判不了"能不能更细**：现在只给三种结果，**不区分是哪个子表达式判不了**（与 / 或 之下）；
- **粗条件命中 → 进慢放之间**那几帧的误差（进慢放本身要一次注入）。
