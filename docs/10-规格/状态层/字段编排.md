# 字段编排

> 状态：讨论中 ｜ 环与编排、三条合成规则、终点的两条去处、时长传播、四条传播性质已立；实现口径待定

对应代码：`src/ark/engine/state/`。

## 它是什么

**从识别结果到字段效果的那一段变换。** 它值得单独一份，因为它**服务两个消费者**：

| 消费者 | 产出落到哪 |
| --- | --- |
| [一档（基础数值）](基础数值.md) | 折进「当前有效值」——**不命名**，AI 只要那个数 |
| [注册字段](注册字段.md) | 一个新名字，进快照 ⑥ |

**它与执行侧的编排零语法交集。** 那边编排**动词**（adb → 手势原语 → 游戏动作，[设备层](../设备层.md) §1），这边编排**值**。只有一个搭接口：**有副作用的读环会驱动一次执行**（§8）。

**它跟「原语」「方法」也不是一回事**：原语回答"**问什么**"（[原语.md](../视觉层/原语.md)），方法回答"**怎么做到**"（[识别方法.md](../视觉层/识别方法.md)），而这里管的是"**怎么把一环串成一串**"。

## 1 环与编排

**一个环 = [方法清单](../视觉层/识别方法.md) 里的一行**（方法必须原子，否则这一栏永远说不清）。

```
环 = 方法 + 输入绑定 + 产出（一个槽）

输入绑定：每个输入要么绑到「外部」——一档 / 工具固定提供 / 我们自己的记录 / 资产 / 一个注册字段，
          要么绑到「前面某一环的产出」
```

- **环的产出天然是中间量**——它没有名字，也不进快照。铃兰那个案例里"范围内的敌人集合"、"这个敌人被停顿了吗"都是这一档；
- **只有编排终点的产出才有"去处"**，见 §5；
- **编排的产出是一个槽**（三态 × 载荷 × 置信度，[契约层](../契约层/README.md) §1），不是一个动作。

## 2 编排里可以有「如果」（用户裁定）

**必须有，而且不能禁。** C 族里那条方法就叫[「效果链推算」](../视觉层/识别方法.md)，定义是"**由 A 触发的 B**"——**它本身就是条件求值**。禁掉"如果"等于把方法清单砍掉一半。

允许的是这些，**全部是纯函数**（同样的输入永远同样的输出）：

- **分段取值**：`脆弱(敌人) = 在范围内 ∧ 被停顿 ? 40% : 0`；
- **按输入挑通道**："有权威读数就用它，否则用推算"（[README](README.md) G2 本来就有的主次）；
- **按输入挑环**："敌人少就逐个检测，多就报聚合下界"——**看着像"看战场情况选做法"，但它是 AI 自己写的，而且结果更诚实**；
- **枚举触发源**：铃兰那个案例里，"被停顿"是**数据库里所有能触发停顿的效果**枚举出来的**触发条件**，不是指向一个叫"停顿"的字段。

> **粒度线① 管不到这里，这是故意的。** [接口层](../接口层/README.md) §2① 立"算子不许有分支"这条线，理由是**"把判断力留给 AI"**——它管的是**我们**的算子不许替 AI 判断，**不是 AI 自己不许判断**。编排是 AI 自己写的，判断力本来就在它手上。

## 3 编排里不许的两样

| 不许 | 为什么 |
| --- | --- |
| **动词** —— 开技能 / 部署 / 撤退 | **原始红线的本体**：编排的产出只能是一个槽。**它的语法里没有动词** |
| **时机** —— 等待 / "等 X 出现再读 Y" / "条件成立了才取" | **字段的值是"此刻值"**（[README](README.md) G3 的默认值）。等待会把**一个时刻**变成**一段时刻**，那时它就不是字段了 |

## 4 方向是单向的：编排 → 槽 → 条件

条件判定（粗条件常速 / 细条件慢放，[控制层](../控制层/识别时机.md)）**不在编排里面，它在编排的下游**。它的输出是"**什么时候停下来**"，不是"某个字段等于多少"。

```
编排 → 槽 → 快照看 ／ 条件读 → 决定什么时候停
```

**这条不是洁癖，是在堵一个循环**：条件要引用字段；若编排里又能引用"某条件成不成立"，就成了**字段等条件、条件等字段**。而"时机"必须留在编排外，也正是因为**等待已经有自己的家了**。

## 5 终点产出的两条去处

| 去处 | 判据 | 结果 |
| --- | --- | --- |
| **折进一档的「当前有效值」** | 这个效果**能落到 20 项里某一项的绝对值上**（停顿 → 移动速度） | **不命名**、不进快照。这就是[基础数值](基础数值.md) 那条"主防线"的**机制**，不是一句口号 |
| **注册字段** | 落不上，但影响决策（脆弱 → 受到的伤害） | 命名、进快照 ⑥，见[注册字段.md](注册字段.md) |

**判据本来就存在**（[注册字段.md](注册字段.md) 的判据表），这里只是把"**往哪送**"补上。

## 6 合成规则：三条（用户裁定）

一个效果可能有**多个来源**，合并它们的是数据库里那条效果的**合成规则**：

| 规则 | 何时用 |
| --- | --- |
| **同名取最高** | **默认，几乎全部** |
| **加算** | 备用（特殊情况） |
| **乘算** | 备用（特殊情况） |

**规则本体在[游戏数据库](../资产生成器/游戏数据库.md) 的效果定义里**，本文件不复制——改规则只动数据库一处。

> **这三条规则全部要求"先按效果名分组、再合并"**，所以字段的键**必须**是 `效果 · 单位`：**键里不能含来源**。否则两个来源会变成两个字段、互不相干，**"同名取最高"根本没机会发生**——而 AI 会看到两笔独立事实，很可能**自己去相加**。那是假事实。

### 来源：不进键，但每片跟着值走（用户裁定）

**身份与溯源是两件事，别让一个去干另一个的活。**

| | 是什么 | 为什么这么放 |
| --- | --- | --- |
| **键（身份）** | `效果 · 单位类别` | 上面那条：三条合成规则都要**按效果名分组**，所以身份里**不能**有来源 |
| **来源（溯源）** | 这个值**是哪条通道给的** | **会漏检、会错检**。AI 觉得某个数奇怪时，必须知道**去怀疑哪一条** |

**来源是通道的属性**（注册时固定），而且**结构化、工具生成**——和键同一条理由：**AI 不起名**。

| 来源标签的部件 | 例 |
| --- | --- |
| 单位 | 铃兰 |
| 技能 / 天赋 | 天赋二 · 三技能 |

#### 合成天然产出「成分表」

合并多条通道时**每一份贡献都过手**，所以成分表是**免费的副产物**：

```
成分：停顿 −80%（铃兰 · 三技能） ｜ 减速 −30%（某干员 · 天赋）
结果：移动速度 ×0.2                     ← 按该效果的合成规则合完之后
```

- **取最高**的字段：表里列出全部贡献，**标出谁赢**；
- **加算 / 乘算**的字段：列出全部贡献与它们的和 / 积；
- **每片重算**——技能一结束、来源一撤，表**跟着变**。这就是"来源也要跟着变化"那条。

#### 它服务的是「看原帧」那个逃生舱

**溯源要回答的最少问题**："这个值是哪条通道给的？"——有了通道就有了它的**输入绑定**，于是：

```
可疑的值 → 来源（哪条通道）→ 它的输入绑定 → 这些输入里哪几个本片降级了 → 看哪几帧原帧
```

**`看原帧` 因此从"盲看"变成"有目标地看"**——这正是它作为逃生舱该有的样子。

**不做环级溯源**：通道级够了。一个通道的输入绑定是**声明过的**，AI 拿它和快照 ⓪ 的[存疑清单](快照.md)一对，就缩到少数几个读数了。

## 7 时长沿编排传播

**编排传的不只是值，还有"还剩多久"。** 铃兰那个案例里：

```
橙条剩 10 秒 → 技能窗口剩 10 秒 → 停顿剩 10 秒 → 脆弱剩 10 秒（"等长时间"）
```

- 每一跳的规则**来自数据库**——"等长时间"不是通用规则，是那条效果的触发关系；
- 所以**时效不是独立字段，也不是注册字段的一个属性**：它是**编排产出那个槽的一部分**（[我方干员.md](我方干员.md) 的「尚未定」因此收口）。

## 8 沿编排传播的四条性质

受理**算得出来**，不需要问 AI（[注册字段.md](注册字段.md) ② 用它）：

| 性质 | 怎么传 | 传错的后果 |
| --- | --- | --- |
| **副作用** | **取并**：有一环要"点详情" → **整条编排有副作用** | 它会被当成无损字段进默认快照，于是每片都在误放技能；而且**这是它与执行侧唯一的搭接口**（挂在 `继续到` 的「点谁」上） |
| **可补齐性** | **取最弱**：混了一条读，整条**不能补** | AI 以为整条轴都有值 |
| **误差单边 / 双边** | **取最坏**：只要有一环是**双边**，整条就是双边 | **这是假事实的入口**——方法清单说"双边就是假事实" |
| **时间态** | **取最苛刻**：由最严的一环决定 | 常速下跑了一条本该慢放才准的环 |

**外加一条代价**：编排的代价 = **环数 + 其中要取像的环数**。它是**算出来的数**，随受理一起返回。

## 9 走一遍：铃兰那个案例

**请求**：效果 = 脆弱；作用对象 = **敌方单位**；编排 = 三环。

| 环 | 方法 | 输入 | 产出 |
| --- | --- | --- | --- |
| 1 | **几何判定** | 三技能形状（数据库 + 技能窗口）+ 铃兰位置朝向 + **敌方位置字段** | 范围内的敌人集合 |
| 2 | **效果链推算** | 数据库的触发关系（**枚举所有能触发停顿的效果** → 脆弱）+ 该集合 | 每个敌人有没有脆弱 |
| 3 | **合成规则** | 数据库的效果定义（同名取最高） | 20% × 2.0 = **40%** |

**起点**：**橙条剩 10 秒**。整条编排**只需要读橙条与敌人位置，不识别任何特效**。

**时长**（§7）：橙条 → 技能窗口 → 停顿 → 脆弱，全程 10 秒。

**两条去处同时出现在这一个案例里**——这正是它值当样板的原因：

| 产出 | 去处 |
| --- | --- |
| 停顿 → **移动速度 ×0.2** | **折进一档**（§5），**不命名** |
| 脆弱 → **40%** | **注册字段**（一档里没有"受到的伤害"这种量） |

**沿编排传播**（§8）：编排里**没有读环**（只需读橙条和敌人位置，其余全在数据库与记录里）→ **无副作用**（可进默认快照）· **可补齐** · **没有双边环**。

**同一个技能的另一半被劝退**：停顿 → 移动速度落进一档，**不注册**。

**键怎么长出来的**：`脆弱 · 敌方单位`——**不含"铃兰三技能范围内被停顿的"**。那些是**编排内部的部件**。理由见 §6：**若含来源，第二个来源就取不了最高了。**

## 尚未定

- **编排的复杂度有没有上限**：不是怕它变成程序（动词与时机已经挡住了），是怕每片成本失控。**先把代价这个数给出来**，再谈要不要设上限；
- **同名来源漏枚举**：铃兰那个案例靠"AI 去数据库搜关键词、枚举全部触发源"，但这条**做不成统一检测**——各字段的触发条件千奇百怪（用户裁定，受理暂不加这条检查）。于是漏了就是**静默的假事实**，只能靠 AI 自觉。**这一条要记着**；
- **编排能不能引用"另一条编排的中间量"**：现在只能引用**终点产出**（一档的项 / 注册字段）。若真需要跨编排共享中间量，那是另一个决定。
