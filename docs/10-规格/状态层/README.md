对应代码：`src/ark/engine/state/`。这个概念在《概念设计共识》里叫「抽象逻辑空间」。

## 这份目录负责什么

**一个时间片下，该给玩合约的 AI 呈现哪些信息。** 干员、敌人、费用、格子、场地机制各怎么表示，每个字段带什么置信度，字段的"未采样 / 已采样但为空 / 有值"三态。

它不是"战场本体论"——**只收 AI 排轴要用的东西**。

**核心验收标准在这里**：零假事实。数不清敌人的时候要明确说"数不清"（给下界或区间），而不是猜一个精确数字。

**字段的列法**：按「**AI 排轴时要做的每一个决策**」倒推，而不是按「画面上有什么」正推。倒推的结果就是 G9 那张索引。

## 全局说明（字段条目里不重复）

**G1 三个轴，别混。**

| 轴 | 回答什么 | 取值 | 归属 |
| --- | --- | --- | --- |
| **三态** | 有没有看到 | 未采样 / 已采样但为空 / 有值 | [契约层](../契约层.md) 的类型 |
| **取值形态** | 这个值长什么样 | 精确 / 区间 / 下界 / 上界 / 未知 | 值的类型标签 |
| **置信度** | 这次测量有多可靠 | 视觉原语内部算出的连续量，无量纲 | 只属于"读" |

- **三态一律带**——为的是处理统一、代码简单。算类与记类字段也有三态，只是"空"常常用不上。
- **取值形态不是一个等级，也不是全序**：区间 `[15,16]` 比下界 `15` 信息更多，所以"区间"并不比"下界"低。**名字已定**（曾叫「质量等级」——那个名字的坏处正是**暗示存在一个全序**，而这里没有）。
- **下界与上界是一对，看单调性**：**只增不减**的量（已击杀数）读到旧值时给**下界**；**只减不增**的量（生命）读到旧值时给**上界**。两个方向都不许把旧读数当当前值。
- **「分档」不是独立形态**：粗略的档位就是**区间**（一档对应一段值域），档位到区间的换算属于**原语规格**（[视觉层/原语.md](../视觉层/原语.md)），不占形态词表。
- **置信度由证据通道决定**：读类必有（原语算的），算类与记类必无（没有识别过程）。

**G2 证据通道三类。**

| 类 | 绑定 | 置信度 | 典型不确定来源 |
| --- | --- | --- | --- |
| **读** | 视觉原语 + ROI | 有 | 识别质量、候选重叠、量化 |
| **算** | 输入字段 + 合成规则 | 无 | 误差传播、时间漂移 |
| **记** | 我们自己的记录 | 无 | 与游戏脱同步 |

一个字段**可以有多条通道**（费用：读卡片数字 + 按公式算；注册字段：我们给的走算、敌人自带的靠读）。多通道必须写**谁主谁次**，以及**不一致时报冲突**——不挑一个。

**G3 其他全局约定。**

- **单位与参照系词表**：逻辑帧 / 格坐标 / 像素 / 比例 / 计数 / 秒。
- **一档（基础数值）是一组跨类字段**：成员、通道、主次、边界 → 见 [基础数值.md](基础数值.md)。
- **原语（问什么）→ 见 [视觉层/原语.md](../视觉层/原语.md)**：七条，**字段条目引用的就是它**。
- **识别方法（怎么做到）→ 见 [视觉层/识别方法.md](../视觉层/识别方法.md)**：一张方法清单，**编排里每一环挑的就是它**（**一个环 = 清单里的一行**）；哪几个方法答哪个原语，写在那张表的「答哪个原语」列里。而"怎么把几环串起来"归[字段编排.md](字段编排.md)。
- **记录与快照**：观测迹变化驱动；每次暂停给一次快照；AI 按需声明即可做低频子集（[时序层](../时序层.md) §5、[控制层](../控制层/识别时机.md)）。
- **快照分两类字段**：**默认取**（免费且无损，每次快照都给）与 **AI 要才取**。后者这个名字底下其实混了**两种代价**，落成两个不同机制：**有损**（读了会改变战局或时间态，例如点开详情面板）走 `继续到` 的「点谁」参数；**昂贵**（只是不想一直读它）由**暂停条件声明自己引用了哪些字段**决定（§5.4 第 4 条）。见[接口层/算子清单](../接口层/算子清单.md) §3。
- **我们自己主动触发的状态转移，一律走记 / 算，不走读**：我们给的 debuff、我们开的技能窗口、**阻挡权的转移**（谁先挡、被技能或撤退转交）都是这一类。**"读不出"往往不是坏事——它意味着这事本来就该算**。**例外**：敌人能改写的输入（例如**通过攻击降低我方干员的阻挡数**）——那类必须走读，而且它**有权威读数**（[基础数值.md](基础数值.md) 的阻挡数在详情面板里）。
- **命名冻结**：字段名就是 AI 引用它的名字，改名等于改接口。**自定义字段由工具按效果键确定性生成**（键 = `效果 · 作用对象 · 方法`），**不由 AI 起名**，否则轴不能跨轮次复用。
- **默认值**：默认"此刻值、无损读取"；**偏离默认的必须在条目里显式标出**。
- **不变量**：编号 I1、I2…，条目里只写参与的编号。现在有四条，都是**自检**——不满足就说明有一次读数错了，**或者有一个机制我们没建模**：

  | | 内容 | 参与字段 |
  | --- | --- | --- |
  | **I1** | **生命只减不增** | [全局与HUD.md](全局与HUD.md) 生命 |
  | **I2** | **已击杀数只增不减** | [全局与HUD.md](全局与HUD.md) 已击杀数 |
  | **I3** | **剩余可放置角色数 = 部署位上限 − 在场我方干员数**，且恒 ≥ 0 | 全局与HUD.md 剩余可放置角色数 · [我方干员.md](我方干员.md) |
  | **I4** | **总数 = 已击杀 + 漏掉 + 在场 + 未出场 + 残差**，残差应 ≈ 0 | 全局与HUD.md 的 敌人总数 · 已击杀数 · 生命（→ 漏掉）· [视觉层/敌方单位.md](../视觉层/敌方单位.md) 的在场估计 |

  **I1–I3 是跨快照的**（对比前后两片）；**I4 是片内的**——它是一条**账目恒等式**：

  - `漏掉` = 初始生命 − 当前生命（初始生命由关卡 / 词条给定）；
  - `未出场` 由**路线资产（含出怪）+ 游戏时间**算出；
  - **`在场` 是余项**——也就是说"**有几个敌人在场**"这件事，本来就可以**算**出来，视觉只用来定位与分类；
  - **它一次同时校验四个独立读数**，而且出错方式是**安全的**：某一项错了会让残差非零、当场暴露，而不是悄悄算出一个错数——非零就进[快照](快照.md) ⓪ 的**存疑清单**（「账目」那一类）；
  - **残差非零的额外含义**：有我们没建模的机制（**召唤物不计入总数但在画面上** · 机制杀 · 词条改出怪）。见 [视觉层/敌方单位.md](../视觉层/敌方单位.md) 的第 8 步。

**G4 两项故意不写进条目。** 采样代价（逐字段估算是实施阶段的事，方案层给不准，给了就是假精度）；以及"这个字段服务哪个决策"（那是 G9 的职责，逐字段写就是双写）。

**G5 逐字段条目的固定项序。** 语义 → 语义边界 → 证据通道 → 多通道冲突 → 允许的形态 → 降级触发 → 单位与参照系 → 时刻 → 不变量 → 有损？（样板见[敌方单位.md](敌方单位.md)）。

- 顺序是固定的，**没有内容就写"不适用"并说明为什么**，不留空行。
- **一类里全员相同的项提到该类的全局说明**，条目里略过——否则条目会退化成抄全局说明。
- **一档（基础数值）不走这套**：它是跨类的一张表，理由写在[基础数值.md](基础数值.md)「逐项表不写哪四件事」。

**G6 字段分三档，只有一档由我们枚举。**（用户裁定）

| 档 | 谁负责 | 在哪 |
| --- | --- | --- |
| **一档 = 基础数值** | **我们枚举**，成员固定（干员 9 项 / 敌人 11 项） | [基础数值.md](基础数值.md) |
