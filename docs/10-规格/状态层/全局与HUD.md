# 全局与 HUD

> 状态：讨论中 ｜ 逐条条目已写（6 项）

一类：**一个时间片里只有一个值、不属于任何单个单位**的东西。

## 本类全局说明（条目里不重复）

- **时刻**：一律**此刻值**。
- **有损？**：一律**否**——本类不是原生 UI 的读数，就是我们自己的计时，都进**默认快照**。
- **不变量**：还没有编号；本类已经产出三个候选，见「尚未定」。

## 本类的字段

| 字段 | 证据通道 | 取法 |
| --- | --- | --- |
| 游戏时间（逻辑帧） | 算（秒表为主轴 + 费用读数校准） | 默认 |
| 当前费用 | 读（整数用字形 + 小数用进度条相位）+ 算（回费公式） | 默认 |
| 生命（蓝门血量） | 读（字形模板匹配） | 默认 |
| 已击杀数 | 读（字形模板匹配） | 默认 |
| 敌人总数 | 读（同一次读数）+ 算（路线资产） | 默认 |
| 剩余可放置角色数 | 读（字形模板匹配） | 默认 |

**「已击杀数 / 敌人总数」原来是写成一项的**，写条目时拆成两项：它俩的形态与降级规则不一样，合成一项就没法各自声明。

**不在本类**：初始费用与自然回费速率——它们是 [时序层](../时序层.md) §3 前提头的一项，不是战局字段。

## 条目

### 游戏时间（逻辑帧）

- **语义**：从**开局那一帧**算起、按逻辑帧计的游戏内时间。
- **语义边界**：
  - 它**不是从画面上读出来的**，是我们自己的时间轴——怎么得到由[时间基](../../30-专题/时间基.md) §4 定义，这里只承担"它是一个字段"的后果；
  - 它是**所有"还有多久"类推算的自变量**，所以它的形态**会往下传**：它成了区间，所有时效、所有"某怪什么时候到某格"都跟着成区间。
- **证据通道**：**算**（工具秒表为主轴 + 费用读数定期拉回）。
- **多通道冲突**：主轴与校准**不是并列的两路读数，是校准关系**——以费用推算的时刻为准，同时**把差值记下来**：差值本身就是"时间基准漂移"的度量，超阈值就上报。
- **允许的形态**：**精确**（帧号）／**区间**（零点没抓准，整条轴平移）／**未知**（从没抓到开局）。
- **降级触发**：长时间拿不到任何费用读数 → 漂移无从约束 → 报区间；再久报未知。
- **单位与参照系**：逻辑帧（整数）；对外呈现时附秒。

### 当前费用

- **语义**：此刻**还能花**的费用余额。
- **语义边界**：
  - 它是**余额**，不是"已花费"——后者是记类字段（[README](README.md) G9 的 D13）；
  - 初始费用与自然回费速率**不在**字段里，它们是前提头的一项；
  - 读到的不是整数：**整数 + 进度条相位**，相位给这一秒之内的小数，所以它是实数、能精确到零点几帧（[时间基](../../30-专题/时间基.md) §3.3）。
- **证据通道**：**读**（整数用字形模板匹配，小数用进度条相位）+ **算**（余额 = 初始费 + ∫回费 − Σ消费 + Σ先锋回费）。
- **多通道冲突**：**读为主**（原生 UI 报的数），算的用途是给游戏时间做校准、顺带校验推算；不一致 → 冲突上报。
- **允许的形态**：**精确**／**区间**／**未知**。
- **降级触发**：数字被遮挡 → 未采样；逐位歧义 → 争取降成**区间**（[视觉层](../视觉层/识别方法.md) 那条待查线索），做不到就是未知。
- **单位与参照系**：费用（实数）。

### 生命（蓝门血量）

- **语义**：还能漏几个怪。**它不是血条，是一个计数。**
- **语义边界**：
  - **全局单值**：多个蓝门共享它，不是每门一个；
  - 漏小怪扣 1，**漏 boss 直接扣完** → **不能从"漏了几个怪"反推血量**，只能直接读；
  - 反过来成立：**单个怪漏掉时的下降量，就是那个敌人的「生命值扣除数」**——这是敌人侧那条间接通道（[基础数值.md](基础数值.md)）；
  - 合约常见词条：**初始生命变为 1**（等于不能漏怪）；
  - 它**只减不增**（用户确认）→ 这是不变量 **I1**，也意味着**旧读数可以当「上界」用**。
- **证据通道**：**读**（顶部 HUD 字形模板匹配）。
- **多通道冲突**：不适用——那条"算"不自立（它的输入正是读来的漏怪事件），只能作校验，不构成并列读数。
- **允许的形态**：**精确**／**上界**（读到的是旧值时）／**未知**。
- **降级触发**：数字被挡或认不出 → 未采样；只剩旧读数 → **上界**，不当作当前值。
- **单位与参照系**：计数（个）。

### 已击杀数

- **语义**：本关累计被击杀的敌人数。
- **语义边界**：
  - **被召唤出来的敌人不计入**——召唤多少取决于母体活了多久、触发了几次，一局内不是定值，游戏自己把它排除在计数之外；
  - 所以**不能拿它推"敌人清完了"**：它只覆盖路线资产里的敌人；
  - 它与敌人总数相等时**游戏判胜**——这是**游戏事实，不是我们另设的判据**（局终不设独立判据，见[控制层](../控制层/结束.md)）；
  - 它**只增不减**（不变量 **I2**）：读到回落，必然是其中一次读数错了。
- **证据通道**：**读**（顶部 HUD 字形模板匹配）。**没有"算"的通道**：哪个敌人是谁击杀的不可观测。
- **多通道冲突**：不适用（只有一条通道）。
- **允许的形态**：**精确**／**下界**（读到的是旧值时）／**未知**。
- **降级触发**：读数失败 → 未采样；只剩旧读数 → **下界**，不当作当前值。
- **单位与参照系**：计数（个）。

### 敌人总数

- **语义**：本关路线资产里的敌人总数。
- **语义边界**：
  - **同样不含召唤物**，与已击杀数口径一致，否则两个数不可比；
  - **一关之内是常量**，开战前就知道；
  - 正因为是常量，它**更像前提头的一项**而不是每片快照里的字段——与[时序层](../时序层.md) §3 前提头怎么对齐还没定，见「尚未定」。
- **证据通道**：**读**（HUD 上它与已击杀数在同一次读数里一起给）+ **算**（输入是路线资产，没有运行时输入）。
- **多通道冲突**：两条都可靠，正好**互为校验**；不一致 → 冲突上报，不挑一个。
- **允许的形态**：**精确**／**未知**。
- **降级触发**：两条都拿不到才叫未采样——**它有资产兜底，是本类唯一不靠识别的字段**。
- **单位与参照系**：计数（个）。

### 剩余可放置角色数

- **语义**：还能再下场几个我方干员。
- **语义边界**：
  - 位置在**右下、费用的下方**；
  - 它与费用是**两个独立约束**：**钱够不等于有位**；
  - 干员离场（阵亡 / 撤退）**会释放这一席**（用户确认）→ 它是**同时在场的余额**，不是累计次数；
  - 上限（本关有几席）来自关卡 / 合约，属前提头；这个字段是**余额**，两者由不变量 **I3** 拴在一起。
- **证据通道**：**读**（字形模板匹配）+ **算**（上限 − 在场我方干员数）。
- **多通道冲突**：**读为主**；算与读不一致 → 冲突上报。
- **允许的形态**：**精确**／**未知**（余额既会因部署减少，也可能因离场回升，所以不单调，旧读数不能当界用）。
- **降级触发**：读数失败 → 未采样。
- **单位与参照系**：计数（个）。

## 尚未定

- **敌人总数与[时序层](../时序层.md) §3 前提头怎么对齐**：它是常量，本该只给一次而不是每片都给；
- **G2 的三类通道里没有"查资产"这一类**：本类已经出现"一个值直接从数据库 / 路线资产来"的情况（敌人总数、基础数值的 20 项全都是）。现在一律归到**算**（算的输入可以是资产），要不要显式承认这一类，等字段表写完再定。

**已经定下来的两条**（原来是这里的问题，已由用户确认并落到条目里）：生命**只减不增** → 取值形态因此补了**「上界」**；干员离场**释放**部署席 → "算"通道成立。三条不变量 I1 / I2 / I3 的编号在 [README](README.md) G3。
