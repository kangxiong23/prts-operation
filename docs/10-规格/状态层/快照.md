# 快照

> 状态：讨论中 ｜ 骨架已立；**默认取名单、注册字段的摆法**两处待定

对应代码：`src/ark/engine/state/`。

**快照 = 一个时间片上、抽象逻辑空间的完整样子**——也就是"一次截图应该变成的样子"。

```
截图 →（视觉层：识别与推算）→ 数值 →（状态层：这一份） → 快照 → AI
```

## 它不是什么

| 不是 | 因为 |
| --- | --- |
| **不是截图** | 截图是像素。AI 不该看像素——看像素就是它自己上多模态，那就回到了这条设计的起点。 |
| **不是观测迹** | 观测迹是**变化流**（`帧号, 字段, 槽`），见[时序层](../时序层.md) §5；快照是**某一刻的样子**。 |
| **不是每片都全量存** | 快照是**视图**：由观测迹 + 前提头 + 静态底图重建出来。存的是迹，不是每片的全文。 |

**一次暂停给一次快照**；"AI 要才取"的字段按 AI 事先的声明取（[README](README.md) G3）。

## ④ 敌人块：一层类型表 + 一层个体

**两层，不是"每个敌人一份 11 项"。**

### ④a 类型表（一局一份，静态）

本局出现过的敌人类型，每个类型一行：**一档 11 项的有效值**，外加生命上限（血条的分母）与几个**类型常量**——移动类型 · **占用阻挡位数（默认 1，少数 2–3）** · 可被阻挡的初值。

- **为什么按类型去重**：同一类型的 11 项对每个个体都一样（都是数据库 + 词条算出来的），逐个体重复就是 N 倍浪费——跟[地形](地形.md) 的"底图与覆盖层分开"是同一个手法；
- **只列本局出现过的**，不是整张敌人表；
- **它一局内不变**，所以严格说也算前提头（跟"敌人总数"一样）。

### ④b 在场个体（每一片，变长）

**两层表达**（[概念设计共识](../../概念设计共识.md) §5.4 已定）：

1. **枚举可辨认的个体** —— 每条：位置 · 归属类型（指针，指向 ④a）· 血量 · 状态 · 是否被阻挡；
2. **一条聚合兜底** —— 数量**下界** + 区域 + "其中 N 个看得清"；
3. **被阻挡的那一类另按「阻挡位」组织**——重叠时个体分不开，但几何给得出**上界**（该干员的阻挡数，来自我们自己的记录），所以给的是**区间**而不是下界。见[敌方单位.md](敌方单位.md)。

**「是否被阻挡」是这一对（敌人, 干员）的性质**——要看敌人的占用阻挡位数、也要看这个干员能不能挡空中。逐项规则在[敌方单位.md](敌方单位.md)。

两条硬要求：

- **聚合兜底不许省**：数不清是常态，零假事实要的是"**老实说数不清**"，不是"精确数出三个"；
- **"有一个东西但我认不出是什么"必须能表示**：位置 + 类型=未知 + 能读到的其余项，**而不是把它丢掉**。

逐项的形态与降级在[敌方单位.md](敌方单位.md) 的表里；怎么读出来在[视觉层/敌方单位.md](../视觉层/敌方单位.md)。

## 位置的呈现：数值为准，图是可选的派生视图

两条结论，**都是实测确认的**。

**① 图不能替代数值。** 位置以**连续格坐标**给（见[敌方单位.md](敌方单位.md)）；把位置只画在图上、不给数值，读的人会**数不准第几格**——而"第几格"恰恰是这个字段的全部用处。

**② 图擅长"哪一格上有谁"，不擅长"谁离谁多远"。** 涉及**比较、计数、距离**的问题，图不但没帮上忙，还会**诱导错误**——图上"看起来挨着"并不等于条件成立。

于是默认这样给：

| | 给什么 |
| --- | --- |
| **默认** | 坐标（数值）——**权威** |
| **不做** | 每一片重画一张网格图 |

**将来真要做图，就做「合成图」，不要另发一张网格**：把单位标进**已有的地形图格子**里，增量只有"单位个数个字符"；而另发一张同格网格要**重发一整张**（空格也得占位）。图与表信息等价，所以它**是派生视图，不构成双写**。

**为什么不默认给**：AI 靠坐标已经答得出"哪一格上有谁"（实测：给不给图，这类问题基本持平），而图是**随时可加的**——代价小、可逆。所以这条留成**一个以后可加的开关**，不押成现在的判断。

**取图的频率是仪表**（与 `看原帧` 同一个用法）：AI 反复要图，说明数值这一侧缺了空间感。

## 前提头不在每一片里

**一局内不变的那几个数不进快照**，它在轴的开头给一次：初始费用 · 自然回费速率 · 部署位上限 · 练度指纹（标识）· 本关词条 · **路线资产指针**。

见[时序层](../时序层.md) §3。**「敌人总数」也属于这一类**（它一关内是常量，只是 HUD 顺带也给）。

## 页眉为什么值得单独一块

- **D17「这份快照是哪一刻的」**：帧戳 + 时间态。**少了它，快照就是无源之水**——AI 无法把它放进轴里。
- **本段为什么结束**：条件命中 / 上限到达 / 画面已不是战斗界面 / 执行中止（[执行与失败](../接口层/执行与失败.md) §3）。它是 [AI侧](../AI侧/README.md) §1③ 的证据之一，所以要有落点。
- **D16「这份快照可信吗」**：它其实是三段，**一段比一段深**：

| | 回答什么 | 谁带 |
| --- | --- | --- |
| **槽自己** | **这个数**有多可信 | 每个槽的三态 / 形态 / 置信度 |
| **存疑清单** | **这一片**有哪些地方不可信、或者**可能错了** | 本文件，见下 |
| **成分表** | 这个数**是谁给的** | 多来源字段才有，见下 |

### 存疑清单

**它不是提议，是契约义务的落地。** §2.2 第 6 条写着：**未识别的内容显式上报为"未识别"，不得从抽象状态里静默消失。**

"散在几十个字段里 AI 未必看得见"只解释了它的一半；另一半是：

> **有些东西，字段级数据在结构上表达不了。**

| 类 | 里面有什么 | 为什么槽带不了 |
| --- | --- | --- |
| **读数** | 有字段降级 / 未采样 / 通道冲突 / **像素是从原帧还原的**（暂停字样遮挡，[控制层](../控制层/识别时机.md)） | 槽自己带——**这里只列名单** |
| **传播** | **一个读数错了，下游一族跟着错**：敌人类型未定 → **11 项整族存疑** | 各字段置信度**全都正常**，错的却是一整族（[基础数值](基础数值.md) 的边界） |
| **时间** | 判定节拍跟不上（[控制层](../控制层/识别时机.md) §7）；**费用读数失败 → 逻辑帧推算跟着失准** | 时钟不是一个字段 |
| **同步** | 我方位置自检失败 · 敌人位置漂移超限 · 轴与记录脱同步 | 跨字段 |
| **采样** | 两片之间**可能存在未观测到的变化**——观测迹是采样出来的，变了又变回来会漏掉中间值（[时序层](../时序层.md) §5） | 它是**缺席**的信息，不在任何字段里 |
| **账目** | I1–I4 被违反；**残差非零 → 有我们没建模的机制** | 一条跨字段的恒等式 |
| **动作** | 生效反馈 = **未确认** | 不是字段 |
| **静默** | 某条通道**长期未采样**（"这条编排可能断了"）· **该按需声明的字段本片没读**（阻挡数那种"不点就发现不了"）· **危险方向的漏检**（敌人血条存在性漏检 = **凭空造出一个满血**） | **它就是"我们不知道自己在不知道"**——[D-全局-09](../../20-决策记录/全局.md) 说这正是零假事实最怕的形态 |

**每一条是结构化的**：`类别 · 涉及哪个字段或来源 · 严重度 · 涉及哪几帧`。**不能是一段散文**——它有三个消费者：

| 消费者 | 拿它干什么 |
| --- | --- |
| **AI** | D16；以及 [AI侧](../AI侧/README.md) §1③ 那张"**凭什么改轴**"的证据表 |
| **离线难例采集** | [采集与验收](../采集与验收/README.md) §1 的**通用层**就是它的内容——尤其是**跨字段的那五类**（账目 · 同步 · 传播 · 采样 · 静默）：它们**字段级信号表达不了**，只在这里汇总，所以这里也是采集唯一读得到它们的地方。它按清单去挑帧、落原帧 |
| **溯源** | 和成分表对账：可疑的值 → 来源 → 输入绑定 → **本片哪几个降级了** |

### 成分表

多来源字段**每片要重算谁赢**，散在字段里同样看不见，所以在页眉汇总一份（[字段编排.md](字段编排.md) §6）——它同时是**溯源**的入口：可疑的值 → 来源 → 那条通道的输入绑定 → **该看哪几帧原帧**。

**只列多来源、或本片有降级的多来源字段**：单来源字段的来源就是它自己的定义，AI 注册时就知道，逐条重复是和"槽不逐条带帧戳"同一种浪费。

| --- | --- | --- | --- |

| D5 | 技能现在能不能开 | ③（技力 / 生效中 / 黄菱形；层数属要才取） + 资产 | ✅ |
| D6 | 什么时候开 | ② 游戏时间 · ③ 血量 · ④ 位置与数量（数量给下界） | ✅ |
| D7 | 能不能关 | ③ 生效中 + 资产 | ✅ |
| D8 | 这波怪什么时候到某格 | ④ 位置 / 类型（→ ④a 拿属性）· 资产路线 · ② 时间 | ✅ 带保留——属性没有对账对象 |

| D13 | 钱是不是不够 | ② 当前费用 + 记类（已用费用） | ✅ |
| D14 | 下次什么时候醒 | ② 游戏时间 | ✅ |

**结论：17 条全部答得完。** 敌人块补上之后，最后那 5 条跟着通了——**它是唯一的瓶颈，补完就没了**。

> **但"答得完"不等于"答得准"。** 我方 9 项里 6 项有权威读数；敌人 11 项是 **0 项**，全靠推算且没有对账对象。所以**覆盖上的缺口没了，准度上的缺口全在敌人侧**，只能靠数据库准确性与卷积识别质量兜住。
