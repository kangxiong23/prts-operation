# 我方干员

> 状态：讨论中 ｜ **能力清单**（字段由 AI 注册，我们不再逐个枚举条目）+ **位置自检**（新）

一类：**每个我方干员一条记录**。它是变长的——场上有几个就有几条；不在场的干员由备战席侧表示状态。

**干员之间不会重叠**（一格一个），所以敌人那套"分离信号"在这边用不上；**干员与敌人**的重叠归[敌方单位.md](敌方单位.md) 处理。

## 本类能提供什么（不写逐条条目）

取法默认是**默认取**；偏离默认的只有两行，已在表里标出。

| 字段 | 证据通道 | 允许的形态 | 该行特有的边界 |
| --- | --- | --- | --- |
| 身份 | **记**（部署记录） | 精确 | 答案是免费的——不需要识别 |
| **位置** | **记**（部署记录）**+ 自检**（差分图） | 精确 / 不确定在哪个格 / 未知 | **会失同步**，见下一节 |
| 朝向 | **记**（我们下的） | 精确 | **是常量**，不必每片都给 |
| 是否在场上（在场 / 再部署中 / 未下） | 记 + 读（备战席卡片） | 精确 / 未知 | 只许用**肯定证据**，不许用"场上找不到" |
| 血量 | 读（蓝条比例）+ 读（详情面板） | 精确 / 区间 / 下界 / 未采样 | **看不到 ≠ 满血**，见下 |
| 技力 | 读（绿条）+ 算 | 精确 / 区间 / 未采样 | **技能生效期间读不出来**，见下 |

| 阻挡数 | 算（数据库 + 技能账）/ 读（**点详情**） | 精确 / 未知 | **按需**；被敌人攻击降低时**必须读**才能发现（[敌方单位.md](敌方单位.md)） |
| **基础数值（有效值，9 项）** | 见 [基础数值.md](基础数值.md) | 由输入传播 | 我方 **6 项有权威读数**；攻速 / 间隔靠**出手节奏**间接反算 |
| 注册字段（本局按效果注册的自定义字段） | **由编排决定**——见[字段编排.md](字段编排.md) | — | **待定** |

## 位置：不靠识别得到，但可以被识别校验

**它是承重墙：**

| 谁依赖我方位置 | 依赖方式 |
| --- | --- |
| **阻挡权的几何判定** | 谁在哪个格 |
| **敌方的「阻挡位视图」** | 按干员组织 |
| **ROI 定位** | 用格坐标开窗口——**整格错位，窗口就开在隔壁格** |
| 部署校验 · 格占用 · D2 / D9 / D10 | 直接读它 |

**它由「记」得来，所以会失同步**：推拉类位移之后我们的记录就是错的，而且**没有任何东西会报错**——静默失效，正是零假事实最怕的形态。

**自检（新）：**

> 干净关卡帧差分图里，**我方干员也是一团变化像素**。它应该出现在**我们记录的那个格上**。
> **没出现、或者出现在别处 → 失同步，当场暴露。**

- 它与敌方块**共用同一条主通道**（[视觉层/敌方单位.md](../视觉层/敌方单位.md) 的差分），成本几乎为零；
- 修正方式是**按差分团重定位 + 上报冲突**，**不静默修正**；
- **边界**：干员正在阻挡敌人时，那一团是干员与敌人**混在一起**的 → 只能确认"附近有东西"，**不能精确定位**。越挤越不可靠（又是同一个规律）。

## 容易吞掉的语义边界

### 技力：技能生效期间，这个字段读不出来

场上只有两种条：**绿条 = 充能中**、**橙条 = 生效中（显示还剩多久结束）**。所以：

- **技能生效期间场上没有技力条可读** → 报**未采样**，或者由轴数据**算**；
- **永续技能**的条一直是橙（没有结束时刻）→ 读得出"生效中"，**读不出"还剩多久"**；
- **第 2 轮起的充能进度场上不显示**，只在详情面板里（[视觉层/技能详情通道.md](../视觉层/技能详情通道.md)）。

### 血量：看不到 ≠ 满血

我方血条是**常驻**的（不像敌人"显示 ⟺ 未满血"）。所以**看不到就是识别失败 → 未采样**——这边没有"看不到即满血"那种读法，也就没有敌人侧那个危险方向。

**两条通道的主次**：详情面板**更精确**，但要付出一次"点"（还可能误放技能）；蓝条**连续且免费**。两者不一致 → **上报冲突**，不挑一个。

### 朝向是常量，不必每片都给

它是"我们下的"，而且**战斗里改不了** → 它属于前提头那一类，不是每片快照都要带的字段。
（若存在能改朝向的机制，这一条要改成每片校验。）

**首轮那一次它是"读"出来的**——脚下白环上的黄箭头（[首轮探索/录轴](../首轮探索/录轴.md) §3）。那是一次性的事：**读到之后它就变回"记"**，线上仍然一次都不用读。

### 部署刚落地时，还选不中这个干员

**朝向选好、手松开之后，要过几帧才能选中该干员**（用户确认）。三个后果：

- **同一干员的两个动作不能贴着排**（部署 → 开技能 / 撤退）——约束写在[时序层](../时序层.md) §4；
- **"放上去了"与"能被操作"是两件事**：生效反馈（[执行与失败](../接口层/执行与失败.md) §3）判的是前者，**不许拿它当后者**；
- **"部署与开技能同帧"这类轴直接不成立**，AI 排轴时就得知道。

**朝向还是"完成一次部署"的必要条件**（用户确认）：不选朝向 = 一次**未完成的放置**——干员画面上放上去了但**不攻击**，点别处会被**撤销**。所以它不是"可选参数"。反过来这也给了一条**可观测的完成判据**：成功部署会**退出备战席的技能详情页**。

## 已确认的输入

**详情面板里没有 buff 列表，但有「叠加了 buff 之后的基础数值」**（生命值、攻击力等）。这条有三个后果：

- 它是**有效数值**的权威读数；
- 因此可以**反过来校验我们的推算式**——推算说有效攻击力是 X、面板说是 Y，不一致就**上报冲突**，不挑一个；
- 但它**给不出非数值类效果**（庇护、回复速率加成这类），那些还得靠推算或特效。

**面板里到底有什么，完整清单（用户确认）**：当前生命值上限 · 当前生命值 · 当前攻击力 · 当前防御力 · 当前法术抗性 · 当前阻挡数。**别的基础属性一概读不出来**——再部署时长、部署费用、攻击速度、攻击间隔都没有面板读数。备战席卡片上方另给**当前部署费用**。逐项对照见[基础数值.md](基础数值.md)。

**时效不能靠读，只能靠算**：由**轴数据**（我们什么时候开的、开了什么）+ 数据库（技能持续多久）+ 时间基准算出。它的不确定性来自**时间基准的漂移**而不是识别，所以必须接受**费用读数的外部矫正**（见 [`../../30-专题/时间基.md`](../../30-专题/时间基.md)）。永续技能与弹药技的"结束方式"不同，剩余时长的含义也不同。

**阻挡数只能点详情看**（同时进慢放），因此它**不进默认快照**。

**干员侧还有会改写「敌人属性」的特性**：靠"起飞"挡空中敌人的那一类——所以「敌人是否被阻挡」是**这一对（敌人, 干员）**的性质，不是敌人单方面的。见[敌方单位.md](敌方单位.md)。

## 尚未定

- **有没有能改朝向的机制**——若有，"朝向上常量"这条要改成每片校验；
- **时效的"结束方式"怎么表达**（计时 / 弹药耗尽 / 永续 / 未知）——**归属已定**（[字段编排.md](字段编排.md) §7：时长是槽的一部分），**表达形态仍未定**；
