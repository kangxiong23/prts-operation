# 敌方单位

> 状态：讨论中 ｜ **能力清单**——字段由 AI 注册，我们不再逐个枚举条目；另留一个格式样板

一类：**变长的敌人在场列表**。长度可变，所以"数不清"是常态而不是异常——这正是零假事实最吃紧的地方。

## 本类能提供什么（不写逐条条目）

| 字段 | 证据通道 | 允许的形态 | 降级触发 |
| --- | --- | --- | --- |
| 位置 | **算**（[路线资产](../资产生成器/地形与关卡资产/路线.md) 的格序列 + 移动速度 + **停留点**），识别退成纠偏 | 精确 / **区间**（**二维区域**，见下）/ 未知 | **模型误差**：路线是格级简化、怪被位移后会重走新路径，而纠偏信号稀疏 → 报区域，区域随时间变宽；**落在形状的「推断段」上 → 区间更宽**（那一段是补的，[路线](../资产生成器/地形与关卡资产/路线.md) §1） |
| 类型 / 身份 | 读（卷积 + 特征库） | 精确 / 未知 | 置信度低 → **未采样**，**不许猜**——类型认错，11 项全错 |
| 血量 | 读（血条存在性 + 亮区比例） | 满血（精确）/ 区间 / **下界** / 未采样 | **存在性漏检 = 凭空造出一个"满血"**，唯一危险方向，见样板条目 |
| 状态 | 读（动画状态分类）+ **算**（我们自己的技能账） | 精确 / 未知 | 看动画认不出 → 未采样；我们自己给的走算，免费且确定 |
| **是否被阻挡** | **算（几何判定），不读** | 布尔 / 未知 | 依赖我方位置不失同步；**判定要同时看两侧**（见下） |
| 数量 | 读（逐个体检测）→ **聚合** | **下界** | 数不清是常态——**聚合兜底不许省** |
| 移动类型（地面 / 近地悬浮 / 飞行） | **算**（类型 → 数据库，不单独读） | 精确 / 未知 | 类型未知 → 未知 |

**基础数值（11 项，含生命上限）见 [基础数值.md](基础数值.md)。** 上表里的「血量」是**血条读数**（当前值），和「生命上限」不是一回事（后者是数据库里的分母）。敌人**没有面板**，那 11 项的可读性逐项列在基础数值.md 的敌方表里。

**11 项在快照里按「类型」去重**——同一类型的 11 项对每个个体都一样，逐个体重复就是 N 倍浪费。怎么摆见[快照.md](快照.md) 的 ④a。

### 位置的单位：连续格坐标（用户裁定）

整数部分是格，小数部分是格内偏移——`(5.4, 3.0)` 表示第 5 格内偏右 0.4 格、第 3 行。

- **多出来的那一位不是精度炫耀，是判定需要的**：[控制层](../控制层/识别时机.md) 举的暂停条件例子就是"敌人到第 3 格"。整数坐标给不出这个事件的时刻，而两段式条件存在的全部理由就是卡帧。
- **不用像素，是因为刻度对 AI 没有意义**：格是它全部决策的单位（目标格、路线、阻挡位）；而像素 ↔ 格的换算本来免费（投影参数在[地形](地形.md) 资产里），AI 付的是理解成本，不是换算成本。像素只在调试与 ROI 追溯里出现。
- **一格多物因此天然可区分**（小数不同），"跨在两格之间算哪格"这个问题也不再需要回答。

**"不确定"的形状：一块二维区域**（用户裁定；**修正过一次**）。曾写成"沿路线的一个参数区间"，理由是"漂移沿路线方向、横向几乎不偏"——**那个前提不成立**：路线是**格级的名义路径**，怪不走正中、拐弯不直角，被位移后还会重走一条新的最短路径，**路径本身就不确定**。所以它退回[契约层](../契约层/README.md) §2 那个**普通的二维区域**，不新增类型；而**"沿路还有多远"是拿它投影到名义路径上算出来的**（D8 问的正是它），不是字段的形态。

## 已确认的输入

- **血条不是常驻的**：必须受过一次伤害（血条有变动）才会显示；一次秒杀则**永远看不到**。而且**回满之后又不显示**。
- **敌人状态没有可见标识，只有动画效果。** 所以这条要靠**方法「动画状态分类」（卷积）**——见[视觉层/识别方法.md](../视觉层/识别方法.md)——并且需要[资产生成器](../资产生成器/README.md)多产出一种资产：**人工把常用状态各触发一遍、采样**——这是"故意构造样本"，与难例采集（碰运气）不是一回事。
- **移动类型不单独识别**：认出类型后查数据库。
- **敌人 debuff 里大部分是我们自己给的**（眩晕、冻结、减速、停顿、束缚、沉默都是我们的技能造成的）→ 走**记 / 算**，免费且确定。
- **「是否被阻挡」原来记的是"没有找到稳定的读法"——那是个错误的提法。** 它本来就不该读：**它是算出来的**（几何判定）。**"读不到"不等于"算不出"**——铃兰那条链也是同一个教训。
- **几何判定有两条修正（用户确认）**，都不小：
  1. **少数敌人要占 2 个、甚至 3 个阻挡位**才挡得住（很少见）→ 判定是"**该干员的剩余阻挡余量 ≥ 该敌人的占用阻挡位数**"，不是"余量 > 0"。占位数是**类型常量**。
  2. **「可被阻挡」不是敌人单方面的属性。** 数据库确实标了**飞行 / 浮空**（默认不可阻挡），但今年开始有**靠"起飞"专门挡空中敌人**的干员——所以能不能挡，是**这一对（敌人, 干员）**的性质，**判定必须同时看两侧**。

  于是「可被阻挡」正好就是[地形模型](../../30-专题/地形模型.md) 说的「**运行时可被技能改写字段**」：**类型给初值，干员侧的特性改写它**。判定的输入因此是：我方位置 · 我方阻挡数（一档）· 该干员的"能不能挡空中" · 该类型的占用阻挡位数与初值。

## 被阻挡时的重叠：这一类怎么收场

**事实（用户确认）**：阻挡多个敌人时，**敌人图层必定重叠**，连**血条都可能重叠**——所以"有几个敌人被挡着"很难数。**这是敌人侧最难的一类。**

**阻挡的真实判定是「椭圆碰撞箱」。** 画面上是单位下方那个灰色椭圆（像影子），**逻辑范围比画出来的大**（为美术好看而设计），长轴大约**格子宽度的 70%**，大体型怪更大，**具体值要实测**。两个椭圆碰撞或重叠即**可能**进入阻挡；正常走向干员的敌人，阻挡恰好发生在**两个椭圆相切**的时候——**所以干员与敌人的重叠区很小**。

**椭圆本身不能当识别通道**：它的图层优先级低、且会**同色重叠**（同色重叠最为致命），复杂环境下想把每个椭圆分开**基本没戏**。所以它只是机制，不是原语。

**但几何仍然把问题关小：**

1. **候选位置是可算的**：干员的椭圆位置**我们知道**（干员位置是我们记的），敌人椭圆尺寸实测之后，**被挡住的敌人停在哪是可以推出来的** → 识别从"满地图找"变成"**在少数候选位置上验**"；
2. **每处的上界由该干员的阻挡数给出**：被挡住的敌人数 ≤ 该干员的**阻挡数**（占位数 ≥ 1，类型未知时按 1 取最保守）。所以这里**给得出区间**（看清几个 = 下界，阻挡余量 = 上界），不只是下界；
3. **上界是硬的**：来自**我们自己的记录**（干员位置 + 阻挡数），**不依赖识别**；
4. **敌人图层在干员之上**：被挡住的敌人**不被干员盖住**。但这只在**没有特效覆盖**时成立——**特效画在它们之上**，见下一节。

**一个坑**：**"邻域里有敌人"不等于"被挡住了"**——不可阻挡的单位会径直**穿过去**，也会在那里出现一瞬。所以还是要走"可被阻挡 ∧ 余量足够"那道门，不能拿"那附近有东西"直接当"挡住了"。

**于是这一类按「阻挡位」组织，而不是按「个体」**（提议）：

| 干员 | 格上被挡住的敌人 | 形态 |
| --- | --- | --- |
| A | 能辨认出 1 个（类型 X） | **区间 [1, 1]** |
| B | 看不清是什么，至少 1 个 | **区间 [1, 2]**，类型未知 |

**血条重叠怎么办**——先把它的地位说清：

> **血条是"校验 / 真值"通道，不是排轴的输入。** 排轴用的数值来自一档与**我们自己的伤害账**（算），不来自血条。

所以重叠损失的是**对账**，不是计划本身。重叠时照旧降级（未采样 / 区间），**绝不因为"看不清"就报满血**——那正是本档唯一危险的方向。

**一条候选技巧（未验）**：敌人有**受击闪白**与**攻击动作**，轮廓在这些帧会变 → 也许能**利用动画把重叠的个体在某一帧分开**。要真机验。

## 阻挡权：规则在数据库，这里只说观测

从**观测**这一侧看，只有三件事要说（其中一件是那个非主动的触发源）：

| | |
| --- | --- |
| **好消息** | 唯一的非主动输入**是可读的**——「当前阻挡数」在[详情面板](基础数值.md)里有**权威读数**（它本来就是一档的成员）。"点一次详情"就能确认阀门被拧到哪儿了 |
| **坏消息** | **不点就发现不了**，而且漏检的后果是**静默的**：等**怪开始走动**、或者**蓝门掉血**了才知道。**这正是零假事实最怕的形态**，而怪海里它恰好最难发现 |
| **缓解** | **哪些怪会这么干是类型属性**（数据库里标得出来）→ **选合约、配队时就知道这一局要不要盯它**；盯的方式就是**按需声明「当前阻挡数」这个字段** |

## 怪海与密集区：能活下来的是「条」，不是「个体」

实例：[战斗演示图——敌人识别.jpg](../../../tests/示例图片/战斗演示图——敌人识别.jpg)。

这张图来自主线 **H9-1**，是经典的**怪海图**：敌人多到**堆阻挡数也挡不下来**。而且要记住一件事——**连人看动画都判不准**：

- 有的怪**一秒之内从未被阻挡变成阻挡**；
- 有的怪因为**被施加停顿**，看着跟被阻挡了似的——**「停顿」与「阻挡」在视觉上同形**。

**所以这不是"算法不够强"，是信息本身不在画面里。**

这张图里敌人扎堆在我方干员身上，而**技能特效（绿 / 白 / 粉 / 青好几层）把它们整片淹没**。于是：

- **敌人本体分不出来**——不是"轮廓互相盖"，是**整片看不出个体**；
- **敌人的血条确实在图上**，但它和我方干员的条**位置相近**（都贴在脚下），**只能靠色相与条宽区分**（小怪条更偏红、更窄；干员条更偏黄、更宽；boss 是宽红条）——这张图连人眼都得分半天；
- **而满血的怪根本没有条**，而"一波刚压上来"正是这种情形。

> **视觉层那把保护伞护的是「条」这类 UI，不是单位本体。**
> 所以密集区里**活下来的是「条」，死掉的是「个体」**；**而当怪全是满血时，连条也没了**。

**这条修正很要紧**：原稿把"血条层层叠"当成了主要现象，其实**血条是最不可靠的信号**——它既会与干员的条混在一起，又会在满血时整体消失。**识别的主通道不能押在它上面**：见[视觉层/敌方单位.md](../视觉层/敌方单位.md)，那里已经把主通道换成**干净关卡帧差分**。

**三个后果：**

1. **别在密集区做个体级识别**——那里只能给**聚合**（这一带有几条）+ **区间**；个体级（谁剩多少血、谁是哪个类型）**报未采样**；
2. **"候选位置能算"也救不了**：位置算对了，那里被特效盖着，照样读不出。所以"验"这条路**只在画面干净时**成立；
3. **"上界是硬的"这条不受影响**——它来自我们自己的记录（干员位置 + 阻挡数），本来就不依赖画面。

**主通道已经翻过来了（用户裁定）**：既然密集区里连"条"都不会有，敌人侧的**主通道就从「识别」翻成「推算」**——[路线资产](../资产生成器/地形与关卡资产/路线.md) 给"第几个、什么时候、从哪个门、出什么、走哪几格、在哪儿停多久"，移动速度是一档，减速 / 停顿 / 阻挡基本都是我们造成的（算）；识别退成**纠偏**（对不对得上），而不是**提供**位置。

**但推算产出的是格级的参考，不是精确位置**（用户确认）：

| 限定 | 什么意思 |
| --- | --- |
| **资产的精度是格级** | 路线是**测出来的**，不刻意为之**起码精确到格** |
| **它是名义路径** | 敌人**不一定走路的正中间**、**拐弯也不一定走直角**——路线简化成格为单位 |
| **用途分级** | **作为"算敌人位置"不行，作为 AI 下干员的参考可以** |

**为什么资产是路线、不是「判定点」**：游戏标识路线靠给怪一串**判定点**（怪持续以最短路径走向当前那个，到了切下一个，终点必是蓝门），而判定点**坐标未知、不是整数**，且**测它只能靠"不断造成很明显的位移"**——方法论上就贵（危机合约攻略组曾为标定一个判定点，画下一百多条辅助线的尺规作图草稿）。**怪怎么走好测得多。** 见[特征库](../资产生成器/特征库.md) §5。

代价因此不只是"漂移"，是**模型误差**：路线本身是格级简化，而且**被位移之后怪会重走一条新的最短路径**。所以位置**默认带不确定度**，而**半径的量级是「格」**，不是零点几格——**这是这一档的常态，不是异常**。

**一条要显式承认的缺口**：格级精度**不够**支撑卡帧类判据（"敌人到第 3 格就停"）——那个事件的时刻误差是 `1 格 ÷ 移动速度`，慢怪就是几十帧。**连续格坐标是表达形式，不是精度来源**（[契约层](../契约层/README.md) §2）。

**配套的一条（实测确认）**：**图不能替代数值**。位置以连续格坐标为准；布局图是可选的派生视图，默认不给，见[快照.md](快照.md) 的「位置的呈现」。

**这张图顺带确认了几件已经写下的东西**：顶部 `104/123`（已击杀 / 敌人总数）、蓝门血量 `3`、费用 `99` + 进度条、右下「剩余可放置角色：4」、备战席卡片**上方**的费用数字（9 / 11 / 16 / 13 / 25）。**"卡片上方"这个位置判断是对的。**

## 投入取舍：阻挡识别该投多少

用户直接问的就是这一条。我的评估：

| 投什么 | 值不值 | 理由 |
| --- | --- | --- |
| **通用、逐个体的阻挡识别** | **不值** | 信息不在画面里（椭圆不可读、同色重叠、**停顿与阻挡视觉同形**、连人眼都判不准）。投进去只会得到一个"经常错"的模块，而**错比不知道危险** |
| **阻挡权状态机（作为排轴模型）** | **值得** | 它是**规则**不是识别：谁先挡、怎么转交、恢复不抢回。一次性写进数据库，价值直接体现在排轴上——用户那个 42 姐战术就是靠它 |
| **该读就读：当前最大阻挡数** | **值得** | 它是阻挡权**唯一**的非主动输入，而且**有权威读数**——[详情面板](基础数值.md)里就有。有"减阻挡数"敌人的局，值得按需声明它 |
| **按词条触发的重装备** | **值得** | 合约词条**由人选、所以已知** → 遇到"阻挡敏感"的条目（如"非阻挡干员伤害 −100%"）才开更贵的观测 / 仿真路径，普通局走便宜路径 |
| **怪海里主动报未采样 / 聚合区间** | **必须** | 否则 AI 会把"不知道"当"知道"；轴上还要显式标注"**这一段对阻挡的判定是未知的**" |

**另一条替代思路**：排轴的抓手不一定是"阻挡"，而是**我们自己施加的控制**——减速 / 停顿 / 束缚 / 眩晕。这些走**算**，免费且确定；对"别漏怪"这个目标，它们和阻挡是同一类手段，但**可算**。

**一条诚实的边界**：如果某个合约**必须**逐个体知道"谁被谁挡着"才能过，而当场在怪海里读不出来——**那这个场景当前方案覆盖不了**。要显式承认，而不是假装能。

## 一条本来就在项目里的通用机制

[地形模型](../../30-专题/地形模型.md) 说的「**运行时可被技能改写字段**」——可阻挡、可被近战、可被对空、缚地、浮空——数据库只给初值，运行时被技能改写。**这就是"可推算 buff"的机制**，只是当时没有被概括成 buff。

上面「是否被阻挡」正是靠它：**"可被阻挡"是类型属性，会被技能改写**。

## 样板条目

格式样板（项序见 [README](README.md) 的 G5）。它留在这里不只是当样板——**血量的语义边界是这一档最容易出事的地方**。

### 敌人血量（未满时）

- **语义**：这个敌人当前血量占上限的比例。
- **语义边界**：
  - **血条显示 ⟺ 未满血**。所以「看不到血条」= **满血**——这是**读**出来的，不是推断，不需要"敌人不回血"这个前提。
  - 反向**读不出**「它是否曾经受伤」：回满之后与从未受伤在画面上完全一样。
  - **血条存在性漏检 = 凭空造出一个"满血"**，这是本字段唯一危险的方向。
  - 「不显示 ⇒ 满血」只在**识别正常**的前提下成立；识别不可靠时必须降级成未采样。
- **证据通道**（两条，都是"读"）：
  1. **血条存在性**（存在性搜索）→ 布尔。无血条 ⇒ 精确的满血。
  2. **亮区比例** → 血条在时给未满血的量；绝对上限查数据库。
- **多通道冲突**：不适用——两条通道是先后关系，不是同一个量的两路读数。
- **允许的形态**：**精确**（满血，或亮区读全）/ **区间**（粗到只分几档也是区间，见 [README](README.md) G1）/ **下界**（亮区被遮挡）。**三态里没有"空"**——未采样是另一个轴，不写在形态里。
- **降级触发**：通道 1 置信度低 → 报**未采样**；通道 2 亮区被遮挡 → 误差**单边偏低** → 报**下界**，不是区间。
- **单位与参照系**：比例（0–1）；上限来自数据库。
- **时刻**：此刻值。
- **不变量**：暂无。
- **有损？**：否，进**默认快照**。
