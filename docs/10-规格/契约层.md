# 契约层

> 状态：讨论中 ｜ 五节骨架已立（槽 / 几何 / 刻度 / 容器 / 端口与错误）；端口的**方法集**与条件三值的归属待定

对应代码：`src/ark/contracts/`。

## 这份文件负责什么

所有人共用的数据定义与端口（Protocol），**没有任何实现**。

它是唯一被所有人 import、且自己不 import 任何内部模块的东西。这条一旦破，解耦就是摆设 —— 由 `tests/contract/import_rules.py` 机器强制。

## 这一层唯一的验收判据

> **让"不知道"在类型上没法被伪装成"知道"。**

可验的问法：**拿一份快照问"这里面哪几个数其实是猜的"——答案必须能在类型里直接看出来，不用读实现。**

三态（未采样 / 已采样但为空 / 有值）写在**类型**里，而不是写在某个模块的实现里，才能保证所有层都不把它混成一个"空"。混了就是假事实的来源。

> **权威在哪**：三态的**概念**出自[《概念设计共识》](../概念设计共识.md) §5.4 第 2 条；那份基线排空后，以本文件的类型定义为准。

## 1 槽：三态 × 载荷 × 置信度

> 它曾叫**「格位」**——那个名字与「格」撞车，读起来像"格的位置"。改掉。

| 轴 | 取值 | 谁有 |
| --- | --- | --- |
| **三态** | 未采样 / 已采样但为空 / 有值 | 一律有 |
| **载荷** | 精确(v) / 区间(lo, hi) / 下界(lo) / 上界(hi) / 未知 | 三态 = 有值 时 |
| **置信度** | 原语算出的连续量，无量纲 | **只有"读"有** |

- **形态不是并列的一个字段，是载荷自己的类型。** 写成并列字段就能构造出 `形态=精确` 而值是 `[15, 16]` 这种自相矛盾的东西。
- **「未知」是"有值"的一种载荷，不是三态的一支。** `有值 + 未知` = "**那里确实有东西，我不知道它是什么**"；`已采样但为空` = "**那里没有东西**"。这两件事混掉就是假事实。
- **区间的两端各自可开放**：一端开放就是「下界」或「上界」。它们与「区间」共用同一套操作。

### 三态是**字段级**的，不是原语级的

一个原语的结果只有两种：**有读数**（载荷 + 分数 + 矩形）或**没有读数**。

- **原语说不出"未采样"**——你调它，它就是采样过了。所以 `未采样` 这一支**在原语内部永远构造不出来**，只有调用方填得出来。
- **原语的"未命中"也不是三态的一支**："我看了，那里没有"是**读数的内容**，不是读数的缺席。

两条推论：

1. **"没调用"与"调了但没能执行"**（被暂停灰罩或特效盖住、前置不满足）**在信息上等价**，都落成字段的**未采样**；原语侧不必为它们分两个态。反过来：**"没能执行"绝不许冒充"未命中"。**
2. **原语的未命中，只有分数够高时才配升格成"已采样但为空"**；分数低时字段只能报**未采样**。这正是三态必须由字段组装的原因——**未命中算不算事实，取决于字段自己的降级策略，原语不知道**。

**一般形式**（覆盖算类与记类）：`未采样` = **还没有任何一条通道为它给出读数**。

- **读类**：原语没跑 / 没能跑（见上）；
- **算类**：**输入不全**——三态往上传染，**不许在输入未采样时凭空算出一个值**；
- **记类**：还没有记录。

**有哪几种原语、每种允许用哪几个载荷** → [视觉层/原语.md](视觉层/原语.md)。本节只定**结果的形状**与**载荷词表**，**不列原语**。

> 这一段与基线 §5.4 第 2 条**一致**：那里把原语结果写成 `{矩形, 分数, 载荷}`，三态单独写在字段上。本文件早先把三态摘进了"原语结果"那一行，**已改正**。

## 2 几何

**格坐标是连续的。** 整数部分是格，小数部分是格内偏移：`(5.4, 3.0)` = 第 5 格内偏右 0.4 格、第 3 行。

- 多出来的那一位**表达的是"格内偏移"，不是精度炫耀**——"敌人到第 3 格"这个事件的时刻，整数坐标给不出，而两段式条件存在的全部理由就是卡帧；
- **但小数位不产生精度。** 精度来自**渠道**（识别 / 推算），不来自刻度：推算出来的敌人位置是**格级**的（[状态层/敌方单位](状态层/敌方单位.md)），所以那个事件的时刻误差是 `1 格 ÷ 速度`。**连续格坐标是表达形式，不是精度来源**——写成小数不会让它变准；
- **不用像素**：格是 AI 全部决策的单位；换算本来免费（投影参数在资产里），AI 付的是理解成本不是换算成本。像素只在调试与 ROI 追溯里出现；
- **一格多物因此天然可区分**（小数不同），"跨在两格之间算哪格"不再需要回答；
- 像素与格坐标**在类型上要分得开**——别让一个 `(float, float)` 既能当格又能当像素。

**区间是一个标量类型** `(lo, hi)`，两端各自可开放。它要提供两件操作：

| 操作 | 用途 |
| --- | --- |
| **包含** | 区间 ⊇ 点 / 区间 ⊇ 区间——判断"哪一次读数更强"、"降级有没有发生" |
| **相交** | 两个区间是否可能指同一个值 |

### 位置的"不确定"：一个二维区域（用户裁定；**修正过一次**）

**先说改错的那一次**：曾写成"路线参数上的区间"，理由是"漂移沿路线方向、横向几乎不偏"。**那个前提不成立**——路线资产是**格级的名义路径**，怪**不走正中、拐弯不直角**，被位移之后还会**重走一条新的最短路径**。**路径本身就不确定**，所以横向也有一份不确定。

于是位置的形态是**二维区域**：点 + 不确定半径（或盒）。它是 `locate` 原语的答案（[视觉层/原语.md](视觉层/原语.md)）；**它算不算第六种载荷，见那份文件的「尚未定」**。

- **"沿路还有多远"是一次算，不是字段的形态**——把那个区域**投影到名义路径**上就有了（D8 问的正是它）。**这样形态才能撑住"连路径都不知道"的情形**，而路线参数区间撑不住；
- 位置本来也不只用于"还有多远"：D9 / D10 问的是"**哪儿有怪**"，而**阻挡的几何判定**更要二维。

### 区间进入条件判定 → 结果是三值

位置是区间时，「敌人到第 3 格」的答案**不是真假二值**，而是**一定真 / 一定假 / 判不了**。

- **这一层定"结果是三值"**（技术上是区间与点求交的三种结果）；
- **"判不了怎么办"已经定了**（[控制层/暂停条件](控制层/暂停条件.md) §4）：**判不了 ≠ 成立**；每一段都**必填时限**，到点立即暂停，超时后如实报是"**确定不成立**"还是"**从未确定成立**"；
- **为什么现在就要说**：控制层写条件表达式时若默认二值，**"不确定"会被静默当成"否"**——那是零假事实在条件侧的破口。

### 投影

`格坐标 ↔ 像素` 映射的参数**宿主是地形资产**（[状态层/地形](状态层/地形.md)），但**有两套**：常速一套、慢放一套（慢放时地图右移倾斜，[控制层](控制层/时间态.md)）。这一层定义映射的**类型**，值在资产里。

## 3 刻度：两种，类型上必须分得开

| 刻度 | 是什么 | 谁在用 |
| --- | --- | --- |
| **逻辑帧** | 游戏时间，1 游戏秒 = 30 帧 | 轴 · 条件 · 快照页眉 · 观测迹 |
| **墙钟毫秒** | 真实时间 | ADB 延迟 · 超时 · 判定节拍 |

**为什么这值得进契约层**：两者混起来会产生一个**静默的错**——同一次 200 ms 的 ADB 延迟，常速下是 **6 个游戏帧**，慢放下只有 **0.6 帧**（[时间基](../30-专题/时间基.md) §5.1）。这是**只有类型能拦住**的一类错。

- **轴上只许出现逻辑帧**（[时序层](时序层.md) §2）；墙钟只在记录里留痕，用来解释"为什么这一段墙钟很长"；
- **逻辑帧不是从时钟读来的**，它由费用推算（[时间基](../30-专题/时间基.md)）——所以"时钟端口"里没有它；
- **时间态**（常速 / 慢放 / 暂停）跟着快照页眉走（D17）。

## 4 容器：定义"什么叫容器"，不定义"里面有哪些名字"

| 容器 | 形状 |
| --- | --- |
| **槽集合** | 具名槽的有序集合，可带**块名**（块名由[状态层](状态层/README.md) 给） |
| **前提头** | 一局内不变的那几个槽（[时序层](时序层.md) §3） |
| **动作** | `帧号 + 动词 + 参数…`（动词表在[时序层](时序层.md) §4） |
| **轴** | 前提头 + 动作表 |
| **记录** | 前提头 + 实际动作表 + 观测迹 |
| **观测迹条目** | `帧号 + 字段名 + 槽` |
| **成分表** | 一个值的**各来源贡献**：来源标签 + 贡献量；取最高时标出胜者 |
| **快照** | 按块组织的槽集合 + 前提头指针 |

**观测迹条目记的是整个槽，不是"数值"。** 三态与置信度也是读数的一部分，只记数值会让重建出来的快照**没有置信度**。

> 于是[时序层](时序层.md) §5 那个 `(帧号, 字段, 新值, 取值形态)` **自然变三元组**——"取值形态"长在值上，不用单列一栏。那条"待回改"自己就了结了。

**槽不逐条带帧戳。** 一片里几十个槽共用一个时刻，逐条带既是重复存储，又给了"同片内两处帧戳不一致"的机会。**帧戳属于容器**（快照页眉 / 观测迹条目）。

## 5 端口与错误

**端口有三个，外加一个待定的位置。**

| | 管什么 |
| --- | --- |
| **设备** | 取像（截图）+ 注入触摸 |
| **时钟** | 墙钟毫秒 |
| **样本** | **难例样本往哪落**——engine 侧发起，实现住 `offline/hardcase/` |
| **资产**（**是端口还是注入的纯数据，待定**） | 投影参数 · 格属性 · **路线（形状 + 出怪记录两层）** · **特征库** · **干净关卡背景帧** · UI 布局常量（它的值在设计代码时定，**不进资产库**） |

- **取像不是独立端口**，它就是设备的截图。[控制层](控制层/识别时机.md) 明说"取像与识别是同一件事的两半、没有常驻取像"——留着这个位置，会诱出一条"只取像不识别"的通路，正好违反那条约束；
- **资产这个位置是硬性欠的**，不是我加的设计：[代码结构](代码结构.md) 规则一说 **`engine` 永远不 import `offline`**，而上面那些值全是 `offline/assets_gen/` 的产物、**视觉层与设备层都要读**（视觉层要 ROI 的投影，设备层要点击的投影）。所以它们**必须经由契约层暴露的某个东西**到达，由 `runtime/wiring.py` 接上。**它究竟是一个端口（按关卡懒取），还是 runtime 一次注入的纯数据，还没定**——但位置本身不能空着；
- **样本这个位置同样是硬性欠的**，出处也是规则一：难例采集的**触发点在线**（槽自己发现不确定、组装发现账不平），而**实现住 `offline/hardcase/`**。触发集与落盘内容见[采集与验收](采集与验收/README.md) §1、[难例采集](采集与验收/难例采集.md) §1。**离线跑的时候它是空实现**——离线验收不需要采集。它因此和设备、资产一样，按构造就被端口完备性测试覆盖；
- **端口必须"纯"到 replay 适配器能满足**（[设备层](设备层.md)）："离线重放不是特例代码"的落地条件就是**换一个适配器**，所以端口里**不许出现"现在真的是游戏在跑"这类信息**。这也正是[代码结构](代码结构.md) 里那条**端口完备性测试**的输入——它按构造就能抓出上面这个欠账。

**错误模型 = 三种**（[接口层/执行与失败](接口层/执行与失败.md) §4）：

| | 含义 |
| --- | --- |
| **拒绝** | 不合法 / 前提不吻合 / 版本认不出 → **整段不执行**，附哪一项不吻合 |
| **降级** | 照常返回，但进快照页眉的[存疑清单](状态层/快照.md)，槽自身带三态与形态 |
| **中止** | 跑到一半坏了 → 返回**跑到哪一帧** + 哪些已确认生效 |

**铁律上类型**：错误集里**不许有"部分成功"这一支**。工具不报"我尽力了"，只报三态。
