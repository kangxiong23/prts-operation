# 地形模型

> 状态：讨论中

## 为什么单独立一份

地形的语义被**四处**使用：状态层（呈现给 AI）、控制层（部署与位移校验）、资产生成器（生成）、契约层（类型定义）。按 [docs/README.md](../README.md) §3，"约束多个子系统的模型"进专题，不进任何一个模块的规格。

## 1. 格子是属性，不是枚举

| 属性 | 取值 | 谁在用 |
| --- | --- | --- |
| 地块 | 有 / 无 | 无 = 洞或地图边界；敌人不能进入（除非被位移推入） |
| 高度 | 地面 / 高台 | 哪类干员能放；哪类敌人能站 |
| 可部署 | 是 / 否 | 部署校验第一道 |
| 地标 | 无 / 红门 / 蓝门 | 路线端点、漏怪判定 |
| 标签 | 集合，可为空 | 机制变体，按需处理 |

## 2. 五个基础类别是组合

| 类别 | 地块 | 高度 | 可部署 |
| --- | --- | --- | --- |
| 可部署地面 | 有 | 地面 | 是 |
| 不可部署地面 | 有 | 地面 | 否 |
| 可部署高台 | 有 | 高台 | 是 |
| 不可部署高台 | 有 | 高台 | 否 |
| 无地块 | 无 | — | — |

前三个属性是**闭合的**（合法组合只有这五种）。

## 3. 机制变体走标签，不走类型

> **热泉通道 = 可部署地面 + 标签`{热泉通道}`。**

新地形的引入**较为常见**，而且通常是已有地形的变体。所以：

- **走枚举**：每来一个"热泉通道"就要加一个类型值，然后回头复查所有 `地形 == 可部署地面` 的分支；
- **走标签**：基础属性不动，部署判定一行不改，新机制只是多一个字符串。

标签的规则**按需实现**：没人问"热泉通道会怎样"的时候，它就是一个字符串，不产生任何行为。

**"不产生行为"是设计，不是缺口。** 机制太杂、枚举不完，所以**我们不给它们写规则表**——地形只提供**挂载点**（哪几格挂了哪个机制名，就是 `.json` 里的 `labels`），**AI 过目一遍地形之后自己[注册字段](../10-规格/状态层/注册字段.md)去观测它**。于是机制走的是和"效果"同一条路：**开放集 + 按需注册 + 兜底未采样**。挂载点要进快照 ①，否则 AI 看不到它。

## 4. 地标：红门与蓝门

| 地标 | 是什么 |
| --- | --- |
| **红门** | 敌人出生的入口 |
| **蓝门** | 敌人要抵达的目标；抵达即漏怪 |

它是**独立的闭合属性，不是标签**。理由：它是核心词汇，被"路线端点"和"漏怪判定"直接使用，不是某个机制的附加行为。一关可以有多个。

**门格必定是不可部署地面**（游戏规则）。但这条**不在读取时生效**：

- **存储保持正交**——"可部署"位该填什么就填什么，不从"它是门"推出来；
- **生成与校验时保证**——资产生成器自动把它填成不可部署地面，校验器把它当不变量检查。

区别在出错时的表现：读取时耦合的话，资产少填一位就会**静默继承**一条没人写下来的假设；生成时保证的话，填错了校验器当场拦下来。

## 5. 词条是覆盖层

沿用已有决定：**一份基础地形 ＋ 每个词条组合一小串被禁用的格子**。覆盖只改"可部署"这一位。

于是 `实际地形 = 基础地形 + 词条覆盖`，而词条写在轴的前提头里，所以实际地形是确定的。

## 6. 地图铺满矩形

地图并非严格长方形，有些地块是纯美术填充、没有方块边界。**建议以不可部署高台填充它们。**

好处很大：网格**始终是完整矩形**，坐标、投影、遍历全都简单，AI 看到的也是一张规整的表。

代价：**把"纯美术"这个信息抹掉了**。将来若出现跟高台本身有关的机制（摧毁高台、按高台计数、高台位移），这些填充格会被误伤。

可以接受，因为**修回来很便宜**——从原图重新生成一次美术掩码即可，是一次性资产重建，不是运行时改动。

## 7. 路线是资产，地形不做寻路

**地形只管"这个格能不能待 / 能不能被推过去"，绝不负责算"敌人该往哪走"。**

路线由关卡策划画好，是资产。一旦我们自己上寻路，就是在猜游戏的内部实现，**猜错产出的就是假事实**。

所以「地形规则」与「路线」是两个独立的东西，各自表述。

**而这份路线资产分两层：「形状」（格序列 + 停留点）与「出怪记录」（出现帧 + 形状引用）**（用户裁定：一个敌人一条）。它住在[路线资产](../10-规格/资产生成器/地形与关卡资产/路线.md)，与地形同关卡、同验收。于是**地形管"能不能待"、路线管"往哪走"、出怪管"什么时候来"**——三件事合起来才是一关的静态先验。

**两层拆开的理由是失效条件不同**：形状随关卡变，出怪记录随**词条组合**变——而**不是版本**（[路线资产](../10-规格/资产生成器/地形与关卡资产/路线.md) §1）。

## 8. 这个分法正好接住"近地悬浮"

近地悬浮的游戏描述是**"近地悬浮，无法被阻挡或近战攻击"**；实测行为是**可跨越无地块**（与飞行一致），但**走的路线都是地面**。

如果地形既管规则又管路线，这就是个必须特判的矛盾。两者分开之后，它只是两条普通数据：

- **移动类型 = 飞行**（所以可跨无地块）——它是单位的交战属性，在数据库里；
- **路线类型 = 地面**（所以看不出它在飞）——它在[路线资产](../10-规格/资产生成器/地形与关卡资产/路线.md) 那一行里。

不需要为它开任何特例。

## 9. 哪些不属于地形

| 项 | 归哪 |
| --- | --- |
| 可阻挡 / 可被近战 / 可被对空 | **单位的交战属性**，在游戏数据库里 |
| 移动类型（地面 / 悬浮 / 飞行） | **单位属性**，同上 |

而且这些**会在运行时被技能改写**：游戏里有干员能把飞行单位缚地、把地面单位浮空，实测发动后近地悬浮敌人就能被近战干员打了。所以状态层里它们是**运行时可变的字段**，数据库只给初值；地形层完全不参与。

## 10. 投影：不是静态的，也不止一套

**视图有两套。**

**进入慢放**（点干员或点备战席卡片）**时**，游戏会把地图**往右倾斜并位移**（为了尽量少挡视野）。所以「格坐标 → 像素」在慢放下是**另一组参数**，不是同一个变换。

依据：[MAA借鉴清单](../50-外部借鉴/MAA借鉴清单.md) §9.7——它的每关数据带两个 3D 机位，而第二套正是在"把干员卡拖到指定格"那条路径里用的。

**平移只发生在切视图的那一刻**（用户确认）——**常速下相机不动**，数值待测。所以"一局之内不变"这句话**只对同一个视图内成立**：**切视图 = 换一套参数**，而不是"参数随时间漂移"。

三条推论：

1. **地形资产要能提供两套投影参数**（常态 / 慢放），**切换时间态时同步切换**；
2. 「投影对不上就拒绝执行」这条规矩仍然成立，但**基准是当前视图的基准**——对不上时先问"是不是视图没切"，再问"是不是数据错"；
3. **慢放下的部署点击**与**关键时段的识别 ROI**，都必须用慢放那一套；
4. **干净关卡背景帧也得按视图各备一份**——识别多数发生在**慢放 + 详情面板**下（[控制层/识别时机](../10-规格/控制层/识别时机.md) §4），拿常速的那一帧去减会整片对不上。

**屏幕位置由投影算出，不每帧从画面里找格子。**

**遮挡是几何问题，不用识别**：详情面板是一个已知矩形，目标的投影位置也是已知的——两者一相交就知道"这个目标被挡住了"。被挡住时切回常速即可（见 [控制层](../10-规格/控制层/时间态.md)）。

## 已定

- **生命是全局单值**——多个蓝门共享同一个生命池，不是每个门一个。
- **门格必定是不可部署地面**——由生成器保证、校验器检查，见 §4。
- **保持「可部署 × 高度」两轴**，不为"近战远程都能放"加第三档——**合约里至今没出现过**这类格子，遇到再补。见 [MAA借鉴清单](../50-外部借鉴/MAA借鉴清单.md) §9.3。

## 尚未定

- **投影要不要吃"高度"这第三个输入**。实测（304 关采样、1280×720，按 [MAA借鉴清单](../50-外部借鉴/MAA借鉴清单.md) §9.2 的投影公式）：
  - **格子尺寸不固定**：跨关列间距 61–112 px（中位 88）、行间距 53–103 px；**同一关内因透视也在变**（列间距最大/最小中位 1.24，极端 6.7）。所以高度偏移**不是常数，是位置相关的**，"存一个常数"这个说法不成立。
  - 偏移 ÷（半个行间距）：中位 0.58，**最大 2.33，304 关里有 5 关 > 1**——那几关按名义中心点击会落到下面那一格。
  - **识别侧用不到它**：干员身份来自我们自己的部署记录；血条与技力条靠**搜索**而不是靠钉死的格子 ROI；地面敌人不上高台、飞行敌人不吃高台偏移。
  - 待定：只在「格 → 像素」这一侧把高度作为**第三个输入**（多存一个高度方向向量），还是一律忽略。
- **标签的具体规则表** → 按需实现，遇到再写。
