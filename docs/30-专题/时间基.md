# 时间基

> 状态：讨论中 ｜ 只剩一处待定：词条对自然回费速率的修正是否计入反推（见 §6）

## 为什么单独立一份

「一帧是多少、时间怎么计量」是**跨模块标准**，不是任何一个模块的实现细节：

- 视觉层要从画面上把它读出来；
- 状态层要把它当一个字段；
- 时序层要用它给每个时间片盖章；
- 控制层要用它判暂停条件里跟时间有关的部分。

所以按 [docs/README.md](../README.md) §3 的规则，它进 `30-专题/`，不进 `10-规格/`。

## 1. 两个时间

| | 定义 | 谁在走 |
| --- | --- | --- |
| **游戏时间** | 游戏内时间。暂停时冻结，慢放时变慢 | 游戏 |
| **墙钟时间** | 真实时间。一直在走 | 世界 |

**轴上的一切只用游戏时间。** 墙钟时间只有两处有意义：AI 的思考耗时（不进轴），以及解释"为什么这一段墙钟很长"。

## 2. 逻辑帧

**逻辑帧是游戏时间的量化单位：1 游戏秒 = 30 逻辑帧。**

不是"33 毫秒"——33 毫秒是常速下的**换算结果**，不是定义。慢放时一个逻辑帧对应的墙钟时间按倍率变长，游戏时间不变。所以同一条轴在常速与慢放下是同一个轴。

## 3. 游戏时间怎么读：费用

### 3.1 余额不是钟

```
费用余额 = 初始费 + ∫自然回费 dt − Σ消费 + Σ先锋回费
```

先锋回费与消费跟时间无关地改变余额；初始费因关卡而异，速率还会被合约词条改。**所以余额本身拿不出时间。**

### 3.2 能拿出时间的是这个量

```
累计自然回费量 = 余额 − 初始费 + Σ消费 − Σ先锋回费
游戏时间       = 累计自然回费量 / 速率
```

三项修正全是**已知量**：初始费来自关卡 + 词条（写在轴的前提头里），消费是我们自己下的指令，先锋回费是可观测的跳变。

### 3.3 进度条给小数位

费用数值下面有一条到"下一费"的进度条，它比整数费精确得多：

- 整数费只能把时间定位到 1 游戏秒；
- 进度条给这一秒之内的小数部分；
- 进度条宽 `W` 像素时，1 像素 ≈ `30 / W` 逻辑帧。`W = 100` 且识别只判到 1%，也有 **0.3 帧**。

### 3.4 为什么这样就不怕 ADB 截图延迟

因为读的是**值**，不是**跳变**。

"费用恰好为 3 的那一帧"要赌跳变检测，而 ADB 截图延迟正好打在这个赌上；"这一帧的读数是 2.37"无论什么时候读到都成立——**延迟只影响你什么时候知道，不影响你知道的是什么。**

### 3.5 零点

**开局时进度条相位必定为 0**（初始费不一定为 0，但那不影响相位）。

于是在第一次能看清界面时读一次 `(整数费, 相位)`，反推游戏时间，再倒推到相位为 0 的那一帧——那就是逻辑帧 0。不需要抓跳变，也不需要全速取像。

### 3.6 边界

进度条的相位是 **mod 1 费** 的，它自己给不出绝对时间，必须配上整数费和 §3.2 的三项修正。所以"读一次就永久准确"不成立——它的价值在于**可以每一帧重新对齐**。

## 4. 秒表与校准

| | 干什么 | 性质 |
| --- | --- | --- |
| 工具秒表 | 只在非暂停时走；慢放期间按倍率缩放 | 每帧都有值、无延迟，**但会累积漂移** |
| 费用读数 | 独立算出当前游戏时间 | 有延迟，**但绝对值准** |

两者对齐 → 秒表被定期拉回，**不累积漂移**。秒表是主轴（每帧都要），读数是校准（定期拉回）。

**当时间态不由工具控制时，主从要对调**：首轮探索里是**人**在切时间态，秒表不知道该按什么速率走——所以那里**费用进度条相位当主轴**（它只被自然回费驱动，暂停不走、慢放变慢），秒表降为"相位断掉时"的兜底。理由与取法见[首轮探索/时间对齐](../10-规格/首轮探索/时间对齐.md)。

顺带白拿一样东西：**慢放倍率**。两个读数之间的游戏时间差 ÷ 对应墙钟时间差就是倍率，不用另做实验。

**而且这套校准会自己揭穿假设。** §8.2 里"慢放的性质是拉长真实时长还是改变游戏逻辑"未验证——如果慢放其实不改变游戏逻辑，费用读数会立刻和秒表对不上，我们当场就知道了。

## 5. 暂停与慢放为什么自动一致

暂停冻结游戏时间、慢放拉长游戏时间——**这两件事作用在游戏时间上，而秒表和费用读数读的也是游戏时间**。三者口径天然一致，不需要为暂停/慢放写特例换算。

### 5.1 顺带一个很有用的性质：慢放把墙钟延迟折算小 10 倍

同样一段墙钟耗时，在慢放下折成的**游戏帧**只有常速下的十分之一：

| | 200 ms 墙钟 ≈ |
| --- | --- |
| 常速 | 约 **6** 个逻辑帧 |
| 慢放 1/10 | 约 **0.6** 个逻辑帧 |

所以"抓一帧 → 按下暂停"之间那段 ADB 延迟，在慢放下几乎不占游戏时间。

**这是两段式条件要在慢放下卡帧的又一个理由**——它压的是**延迟折算**：同样的墙钟延迟，慢放下折算成的游戏帧只有十分之一。

（**不是**"给 AI 更多的思考时间"——**AI 的思考只发生在暂停**，慢放不给思考时间。见 [概念设计共识](../概念设计共识.md) §2.2 第 1 条、§3 推论 2、§4.1 表格。）

## 6. 待定

合约词条可能降低自然回费速率（例如 −50% → `0.5 费 / 游戏秒`）。

倾向：**按词条算进去**（词条是人选的、已知的，它只是个系数）。

风险量级：若该词条生效而我们仍按 `1 费/秒` 反推，零点会偏，**偏的量正好等于第一次清晰读数的游戏秒数**。首读越早偏得越少，但不是零。
