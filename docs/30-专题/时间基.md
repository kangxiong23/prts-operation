# 时间基

> 状态：讨论中 ｜ 只剩一处待定：词条对自然回费速率的修正是否计入折算（见 §6）

## 为什么单独立一份

「一帧是多少、时间怎么计量」是**跨模块标准**，不是任何一个模块的实现细节：

- 视觉层要从画面上把它读出来；
- 状态层要把它当一个字段；
- 时序层要用它给每个时间片盖章；
- 控制层要用它判暂停条件里跟时间有关的部分。

所以按 [docs/README.md](../README.md) §3 的规则，它进 `30-专题/`，不进 `10-规格/`。

## 1. 两个时间

| | 定义 | 谁在走 |
| --- | --- | --- |
| **游戏时间** | 游戏内时间。暂停时冻结，慢放时变慢 | 游戏 |
| **墙钟时间** | 真实时间。一直在走 | 世界 |

**轴上的一切只用游戏时间。** 墙钟时间只有两处有意义：AI 的思考耗时（不进轴），以及解释"为什么这一段墙钟很长"。

## 2. 逻辑帧

**逻辑帧是游戏时间的量化单位：1 游戏秒 = 30 逻辑帧。**

不是"33 毫秒"——33 毫秒是常速下的**换算结果**，不是定义。慢放时一个逻辑帧对应的墙钟时间按倍率变长，游戏时间不变。所以同一条轴在常速与慢放下是同一个轴。

## 3. 游戏时间怎么读：费用

### 3.1 余额不是钟

```
费用余额 = 初始费 + ∫自然回费 dt − Σ消费 + Σ回费类机制 − Σ扣费类机制
```

右边那几类机制各有若干种：自然回费（连续、恒定）· 先锋技能的**逐渐**回费（连续、限时）· 一次性 / 攻击 / 击杀回费（跳变）· 撤退退款与装置返还（跳变）· **行商在场时每 3 秒扣 3 费**（周期跳变）· 少数敌人机制的扣费与锁费 · 关卡与词条对初始费、速率、上限的改动。

**这份清单不需要完整，因为我们不处理其中任何一个**——它只说明一件事：**余额不是钟。**

最硬的反例是**行商**：每 3 秒 −3 费 = 平均 **−1 费/秒**；在 `r = 1` 的关卡上它恰好抵消自然回费的 **+1 费/秒**。于是余额**一动不动**，而时间在走。任何"拿余额增长推时间"的做法在这里都会得出"时间停了"。

### 3.2 相位是钟

费用数值下面有一条到"下一费"的进度条。**它只被自然回费驱动**（用户确认）：

- 消耗**不动**它，加费（撤退退款 / 装置返还 / 回费技能）**也不动**它，先锋的逐渐回费**也不动**它——**任何余额变化都动不了它**；
- 所以它是画面上**唯一一个只被时间驱动的量**。于是余额进「资源」、相位进「时间」，**两者共用一次读数，走两条路**。

它比整数费细一档：

- 轨道 **153 px** 宽（原生），一个费用点 **30 逻辑帧** → **`1 px ≈ 0.196 / r` 逻辑帧**（`r` 是自然回费速率，**不是常数**，见 §6；`r = 1` 时 ≈ 6.5 ms）；
- 也就是说**读相位就能把一帧定到零点几帧**——比帧本身细五倍。它在[状态层/全局与HUD](../10-规格/状态层/全局与HUD.md) 里是「当前费用」的小数部分。

**顺带，这把尺子能量墙钟**：背靠背连抓两帧，`Δ整数 + Δ相位` 就是两帧之间的墙钟间隔，精度约 **±7 ms**——比秒表准得多。[设备层](../10-规格/设备层.md) §3 那几个墙钟耗时用它量。

> **但"1 px"可能比条的实际档位还细。** 一支录像里（`r = 1/3`）条的填充是 **2–3 px 一档**，而 1436 帧里 **925 帧 `Δ = 0`**——**条的渲染是跳档的**，所以读数带一个量化台阶。按 `153 ÷ 60 = 2.55 px` 猜，档位可能是"**1/60 费**"，但那支录像的四条读数（133 / 114 / 92 / 10）除下来是 **52.16 / 44.71 / 36.08 / 3.92**，**不是干净的整数倍，所以没证实**。
>
> **这条待验**：看一段**已知速率**的录像里 `filled` 是不是恒为某个固定台阶的整数倍。**在验出来之前，`0.196 / r` 是上界，不是实际分辨率。**

### 3.3 为什么这样就不怕 ADB 截图延迟

因为读的是**值**，不是**跳变**。

"费用恰好为 3 的那一帧"要赌跳变检测，而 ADB 截图延迟正好打在这个赌上；"这一帧的读数是 2.37"无论什么时候读到都成立——**延迟只影响你什么时候知道，不影响你知道的是什么。**

**它也不怕"帧与帧不连续"。** 0.9 s 的取像节拍打在 1 s 的费用周期上，相邻两帧经常**跨条**（条走满一轮又从左往右走）。这不是信息丢失：

- **跨了几次条，整数位记着**——`Δ费用 = Δ整数 + Δ相位`，跨条只让 `Δ相位` 变负，整数位把那 1 补回来；
- 更要紧的是**根本不需要两帧**：一帧的相位就给出这一帧的绝对时刻，两帧之间的空档由秒表填（§4）。

> **顺带一个必须记住的数值**：0.9 s 与 1.0 s 是**近共振**——每帧相位**倒退 0.1 费**（约 15 px），**10 帧一个循环**（拍频 9 s）。所以**帧间相位差几乎是个常数**，它单独当 Δt 用是退化的（分不出 0.9 s 和 1.9 s）；Δt 必须靠整数位补那个 1。反过来这也说明这把尺子很稳：读数差 1 px 就是 6.5 ms。

### 3.4 零点

**开局时进度条相位必定为 0**（初始费不一定为 0，但那不影响相位）。零点就是**开局那个相位为 0 的帧**。它有两个来源，任一即可：

1. **看见开局**（首选）：工具在战斗开始前就挂着，看见战斗界面出现就把秒表归零。**不需要任何费用算术**；
2. **冷启动读数**：首读时**修正项为零**（还没部署、场上也还没有回费或扣费机制在场），于是

   ```
   游戏时间 = (整数费 − 初始费) + 相位
   ```

   倒推到相位为 0 的那一帧就是开局帧。它只要**初始费**（前提头的一项），**不要** §3.1 那十几种机制的账——因为首读时它们都还没发生。

两个来源都没有（工具中途才接上）→ **零点抓不准** → 游戏时间报**区间**（整条轴平移），[状态层/全局与HUD](../10-规格/状态层/全局与HUD.md) 已经允许这个形态。

**零点只定一次，之后交给秒表**（§4）：相位继续把它拉回来，但跨条数由秒表给。不需要抓跳变，也不需要全速取像。

### 3.5 会停的钟

相位**不是永远在走**的。停有三种原因，而**只有两种我们判得了**：

| 停的原因 | 判得了吗 | 怎么判 |
| --- | --- | --- |
| 暂停 | **判得了** | 暂停是我们自己按的 |
| 封顶（费用到上限） | **判得了** | 满态是另一种视觉：整条中灰 + 白 `MAX`（[视觉层](../10-规格/视觉层/顶部HUD与数字.md)） |
| **锁费**（敌人机制：费用不能增加） | **判不了** | 画面上没有"我为什么停"的指示 |

于是有这条硬规则：

> **相位不动 ≠ 时间不动。** 相位停住时，若我们**没暂停**、画面也**不是满态**，那就只剩锁费一种解释——而它看不见。此时**必须报「时间不可信」**，不许静默外推。

这条走的是已有的降级通道：[接口层/执行与失败](../10-规格/接口层/执行与失败.md) §4 的「时间不可信」→ [状态层/快照](../10-规格/状态层/快照.md) 存疑清单的「时间」那一类。

## 4. 秒表与校准

| | 干什么 | 性质 |
| --- | --- | --- |
| 工具秒表 | 只在非暂停时走；慢放期间按倍率缩放 | 每帧都有值、无延迟，**但会累积漂移** |
| 费用读数（相位） | 独立算出当前游戏时间 | 有延迟，**但绝对值准** |

**主从关系：秒表是主轴（每帧都要、零延迟），相位是校准（定期拉回）。** 两者对齐 → 秒表被拉回，**不累积漂移**。

**跨条数也由秒表给，不由整数费给。** 相位是 mod 1 费的，要定绝对时间就得知道"这是第几秒"——秒表给这个数。整数费不给：整数会被 §3.1 那十几种机制污染，而秒表只被时间驱动。

**所以"截图不连续"在这里彻底不是问题**：两帧之间由秒表填，截图只负责定期把秒表拉回来。**拉回的频率只需要跑赢漂移，不需要追上游戏帧率**——0.9 s 一帧完全够。

**当时间态不由工具控制时，主从要对调**：首轮探索里是**人**在切时间态，秒表不知道该按什么速率走——所以那里**相位当主轴**（它只被自然回费驱动，暂停不走、慢放变慢），秒表降为"相位断掉时"的兜底。理由与取法见[首轮探索/时间对齐](../10-规格/首轮探索/时间对齐.md)。

顺带白拿一样东西：**慢放倍率**。两个读数之间的游戏时间差 ÷ 对应墙钟时间差就是倍率，不用另做实验。

**而且这套校准会自己揭穿假设。** [概念设计共识](../概念设计共识.md) §8.2 里"慢放的性质是拉长真实时长还是改变游戏逻辑"未验证——如果慢放其实不改变游戏逻辑，费用读数会立刻和秒表对不上，我们当场就知道了。

## 5. 暂停与慢放为什么自动一致

暂停冻结游戏时间、慢放拉长游戏时间——**这两件事作用在游戏时间上，而秒表和费用读数读的也是游戏时间**。三者口径天然一致，不需要为暂停/慢放写特例换算。

### 5.1 顺带一个很有用的性质：慢放把墙钟延迟折算小 10 倍

同样一段墙钟耗时，在慢放下折成的**游戏帧**只有常速下的十分之一。"抓判定帧 → 按下暂停"之间那一段 = **取像往返（0.9 s）+ 注入耗时**：

| | 约 |
| --- | --- |
| 常速 | **27–33** 个逻辑帧 |
| 慢放 1/10 | **2.7–3.3** 个逻辑帧 |

（**不是** 200 ms / 6 帧——那个数**漏算了取像往返**。见[控制层/识别时机](../10-规格/控制层/识别时机.md) §4.1。）

所以那一段 ADB 延迟，在慢放下几乎不占游戏时间。

**这是两段式条件要在慢放下卡帧的又一个理由**——它压的是**延迟折算**：同样的墙钟延迟，慢放下折算成的游戏帧只有十分之一。

（**不是**"给 AI 更多的思考时间"——**AI 的思考只发生在暂停**，慢放不给思考时间。见 [概念设计共识](../概念设计共识.md) §2.2 第 1 条、§3 推论 2、§4.1 表格。）

## 6. 速率 `r`：**不许假设 1 费/秒**

```
游戏时间 = 累计自然回费量 ÷ r
```

**`r` 错 3 倍，整条时间轴就错 3 倍**——不是"偏一点"，是全错。

**在我们的场景里，改 `r` 的只有一样东西：合约词条**（用户裁定：**只打合约关卡**，而合约关卡没有「部署费用回复缓慢」这类场地机制）。

- **`r` 进前提头**（[时序层](../10-规格/时序层.md) §3 的「自然回费速率」）——词条是人选的、已知的，所以它是一个**已知系数**；
- **但仍要测出来做校验**：词条文本写的修正不一定就是实际生效的那个数。

**测法（首轮探索的固定产出之一）**：常速下 `上升总 px ÷ 帧数 × 60 ÷ 153`。**这是工具搬的、不是人填的**，符合首轮探索「人的输入里不许有搬运」那条。详见[首轮探索/时间对齐](../10-规格/首轮探索/时间对齐.md) §1。

> **"`r` 可以变"这件事是一次非合约关卡上的实验证明的**：某主线关卡带「部署费用回复缓慢」机制，实测 `1/3 费 / 游戏秒`（24 s 走了 8 圈）。**那个关卡不在我们的场景里**，所以它的值不用处理；它留下的是两样东西——① "速率不是常数"这条**事实**，② 上面那个**测法**。

**连带一条**：相位的**每像素逻辑帧数也随 `r` 变**——`1 px = 30 ÷ (r × 153) = 0.196 / r` 逻辑帧。`r = 1` 时是 0.196 帧，`r = 1/3` 时是 **0.59 帧**。所以"相位把一帧定到零点几帧"这句话**依赖速率**。
