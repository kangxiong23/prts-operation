# 决策记录

> 状态：已定

## 这是什么

这里的每一份日志对应 `10-规格/` 里的一个子系统。它回答的不是"系统现在长什么样"（那个在规格里），而是**"为什么长这样，以及当初为什么不选别的"**。

规格会被改写，日志不会。**只看不改。**

## 写法（四条硬规矩）

### 1. 最新一条写在最上面

打开就是当前状态，不用翻到文件末尾。

### 2. 一条不超过 15 行，字段固定

```
### D-视觉-07 原语只做颜色与统计量，模板只用于定位
状态：已定 ｜ 取代：D-视觉-03
结论：……
理由：……
考虑过的其他方案：……（为什么否掉）
```

`D-<子系统>-<两位序号>` 是这条决策的编号，用来被引用。

### 3. 定了的不改

要改主意，就**新写一条**，在它的「取代」里写上旧编号；同时回到旧那条，只填它的「被取代」字段。**除了这一个字段，旧条目一个字都不许动。**

### 4. 分卷

一份日志超过约 400 行，就切成 `视觉层-01.md`（冻结，不再追加）和 `视觉层-02.md`（活跃）。旧卷改名一次，内容是死的。

> 这条规矩就是为了防止追加式日志变成又长又读不完的文件。如果你发现某份日志已经不好读了，说明该分卷了。
