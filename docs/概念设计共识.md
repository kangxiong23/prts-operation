# 明日方舟 AI 排轴工具：概念设计共识

- 日期：2026-09-25
- 状态：**已定** ｜ 概念层已闭合，方案层进行中
- 范围：只记录已达成共识的目标、功能、行为契约与已排除方向。不含实现方案、不含代码。

---

## 0. 一句话

通过 ADB 让 AI 操作《明日方舟》，把"与游戏交互"的全部负担从 AI 身上剥离，只留下"排轴"这一件事；用抽象逻辑空间替代 AI 识图，用带时序的记录让 AI 反复迭代同一条轴。

---

## 1. 目标与范围

| 项 | 结论 |
| --- | --- |
| 玩法模式 | **危机合约**（Contingency Contract） |
| 关卡粒度 | **单关卡** |
| 达成判据 | **通关一次**即达成，不追求 100% 成功率的轴 |
| 合约词条 | 由**人**选定，AI 不参与 |
| 配队 | AI 可自行决定，也可由人指定 |
| 首轮探索 | 由**人**完成（摸清出怪顺序等），且**该轮同样经过工具记录** |
| 游戏数据库 | 会建立一份游戏数据库，作为 AI 计算的基础 |
| 运行环境 | **安卓真机**，经 ADB 控制（不用模拟器） |
| 速度设置 | **不考虑 2 倍速** |
| 不在计划内 | 普通关卡、集成战略等其他模式（玩法相通，但优化方向专注合约） |

排除集成战略的原因：它是层间策略决策而非战斗轴，与"单关卡排轴"的模型不兼容。

## 2. 系统做什么

### 2.1 功能部件与职责

系统由以下部件构成。每个部件都说明它**负责什么、给谁用、产出什么**。

| 部件 | 负责什么 | 产出 / 给谁用 |
| --- | --- | --- |
| **特征库** | 存放**离线预先采样好**的像素特征，供运行时识别画面元素。覆盖**干员身份、敌人**；血条一类无法用特征描述的元素走规则匹配。**场地机制不在其列**——它由人在地形上标出**挂载点**，**AI 过目一遍地形之后自己[注册字段](10-规格/状态层/注册字段.md)**去观测它。 | 识别所需的特征数据；被抽象层调用 |
| **游戏数据库** | 存放 AI 做纸面推演所需的全部静态数据：干员属性 / 技能 / 部署费用 / 再部署时间，敌人属性，伤害与费用公式等。**另需标注哪些机制可能出现随机**——AI 查阅资料就能知道哪些地方可能有随机，归因因此变得容易。 | AI 的计算基础；被 AI 直接查阅 |
| **关卡地形资产** | 逐关离线固化的地形语义（可部署性、高低台、门），**以及一条一条的出场记录（出怪与路线，一个敌人一条）**，**并携带"格坐标 → 像素"的投影参数**——屏幕位置由投影算出，而不是每帧从画面里找格子。形态是「**一份基础地形 + 每个词条组合一小串被禁用的格子 + 每个词条组合的一小串加怪**」——合约只把部分地面/高台变为不可部署，所以成本与被禁用格数成正比、与地图大小无关。 | 抽象层的静态先验；部署动作的校验依据 |
| **抽象逻辑空间** | 把画面折换成符号化的战局表示，并**自动注入**给 AI。**常驻运行**。 | 注入给 AI 的战局事实；AI 不需要主动索取 |
| **时序存储** | 记录一场战斗的完整过程，并派生出面向 AI 的稀疏视图。 | ①完整时间片记录（机器用）；②关键操作点视图（AI 用） |
| **轴（操作流）** | 一场战斗的操作计划，是**一等公民的产物**：可审阅、可编辑、可批量审批、可复现。**必须声明格式版本与它成立的环境前提**（分辨率、帧率、练度指纹、游戏版本、合约词条、队伍）——否则"审批后重放等于复现"是假的。 | AI 编辑的对象；工具的执行输入 |
| **时间态控制** | 控制游戏处在常速 / 慢放 / 暂停中的哪一种。 | **暂停**：给 AI 思考与介入的窗口；**慢放**：给条件判定的精度 |
| **工具集** | AI 可调用的操作，负责所有"与游戏交互"的动作。 | AI 的指令入口 |

### 2.2 工具对 AI 的行为契约

这是整套设计的核心行为，也是最需要明确记录的部分：

1. **工具会在 AI 思考期间自动保持暂停**，**等到 AI 下达操作指令才继续**。
   即：AI 的思考时间不计入游戏时间。
2. **AI 每次下达指令时，必须同时给出"下一次暂停条件"。** 这是强制要求，没有例外。
3. **在未暂停的情况下，工具收到 AI 的指令会选择暂存而不执行**，直到暂停条件成立。
4. 暂停条件成立 → 工具暂停并唤醒 AI。
5. **抽象状态自动注入**：AI 一般在需要时无需主动截图，因为战局事实已经被送到它面前。
6. **未识别的内容显式上报为"未识别"**，不得从抽象状态里静默消失。
7. **AI 直接截图看图是一条绕过抽象层的独立通道**（不是抽象层的备用通道）；抽象层不需要为它做任何准备。
8. AI 可以**审批操作流**，且支持批量审批。
9. AI 可以先暂停再观测；下一次观测的时机由 AI 决定。
10. 慢放由工具控制进入与退出（进入方式为点击干员，执行任意操作即恢复常速）。
11. 不提供"回到某个时刻"的功能；要重来必须走审批操作流。

12. **轴的格式版本必须显式**；校验不过、版本不认识、动作认不出 → **报错并拒绝执行**，不跳过、不降级、不猜。静默跳过会让"已批准"变成假的。
13. **轴的环境前提由工具在启动前校验**；与当前环境不吻合即拒绝执行，而不是"尽力执行"。

14. **每个动作都必须有可观测的生效反馈。** 工具不得"发完指令就当成功"——部署、开技能、撤退都要能确认是否真的生效，这直接对冲"目标地块被掀掉""费用不足""技能没转好"这类静默失败。确认不了就降级上报，而不是假定成功。

### 2.3 AI 侧要做什么

工具负责交互，那么 AI 剩下的全部工作就是：

- **配队**（可自定，也可由人指定）。
- **首次迭代前读记录**：读人工首轮留下的轴与抽象记录，结合游戏数据库做纸面推演。
- **构轴与改轴**：编辑那条一等公民的轴。
- **实时决策**：战斗中在暂停态下看抽象状态，决定下一步。
- **审批关键操作点**：不是通读全部时间片，只审几个关键点。
- **失败归因**：判断一次失败是概率导致的还是必然的。
- **逐步优化**：每轮吸取上一轮的教训，而不是做排列组合遍历。

## 3. 核心原则：工具与 AI 的责任边界

这是整套设计的第一原则，也是最初诉求"让 AI 专注于攻略构思"的精确化。

- **工具负责**一切"必须边跑边做、且不需要判断力"的事：
  时间态控制、操作注入、画面 → 抽象空间的折换、暂停条件的常驻判定与唤醒、时序记录与操作流审批。
- **AI 负责**一切"需要判断力、且可以停下来想"的事：
  配队、排轴、何时下谁、何时开技能、失败了改哪里。

推论：

1. **工具不需要智能，AI 不需要手眼。**
2. **慢放的唯一职责，是让条件判定足够精准。** 它**不**提供思考时间——思考只发生在暂停（见 2.2 第 1 条）。
   操作的准时性是**顺带的结果、不是慢放的职责**：一次 ADB 注入的墙钟耗时，在常速下折算成好几个游戏帧，在慢放下只折算成约一帧。所以"已经慢放了"的时候，开技能、部署这类操作几乎不会丢帧。**反过来说，不要为了"把操作卡在某一帧"而去开慢放——慢放只为判定而开。**

## 4. 时间模型

### 4.1 三种时间态

常速 / 慢放 / 暂停不是三个独立功能，而是同一条连续谱：

| 时间态 | 用途 |
| --- | --- |
| 常速 | 工具自主执行已知操作 |
| 慢放（约 1/10 速度，未实测） | 让条件判定达到帧级精度 |
| 暂停 | AI 长时间思考；游戏时间冻结，思考不污染轴 |

### 4.2 时间基

- **单局内时间轴为主轴**，逻辑帧（1 倍速下 30 帧/秒）为时间的基本单位。
- **条件触发作为嵌入模块**：游戏内存在少数概率触发的机制会影响排轴，这部分用条件表达而非绝对时刻。
- 暂停期间游戏时间一同冻结，因此 AI 的思考时间不进入时间轴。

### 4.3 观测与条件判定

- **不设置"观测频率"这一设计参数**：下一次观测由 AI 决定，可以先暂停再截图。
- 但**暂停条件必须由工具持续判定**——AI 在思考时判定不了。
  因此**抽象层不能是"AI 问了才答"的被动工具，它必须常驻运行**，是系统里唯一需要一直在线的部件。
- 这两点并不矛盾：慢放把工具的观测周期折算成很小的游戏帧数，于是"不设观测频率"与"工具持续判定条件"可以同时成立。

---

### 4.4 慢放的用法：两段式条件

慢放不是"出错了才用"，而是**精度预算的提供者**：

- **粗条件在常速下判定**。它的容差很大，因此对取像延迟不敏感。
- 粗条件命中 → **提前进入慢放**（进入方式是点击干员，执行任意操作即恢复常速，因此这一步本身不是操作）。
- **细条件在慢放下判定**。1/10 速下一个逻辑帧约 333ms，与 3 FPS 量级的取像周期**同量级**，于是**同一套取像节奏在慢放下就获得了接近逐帧的观测粒度**。

结论：**精度问题靠慢放解决，不必去追求更高的取像帧率。**

因此 **AI 下达指令时要给出两个条件**：**进入慢放的条件** 与 **暂停条件**（这是 2.2 第 2 条的扩展，二者可以相同）。

两条推论：

- **操作不需要"卡帧"这个能力**——**操作发生在暂停点上**，而暂停点的精度已经由慢放保证。慢放在场时，一次 ADB 注入只占约一帧，所以开技能、部署这类操作几乎不丢帧；但那是**顺带的结果，不是慢放的职责——慢放只为判定而开。**
- 一旦精确轴定型，**重放时不再需要慢放**。

代价：慢放可能自身掉帧（估测可接受），以及墙钟时间成倍增长。

## 5. 机制说明（上面那些事怎么做到）

本节只解释第 2 章的功能如何实现，不是设计目标本身。

### 5.1 抽象逻辑空间与指纹复用

- 画面经**像素分布特征匹配**折换成逻辑空间里的标签。特征来自离线采样的特征库：**像素统计特征**，或**简单卷积**。
- 第一次遇到的状态才需要真正识别；识别成功后把**"像素指纹 ↔ 逻辑标签"绑定存档**。
- 此后复现同一条轴时，**识图成本趋近于零**，只有没见过的状态才需要重新识别。
- 于是：**探索轮次越往后越便宜。**
- 结论：**时序存储 / 像素匹配 / 抽象逻辑空间不是三个独立功能，而是同一个闭环的三面**——存储提供已知状态的指纹，匹配把画面折成标签，逻辑空间是标签的容器，新出现的未知状态又回写进存储。

### 5.2 时序存储的双形态

- **完整记录求"全"**（机器用）：每个时间片的状态与操作。
- **面向 AI 的视图求"省"**：只给关键操作点与抽稀状态。
  一场 3 分钟的战斗是 5400 帧，记录体量不允许直接进上下文；AI 只审批几个关键操作点，原始时间片仅在明确要看某一段时才展开。
- **轴是一等公民的计划，不是日志。**（若轴只是日志，AI 就没有可编辑的对象，只能从头再来。）

### 5.3 AI 会自发验证，需要防的是验证过度

AI 会自发核对注入给它的抽象是否正确。因此不需要额外设计"促进 AI 验证"的机制；需要约束的是**过度验证烧 token**。

---

### 5.4 四条地基约束（现在就得定，补起来极贵）

这四条决定接口形状，属于"定晚了代价翻倍"的类别；来源见 [MAA借鉴清单.md](50-外部借鉴/MAA借鉴清单.md)。

1. **定死运行环境，不做分辨率适配。** 所有识别压到一块归一化画布上，坐标只以该画布为单位；不合规的分辨率**直接报错**，不降级、不适配。分辨率一旦成为资产的一个维度，条目数与回归成本直接翻倍。
2. **视觉原语契约**：`ROI + 原语种类 + 结果 {矩形, 分数, 载荷}`。抽象战局里的**一切需识别字段**都必须能回答"在哪个 ROI、用哪种原语、置信度多少"。**（置信度是视觉原语结果的属性，不是字段的属性：身份来自部署记录、游戏时间由费用推算，这两类没有识别过程，也就没有置信度。）** 字段取值为**三态**：未采样 / 已采样且为空 / 有值——**AI 把"没采样"当成事实，比认错更危险。**
   **补充——结构化模糊（识别可以不精确，但不得产生假事实）**：识别的最小单元允许退化为"已知有东西 + 结构化估计"，不追求真值。字段除三态外还带**取值形态**（权威定义见 [状态层/README](10-规格/状态层/README.md) 的 G1；**「分档」不是独立形态，它就是粗区间**）（**"定性"一档已由下方修正删除**）。群体与个体分两层表达：**一个粗略的群体描述 + 枚举出可辨认的个体**（怪群重叠时，"数量下界 5、区域内混合，其中这 3 个看得清"比强行逐个识别更接近人类视觉理解；强行识别本就很难识别的东西，本就不太可能）。两条硬约束：① **模糊必须结构化且可计算**（"数量下界 5"而不是自然语言），否则 AI 的纸面推演无法与数据库对账；② **识别失败必须降级，不能消失**——我方干员的身份另有第二来源（我们自己下达的部署记录），因此特效遮挡（例如保护罩表现为把干员包裹起来的粉色泡泡）导致的失败，应表达为"该格有我方单位、状态未知"，而不是"无法识别所以当它不存在"。

   由此，**抽象层的验收标准不是识别准确率，而是"零假事实"**：在难例（怪群重叠、特效包裹、遮挡、动画中间帧）上不得输出错误的确定值，允许输出"未知或结构化模糊"。

   **修正（关于上面这一段的表述）**：视觉层**不走大模型**——它用卷积或特征匹配，输出的是**可计算的数值与置信度**。因此：
   - 所谓"模糊"应当是**数值形态**（估计值 + 置信度、区间、下界），**"定性（这里有很多怪）"这一档应当删除**。不是因为 AI 无法对账，而是因为视觉层本来就产出数值，没有理由把它降级成文字。
   - "AI 的纸面推演无法与数据库对账"这个理由**不成立**——AI 拿到的是数值，本来就能对账。
   - **AI 直接截图看图是绕过抽象层的独立通道**（此前已决定保留），抽象层不需要为此做任何准备。
   - 保留下来的只有两条：**输出必须是可计算的数值**，以及**识别失败必须降级、不得消失**。

   **补充——主判据的选择**：识别应当**以颜色与统计量为主判据，模板只用于限定 ROI 与做锚点**；对遮挡物使用**取自原图的掩码**把它排除，只匹配没被盖住的部分。理由来自"特效把干员整个包住"这类难例（例如保护罩表现为一个大泡泡）：拿一张会被特效破坏的模板去匹配整张立绘必然失败，而"先按颜色找到泡泡、再在泡泡之外匹配"是可做的。（依据见 [MAA借鉴清单.md](50-外部借鉴/MAA借鉴清单.md) 第八节。）

3. **视觉层必须能被离线驱动。** 它不允许与实时取像耦合：只有这样才能把本地截图喂进**与线上完全同一条**链路，产出命中项与分数，作为抽象层的验收手段；并且必须显式记录"离线复刻与线上的不一致之处"，否则结论本身会错。
4. **按需声明识别字段。** 每个暂停条件声明它依赖哪几个字段，工具只对这些字段做高频判定；部署一类动作只在入口校验它自己需要的那一格/那一项。这是"工具常驻判定条件"在算力上可行的前提，也是"地形不做常驻监测"的依据。

### 5.5 难例采集与基准集

工具必须在运行时**自动采集样本**，而触发条件应当是"**模型自己不确定**"而不是固定时刻。**具体是三层**（通用层 / 方法层 / 资产层），已落成规格 → [采集与验收](10-规格/采集与验收/README.md) §1；**这一节不复述那份清单**，只留这条精神。落盘时把那一帧连同它对应的逻辑标签与置信度一起按类分目录保存，并保留一个**定量上限**。

这一份数据是**两样东西：A4 的基准集、回归测试的输入**（外加[特征库](10-规格/资产生成器/特征库.md) §4 的一条**回流驱动**）。它成本极低——采集器是记录层的副产品，不需要额外设计。

> **曾经写作"三样东西"，第三样是"训练数据"——已删。** [D-全局-06](20-决策记录/全局.md) 定了**不上训模型**，否掉的理由正是"在还不知道哪一步最不准之前训模型，是在猜"；而**难例集恰好就是回答"哪一步最不准"的那个东西**——所以它是**那条决定要用的输入**，不是一份数据集。见[采集与验收/难例采集.md](10-规格/采集与验收/难例采集.md) §3。

**而且标注的大头是免费的。** 我们知道自己下达过哪些部署指令，也知道关卡的**路线资产**（一个敌人一条，含出怪）——这两样本身就是答案：干员身份的标注几乎自动可得；敌人一侧至少能用它打上"这几张里该出现哪几种"的粗标签。**用已知信息当真值可以把数据成本砍掉一大块，而这取决于记录层怎么设计，不是只能靠时间硬堆。**

## 6. 探索循环

```
人工首轮（经工具记录）
  → 得到粗糙的轴 + 出怪顺序 / 费用曲线 / 首次接敌时刻（记录的副产品）
  → AI 读记录 + 查数据库 → 纸面推演 → 提出改法
  → 工具执行（暂停 / 慢放 / 条件唤醒）
  → AI 依推演归因，调整
  → 收敛：通关一次
```

关键约定：

- **纸面推演与实机搜索互相促进，两者都需要。** 空有推演是理论脱离实际，空有实机是缺乏理论指导的盲目实践。预期 AI 会自发采用这套模式；若不行，用提示词约束。
- **不提供"回到某个时刻"的功能**（重放很耗时）。要重来，必须**审批操作流**（可批量审批）。
- **重跑允许，但不推荐反复重跑。**
- **排除"稳定失败再改轴"这条策略。** AI 应当有能力判断一次失败是**概率导致**的还是**必然**的，而不是靠重复实验去测。
- 不推荐 AI 为单个操作反复试验（各种操作玩排列组合搞遍历）。每轮应当**吸取上一轮的教训逐步优化**。

## 7. 随机性与可复现性

- 随机仅存在于**少数带文本条的判定**上，例如概率物理闪避、概率造成等同若干比例攻击力的法术伤害。
- 敌人技能释放顺序是**半随机**。
- **经验判断**：即使存在随机，对 DPS 的影响通常约 **5%**；个别机制以及小概率运气下会有较大差别。
- 处理方式：**数学期望可以处理大部分随机。**
- **确定性骨架**：地形、敌人路线、出怪顺序、索敌目标等大量因素都不存在随机。
- **地形的两点例外**：合约词条会在开局把部分地面/高台变为不可部署（静态，随所选词条一次性确定）；另有"掀地板"类敌人技能可在战斗中把可部署地块变为不可部署（**目前尚未出现在合约中**）。因此地形按「离线初值 + 部署时定点校验」处理，不做常驻监测（见 5.4 第 4 条）。
- 因此：**"轴可复现"不依赖任何锁种子机制。**
- **凹概率本质也是凹轴的一环**，但高度依赖概率的轴（惯称"邪修"）**不属于常规凹轴，不在本项目范围内**。
- 游戏数据库需标注"哪些机制可能出现随机"，使 AI 的归因有据可依。

### 8.1 已知事实

| 项 | 状态 |

| 战斗 30 帧/秒（1 倍速），逐帧操作可行 | 已知 |

### 8.2 待实测（设计依赖它，但尚未验证）

| 项 | 说明 |
| --- | --- |
| 暂停是否完全冻结一切 | **不作为方案前置**。这属于游戏方的设计，即使验证出问题我们也无法改变，因此按"已冻结"处理，实现期自然会见分晓。 |
| 慢放倍率 | 约 1/10（未实测）。外部资料存在 1/5 与 0.25 倍两种互相矛盾的口径。**实现期测量即可，不作为方案前置**（已确定不使用 2 倍速，故不涉及叠加）。 |
| 慢放的性质 | 是"拉长真实时长"还是"改变游戏逻辑"。——**设计按"改变游戏时间本身"推进**：自然回费是 1 秒 1 费，而它**跟随暂停与慢放变慢**，说明慢放动的是游戏时间，不只是画面刷新。实现期用费用读数复核（见 [时间基](30-专题/时间基.md) §4）。 |

| 失败 / 中途退出的理智返还、演习次数限制 | 外部来源称已全额返还且演习无限次，未实测。 |
| AI 的暂停态与游戏的暂停态是否同步 | 需确认"工具在 AI 思考期间自动保持暂停"能稳定成立。 |

### 8.3 开放项（已明确推迟到方案阶段）

1. **失败归因的具体判据**：什么算"概率失败"、什么算"必然失败"。不做一刀切，实际情形复杂，届时再定。
2. **重跑的次数上限**：跑几次算"反复"。
3. **抽象层自校验的强度** —— **已结案**：以"离线重放线上识别链路"作为验收手段（见 5.4 第 3 条）；方案阶段仍需确定的是**过度验证的 token 量级约束**。
4. **数据库与实测冲突时以谁为准**（倾向：以实测为准，并上报冲突）。
5. **观测频率的折算**：慢放倍率实测值如何把工具的判定节奏折算成游戏帧。
6. **工具粒度**：具体封装哪些工具、原子操作与宏的切分线。

## 9. 已排除方向

记录在此以免重复讨论。每条都是明确否决，不是待议。

| 方向 | 否决理由 |
| --- | --- |
| 以**代理指挥**作为探索循环的基石 | 代理指挥是通关后便于玩家挂机刷材料的功能，与"通关"这一目标无关，不纳入设计。 |
| 以**容错余量**作为优化目标 | 容错不意味着能力强；高水平的轴往往打得很极限、容错很低。优化目标就是通关。 |
| 由工具或 AI 做**遍历试探**来定位问题操作 | 交给 AI 自由判断，给它足够的思考空间，不一味束缚。 |
| 敌人身份可由关卡数据 + 出怪顺序**推导**，因而无需识别 | 否决。敌人和干员一样需要识别，另有各类场地机制也需要识别。 |
| 归因规则**一刀切** | 否决。归因留到方案阶段按实际情况处理。 |
| "通用 AI 玩方舟"（任意关卡任意编队端到端通关） | 与"单关卡排轴"的模型不符，且会让"AI 专注攻略构思"的承诺落空。 |
| 集成战略 | 层间策略决策而非战斗轴，模型不兼容。 |

## 10. 术语

| 术语 | 含义 |
| --- | --- |
| **轴 / 排轴** | 一场战斗内操作与时刻的完整计划。本项目中的"轴"是一等公民的计划对象，可审批、可编辑。 |
| **邪修** | 高度依赖概率的轴。不属于常规凹轴，不在本项目范围内。 |
| **凹轴 / 凹概率** | 反复重开以取得理想随机结果，本质也是凹轴的一环。 |
| **时间片** | 时序记录的最小单位，记录该时刻的状态与操作。 |
| **暂停条件** | AI 指定的、由工具持续判定并在成立时唤醒 AI 的谓词。 |
| **慢放** | 游戏自带的减速状态，约 1/10 速度。进入方式为点击干员，执行任意操作即恢复常速。 |
| **抽象逻辑空间** | 画面被折换成的、供 AI 理解的符号化战局表示。 |
| **特征库** | 离线预先采样好的像素特征集合，覆盖干员身份与敌人。场地机制不在此列。 |
| **地形资产** | 逐关离线固化的地形语义：一份基础地形 + 每个词条组合一小串被禁用的格子；**另含一条一条的出场记录（出怪与路线，一个敌人一条）**。 |
| **指纹** | 某个战局状态对应的像素分布特征，绑定逻辑标签后可复用。 |
| **识别器** | 针对固定 UI 元件的匹配规则（如血条比例）。 |
