## 二、技术栈（提议，未定）

| 项 | 选择 | 理由 |
| --- | --- | --- |
| 引擎语言 | Python 3.12 | 视觉生态最全；离线资产生成器可共用同一套代码 |
| 引擎形态 | 独立进程 | 图像处理再重也卡不住 AI 会话 |
| 接口 | MCP（Model Context Protocol）over streamable-http | 见第三节。进程独立存活，AI 会话重启不丢战局 |
| AI 侧 | 不写代码 | 跑在 DSH 里，只需配置 |
| 设备层 | 可替换接口，先实现纯 adb | 见下面的三条红利 |
| 视觉 | OpenCV 原语 + 小模板匹配 | ONNX 分类器延后到确实需要时 |
| 时序数据 | JSON Lines | 可读、可 diff、可离线重放；量大再换 |

### 三条架构红利：为什么不需要高性能方案

1. **会暂停** → 不需要低延迟输入，`adb shell input` 那点延迟无所谓。
2. **判定发生在 1/10 速下** → 不需要高帧率取像，3 FPS 够用。
3. **识别只在小 ROI 上做颜色与统计量** → 不需要重型 CV，更不需要大模型。

所以 `scrcpy` 那种 30–120 FPS、35–70 ms 延迟的通道暂时不值得装。等实测发现纯 adb 跟不上再换，接口留好了换起来不痛。

## 三、已查实的 DSH 侧事实

以下来自本机 DSH 安装目录的代码与文档（版本 `0.2.0-rc.1`），或通过 Inspect 接口的实时查询。

### 3.1 MCP 能给什么

| 能力 | 状态 |
| --- | --- |
| 工具定义（名称 / 描述 / 参数 schema / 输出 schema） | 支持，含输出 schema 校验 |
| 返回结构化 JSON | 支持 |
| 返回图片（PNG / JPEG / WebP / GIF） | 支持，直接进对话 |
| 单次调用可取消 | 支持 |
| 调用超时 | 默认 60 秒，**可配置** |
| 工具列表动态变化 | 支持，自动重新同步 |
| 资源（resources） | 支持，按需拉取，二进制不内联进上下文 |
| 服务器指令进系统提示词 | 支持，上限 32 KB |
| 结果走 DSH 同一套策略管线 | 支持 |

`toolCallTimeoutMs` 可配置，是阻塞式 `wait_until` 能成立的硬前提。

### 3.2 MCP 给不了什么

- **没有进度通知。** MCP 协议有 progress，但 DSH 这一侧没有接（`dsh-mcp-client` 里没有任何 progress 处理）。长调用期间界面上只有「调用中」。
- 服务器不能主动发起对话 → **不影响**，阻塞式等待不需要这个能力。
- 拿不到 DSH 宿主服务（timer / storage / jobs / spillStore / session 事件）→ **不影响**。
- 提示词模板、音频、嵌入资源、资源订阅、task 扩展均不支持 → **都不用**。
- stdio 传输会清洗环境变量（去掉匹配 `*KEY|PASSWORD|SECRET|TOKEN*` 与 `DSH_*` 的名称）→ 我们走 HTTP，不受影响。

### 3.3 MCP 不必是全局共用工具

把 `@deepseek-ai/dsh-mcp-client` 写进预设（preset）的 `config.plugins`，它的工具与提示词段落**只对选中该预设的会话可见**。

证据：

- `dsh-agent-preset-registry/README.md`：「Plugin registrations inherit the preset scope, and the Agent scope's parent link controls visibility.」
- `dsh-tools` 的 `register()` 把工具落在注册方 context 所属的作用域层；读取时按调用方作用域解析。
- `dsh-mcp-client/lib/index.js` 的注释明确承认「Agent-scoped MCP servers may reuse a namespace in another Agent, while global instances and duplicates inside one Agent remain mutually exclusive」——即两种模式并列，是选择而非必然。

附带好处：预设的实例是「eagerly activated once and shared」，MCP 连接只建一次，不会每个会话各起一份连引擎的连接。

### 3.4 模式（预设）本身也是零代码

| 想要的 | 怎么给 |
| --- | --- |
| 专属工具链 | 挂 `dsh-mcp-client` 一行 |
| 专属系统提示词 | 挂 `dsh-persona`，字段 `prefix`（必填） |
| 专属 skill | 挂 `dsh-skill-filesystem`，`includeDefaultRoots: false` + `customSkillDirs` |
| 专属工具包 | 挂现成的 `@deepseek-ai/dsh-tool-*` |

落盘是一个 bundle（捆绑包）目录两个文件：`package.json` 与 `cordis.patch.yml`。所以**接引擎与建模式可以合并成一次配置**。

**硬约束**：预设**不是安全沙箱**。官方原文「Presets are not security sandboxes: YAML and plugins can execute Host code.」不能用模式来限制 AI 只能操作游戏；真正的边界是 permission preset（权限预设）与沙箱策略。

### 第 3 档的具体风险

官方在 `references/practices.md` 里自己划了线：

| 接口点 | 风险 | 变动后果 | 官方态度 |
| --- | --- | --- | --- |
| 主题 token（`--dsw-alias-*`） | 最低 | 外观降级 | 重命名「只会让外观降级，永远不会让渲染崩掉」 |
| 任何 Harness Client 包（如 `dsh-client-ui-primitives`） | 最高 | 组件抛错 → 整块 slot 空白 | 「会无预警变化」，明确要求不要这么做 |
| slot（插槽）key 名与 `ctx.slots.register` 选项 | 中高 | 面板不出现 | 真正的耦合点，无法消除 |
| `window.__ModuleLoader__` | 中 | client 半边不加载 | 契约本身，没有替代 |
| 给 session 事件加新 `type` | 禁止 | Session 拒绝重开 | 明令禁止 |
| 监听 `system-prompt/assemble` 改文本或工具 | 禁止 | 覆盖别的插件 | 应该用 `ctx.systemPrompt.section()` |

三条有利事实：

1. **失败是局部的**：slot entry 崩掉只是那一块空白，不会带崩 harness，也不会带崩 AI 会话。
2. **配置在补丁层（patch），升级后存活。**
3. **有不兼容门禁**：不兼容的 DSH peer 依赖会被拒绝安装与激活；最小插件不声明任何 DSH 依赖，不会触发它。

**纪律**：UI 插件是**纯消费者**——只从引擎的 HTTP 接口读数据画图，不参与业务逻辑、不加 session 事件、不 import DSH 包、只用主题 token。违反这条，风险就从「最坏看不见面板」变成「可能修不动」。

### 坐到哪个位置上（实时 Slot 树已查实）

平台为每个 slot 标了 `replaceRisk`，这是它自己给出的稳定性信号：

- `none` —— 追加式座位，你的注册只增加内容。**优先选这些。**
- `shadows-shipped-ui` —— 你的注册会**替换掉官方 UI**。别用。

| 座位 | 类型 | 风险 | 用途 |
| --- | --- | --- | --- |
| `tool.call.toolview` | keyed，keyDomain 开放 | 追加 | **给某一次工具调用的卡片做自定义渲染** |
| `sidebar.panellist` | list | none | 全局面板图标（现有的 skill-explorer、skin-center 都挂这里） |
| `main` | keyed，已被 `conversation` 占一个 key | 追加 | 中央大面板，由上面那个图标打开 |
| `sidebar.right.pane.tab.title`、`sidebar.right.tab.document.*` | keyed，尚无人占用 | 追加 | **会话级**右侧面板的标签页 |
| `settings.section` | list | none | 一个独立设置页 |
| `conversation.input.dock`、`conversation.composer.dock` | list | none | 输入框上方／下方的整宽条目 |
| `sidebar`、`sidebar.settings`、`conversation.session` 等 | — | **shadows-shipped-ui** | 不要用 |

### 第一版可视化应该做什么（结论改了）

本来是「做一块轴的面板」。查完实时 Slot 树之后，**第一步应该是给工具调用做自定义渲染**。

`tool.call.toolview` 是「按工具名分派的自定义视图」，keyDomain 开放。给 `mcp__ark__*` 注册它，意味着 **AI 每读一次状态、每回看一次轴，那张图就就地出现在对话流里**，而不是甩一坨 JSON。

这比新开面板好在三点：用的是最常规的一类 slot、用户不需要主动去开面板、而且它直接命中「像黑盒」这个具体抱怨。

大面板留到第二步 —— 那时才需要 `sidebar.panellist` 与 `main` 那一对。

## 五、配置契约的漂移风险（本机实证）

这一条比插件代码的风险更值得注意，而且本机已经发生过。

1. **本机有一份死代码。** `C:\Users\ASUS\.dsh\.agent-presets\liangshen\` 目录还在，但注册中心**不扫描这个目录**；检索整个安装目录，读取 `.agent-presets` 的地方是零处。
2. **有一份过时的官方 skill。** `dsh-preset-authoring` 仍在教这个已经没人读的目录格式，与 `editing-cordis-compositions` 互相矛盾。
3. **字段级漂移是静默的。** 那个死目录用的是 `config.text`，而现在 `dsh-persona` 的字段是 `prefix` 且必填，没有 `text`。schema 校验不过 → 预设无法挂载，且不报崩溃。
4. **包名漂移同样静默失败。** 包改名后预设仍留在列表里带诊断信息，但选它开不出会话。
5. **覆盖是整体替换，不合并。** 不要复制官方 `standard` 预设全量再改——官方以后新增的行不会进你的副本。

版本锚点：`dsh`、`dsh-mcp-client`、`dsh-agent-preset` 全部是 `0.2.0-rc.1`。rc 阶段，上面那个迁移就是格式仍在变动的直接证据。

**对策**：

- 把 bundle 源目录放在工作区并纳入版本管理，把它当**可重建的派生物**，不是长期手工维护的资产。升级后重装。
- 字段名只从实时投影的 schema 或官方自带预设抄，**绝不凭文档或记忆**。
- 升级后的验收：**新开一个空白会话**选中该预设，用 Inspect 查工具面里有没有 `mcp__ark__*`。已加入的会话保留启动时的版本，必须新会话验。
