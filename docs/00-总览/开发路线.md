# 开发路线

> 状态：讨论中 ｜ 两条轨 · 四段 · 分工边界已定；每段里面的细项随做随补

**它是什么**：**接下来怎么排活**。已经做掉的记在[方案逻辑全景](方案逻辑全景.md) §8，这里只排**还没做的**。

## 1 总目标与主轴

**总目标**：AI 在**合约**关卡上经 ADB 操作真机，**通关一次**。

**主轴只有一条**：一条数据从手机屏幕走到 AI 的决策，中间每一段都是一层。

```
屏幕 → 帧 → 数值 → 状态 → 记录 → 决策 → 动作 → 屏幕
      设备层  视觉层  状态层  时序层  控制层  接口层  设备层
```

**顺序就是这条链的顺序，不能跳。** 跳了就会出现"拿着一堆没法验证的东西往下写"。

**链上有两处"没有前置就走不动"**，所以资产不是并行插进来的，是**前置**：视觉层要资产（字形表 · 卡面与指纹 · 图标模板）才读得出东西；状态层要[游戏数据库](../10-规格/资产生成器/游戏数据库.md)才知道读出来的数是什么意思。

**贯穿全程的一条纪律**：视觉层是最大的一块，所以**离线回归必须尽早建** —— 否则改一行就得掏手机。

## 2 两条轨

| 轨 | 是什么 | 谁 |
| --- | --- | --- |
| **A 在线链路** | `contracts` → `engine`（设备 → 视觉 → 状态 → 时序 → 控制 → 接口）→ AI 侧 | 规划者 + 执行者 |
| **B 数据与资产** | 游戏数据库 · 关卡资产 · 卡面与素材 | 协作者（见 §6） |

**两轨之间只通过「文件」说话，不共用代码。** 轨 B 产出 `assets/` 下的文件与 `data/` 里的原始数据，轨 A 通过资产端口读它们。这就是不撞车的全部道理。

### 协作边界三条

1. **目录分开**：轨 B 只写 `src/ark/offline/dbgen/` · `data/` · `assets/gamedata/`；轨 A 写 `src/ark/engine/` · `src/ark/contracts/` · `src/ark/offline/assets_gen/` · `src/ark/runtime/` · `tests/` · `scripts/`。
2. **文档只有一个作者**：`docs/` 全归规划者。轨 B 要改规格就写**提案**，由规划者落档 —— 两个人同时改同一份文档是冲突最凶的一种。
3. **交界处先有规格**：轨 B 要产出的文件长什么样，由规划者先写成规格（例如[游戏数据库](../10-规格/资产生成器/游戏数据库.md) 的字段表），轨 B 照着产出。**格式没定之前不开工。**

**走 GitHub 之后这三条不变**，还多一条：**产数据的脚本必须在版本库里** —— `data/` 与 `assets/gamedata/` 都是**不进版本库**的（可重建的产物），所以脚本不进库，别人就复现不出那份库。

## 3 四段

| 段 | 目标（做完能干什么） | 判据 | 主要产出 |
| --- | --- | --- | --- |
| **一 看得见** | 一帧能读成几个数；这套识别**不看真机也能跑** | 对着基准集逐帧对得上；读不出的如实报"读不出" | 设备层收口 · 重放适配器 · 基准集 · 视觉层读数链 |
| **二 说得清** | 一串帧能变成一份**人能看懂的记录** | 前提头对不上就拒绝；记录里每个字段都带三态 | 状态层字段与快照 · 时序层记录与轴 · 游戏数据库 |
| **三 拿得住** | AI 写一条轴，工具**在离线重放上跑完一整局** | 跑完产出一份记录，动作"只记不点" | 控制层（暂停 / 慢放 / 条件）· 接口层（算子 / 生效反馈） |
| **四 打得过** | 真机上打完一局 | **通关一次** | 首轮探索编辑器 · 地形 / 路线 / 背景帧 · 采资产与录轴两局 |

### 段一 看得见

1. **设备层收口**：端口那笔账 · 设备事实 · 轴上的四个动词 · 备战席卡框 · `r` 的实测值 · 朝向取法裁定 · **一次最小投影标定** · 真机上一次部署成功且朝向正确。
   > 投影标定这里只做**最小的一块**（给张截图 + 一个可拖的格网，人对齐 → 原点 / 列步长 / 行步长）。完整编辑器在段四 —— 它**复用段一的识别策略**，所以不能提前。
2. **离线回归闭环**：重放适配器 + 基准集（**帧 + 出处**——期望值住 `tests/spec/`，见[基准集](../10-规格/采集与验收/基准集.md)）。**紧跟第一步**，它是后面所有识别工作的省力装置。
3. **视觉层读数链**，按"AI 最需要"排：顶部 HUD（费用已有 → 生命 · 敌人计数与总数）→ 备战席（哪几张卡 · 每张是谁 · 费用 · 可用与冷却）→ 场上我方干员（在哪 · 朝哪 · 血条 · 技力 · 可释放菱形）→ 敌方单位（候选区 + 至少几个）→ **时间态**（现在是不是暂停 / 慢放，这条是段三的前提）。

### 段二 说得清

1. 游戏数据库可用（轨 B）
2. 状态层：字段表落地 · 快照 · 存疑清单
3. 时序层：观测迹（稀疏、变化驱动）· 轴与记录

### 段三 拿得住

1. 控制层：暂停 / 继续 / 慢放 · 暂停条件（**时限必填**）· 主循环
2. 接口层：算子清单 · 执行与失败（生效反馈 · 三种错误）
3. **离线重放一整局**：录下来的帧序列喂进去，动作只记不点，跑完出记录

### 段四 打得过

1. 首轮探索编辑器（投影标定 → 地形 → 路线 → 背景帧 → 卡面），**复用段一的识别策略**
2. 采资产那一局（一个词条都不选）
3. 录轴那一局（带目标词条）
4. 真机闭环 → 通关一次

**打哪张图见 [D-全局-21](../20-决策记录/全局.md)**：产品只打合约，而**开发期可以打「全息作战矩阵」**（常驻，模式接近老合约）—— 所以段四**不等活动**。

## 4 资产轨的时间表

| 资产 | 谁要 | 什么时候要 |
| --- | --- | --- |
| 字形表 | 费用 / 生命 / 计数 | **已有** |
| 游戏数据库 | 状态层 · 卡面与指纹 | 段二之前 |
| 卡面与指纹 | 备战席识别（谁是谁） | 段一 3 的备战席那一步之前 |
| 特征库（图标模板） | 黄菱形 · 暂停按钮 | 段一 3 的场上干员那一步 |
| 背景帧 | 敌方单位差分 | 段四（只有无词条局的开局帧算数） |
| 地形 / 路线 | 状态层地形 · AI 排轴 | 段四 |

**一个要认的后果**：敌方单位那条**差分**读法要背景帧，而背景帧要段四的无词条局 —— 所以段一里敌方单位**只能先走不靠背景的读法**（色块 / 轮廓）。这不是取舍，是没得选。

## 5 谁读这份文件

- **规划者**：按段排任务消息，每段做完走一次闭环；
- **执行者**：知道自己这一单在哪一段、下一步是什么；
- **协作者**：只看 §2 的边界三条与 §6 自己的工作包。
