# 协作方式

> 状态：已定 ｜ 四个角色 · 一个工作单元 · 一套消息格式；改这套以前先改这份文件

**它是什么**：这个项目**怎么被推进**。系统长什么样在 [10-规格](../10-规格/代码结构.md)，为什么长那样在 [20-决策记录](../20-决策记录/全局.md)，接下来排什么活在[开发路线](开发路线.md)。这里只写**交接**：谁干什么、一件事怎么算做完、消息长什么样。

## 1 谁干什么

| 角色 | 是谁 | 干什么 | 不干什么 |
| --- | --- | --- | --- |
| **规划者** | 本项目里的 AI（PM + 系统测试） | 定"要什么" · 定真值与判据 · **判定** | **不下场**（见 §3） |
| **执行者** | 另一个 AI 会话 | 重的活：实现 · 量数 · 建夹具 · 单元测试 | 不读**也不跑** `tests/spec/` |
| **子代理** | 规划者临时开的一次性 AI | 轻的活：探针 · 复算 · 查证 | 不碰交付物 |
| **协作者** | 人 | 轨 B：数据与资产 | 不改 `docs/` |

几条界线**已经有正文，这里只指路**（重述没意义，漂移才是有害的）：

- **`tests/unit/` 与 `tests/spec/` 分家** —— 权威是 [D-全局-17](../20-决策记录/全局.md)；那个目录自己的说明在 [`tests/spec/README.md`](../../tests/spec/README.md)。**"不读"要连"不跑"一起算**：跑一次绿的漏一个条数，跑一次红的会把每条检查的判据、出处与证据一起端过来 —— 而 `testpaths` 把 `tests/spec/` 排除在外就是为了这个（[D-全局-22](../20-决策记录/全局.md) ③）。它要跑的是 `tests/unit/`、`tests/contract/` 与那四道工程卫生闸门。
- **轨 A 与轨 B 的边界三条**（目录分开 · 文档只有一个作者 · 交界处先有规格）—— [开发路线](开发路线.md) §2；
- **游戏机制的问题问用户，不查网上** —— 机制细节查错了，会把"我以为"写成规格，而规格是所有下游的地基。**用户是这一件事的唯一判据来源。**

## 2 工作单元是「层」，检查点是「闭环」

**一件活 = 一层。** 层的顺序就是链的顺序（设备 → 视觉 → 状态 → 时序 → 控制 → 接口），一层都跳不得 —— 跳了就会出现"拿着一堆没法验证的东西往下写"（[开发路线](开发路线.md) §1）。

**一层做完走一次闭环**：

```
规划者写规格 → 发任务单 → 执行者做 → 执行者按四节报（§5）
    → 规划者机械核对 + 跑验收网（tests/spec/）→ 验收报告 → 才进下一层
```

闭环不是仪式，它是**"这一层可以往下压了"这句话的唯一依据**。验收报告必须说清三样：**过了什么 · 拿什么证 · 哪几处没证**。只说"全绿"不算报告 —— 那没回答"还有哪一面没有网"。

**没做完的活不许带进下一层**：真做不完就记进欠账，写明"谁欠谁、卡在哪"。

## 3 规划者不下场

**要动手的活按重量分两路**：重的给执行者，轻的（一次性探针 · 复算 · 查证）开子代理。理由与那个代价见 [D-全局-26](../20-决策记录/全局.md)。

**"不下场"不包括查验。** 读文件 · 搜代码 · 跑规划者自己的验收网（`tests/spec/`）仍然归规划者 —— 那是**判定**，不是下场。**判不了就不算审过。**

**画面事实不以下发常量的形式给出。** 某一帧上量出来的坐标 · 尺寸 · 阈值，由**要用它的那一侧**量、或者由**画面本身**来判；规划者下发的是**要求**，不是**值**。理由与一个四层网全塌的实例见 [D-全局-25](../20-决策记录/全局.md)。

## 4 任务单：一张表

派活 = 一份任务单。**字段缺一个就不发**，顺序固定：

| 字段 | 写什么 |
| --- | --- |
| 【目标】 | 这一单做完能干什么。一句。 |
| 【先读】 | 开工前必须读的文件，**每条带 LF 折算 sha256**（[D-全局-18](../20-决策记录/全局.md)）。 |
| 【已裁定】 | 已经定死、**不许再讨论**的取舍。 |
| 【已批准】 | 用户明确点头过的事。 |
| 【做】 | 这一单要产出的东西，逐条。 |
| 【不许做】 | 越界项：不属于这一单的 · 会破坏别层的 · **以及已经否掉的方案**（否掉的不写，它下一轮还会再提一遍）。 |
| 【验收】 | 判据。只说**哪些话成立** —— 不列检查编号、不写绝对条数（[D-全局-22](../20-决策记录/全局.md)）。 |
| 【汇报】 | 交回时的四节，见 §5。 |
| 【卡住】 | 卡住先报再等；**不许自己改判据**。 |
| 【哈希】 | 交付物按 LF 折算的 sha256 + 裸 LF 行数（[D-全局-23](../20-决策记录/全局.md)）。 |

**发单之前，【做】里的每一项都要指得出它落在哪张网里。** 网有三种：它自己的 `tests/unit/` · 规划者的 `tests/spec/` · 以及那几道工程卫生闸门（`import_rules` · `port_completeness` · `check_docs` · `check_text`）。**指不出来的，要么当场把网建起来，要么这一项不许进单。**

理由：**纠正清单的轮数是"缺网"的读数。** 同一个单子里摆着两条对照 —— 有网的那部分（阈值 · 尺度 · 红罩：规划者 6 帧的实测 + 它 26 条单测 + 规划者 12 条检查跑 10 帧）**一轮就过**；没网的那部分（编队页几何：一个数 · 一帧 · 一个来源）**挖了四轮**，而每一轮挖出来的都是同一个错往下的一层。网一次建好，比事后一轮一轮补便宜得多；而"这一层只剩一件小事了"这种话，没有把【做】的每一项对着网点过一遍，就不许说。

**还有半句：数一数有几份抄本。** 不止问"【做】里的每一项落在哪张网里"，还要问"**这个数 / 这条结论在仓里有几份抄本，每一份都指得出网吗**"。一个数同时住在常量 · 规格文档 · 夹具 · 代码注释里是常态；只给"这一单要做的那一份"配网，其余几份会**安静地过期**。实例：编队页那组几何数一共四份，第一轮只想到了三份 —— 第四份（代码 docstring 里那张同款表）是子代理翻出来的。**定完网，先数一遍有几个人在说同一句话。**

**一条硬规矩：凡是要跟执行者说的话，都放进代码块。** 代码块之外是给用户看的 —— 说清"为什么这么派"。混着写，人就得替你挑，挑漏一句就是一次返工。

## 5 汇报：四节

交回来必须分四节，**缺一节不算交付**：

| 节 | 回答 |
| --- | --- |
| ① 交付了什么 | 文件 · 哈希 · 裸 LF 行数。**实际动了几个文件要如实说** —— 计划外那个往往才是关键。 |
| ② 怎么验证的 | 跑了什么、看到什么。**贴命令与输出的尾巴**，不要只写结论。 |
| ③ 哪里最不放心 | 自己拿不准的地方，**含"这条我没法自证"**。这一节写空，本身就可疑。 |
| ④ 需要裁定的 | 一条一条列。裁定回来之前**不许自己拍**。 |

## 6 纠正清单：改单不重发

任务单发出去之后要改，**不重发整单**，只发一份**纠正清单**：没动的照旧，只写改动。

理由：重发整单之后，两边得逐字对一遍哪里不一样 —— 而"哪里不一样"正是最容易看漏的地方。纠正清单**永远是增量**，看漏的机会只剩它自己那几行。

纠正清单收尾固定要三样：**改完的文件哈希 · 行数 · 验收命令的尾巴**。

**规划者自己受它管。** 清单写错了（漏了一处、或指了一条并不存在的"下一条"），要**明说是自己错**，别让执行者去猜是不是自己漏读 —— 那会白白烧掉一轮。
