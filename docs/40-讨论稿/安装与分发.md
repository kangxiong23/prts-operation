# 安装与分发（讨论稿）

> 状态：讨论中

## 这份稿子在争什么

别人（或者你换了台机器）要装上这套东西，需要几步、卡在哪一步。

相关：[总体架构与技术栈.md](../90-归档/总体架构与技术栈.md)（已结案归档）、[DSH平台事实.md](../30-专题/DSH平台事实.md)。

## 一、要装的是三样东西，难度完全不同

| 部分 | 第三方怎么装 | 难度 |
| --- | --- | --- |
| DSH bundle（捆绑包：预设 + MCP 行 + skill 配置） | 一条 `dsh plugin` 命令 | 低 |
| Python 引擎 | Python 3.12 + 视觉依赖 + `adb`（platform-tools） | **高，真正的劝退点** |
| 资产（特征库 / 地形 / 游戏数据库） | 随仓库分发，或首次运行生成 | 待定 |

讨论"装机便利性"时容易只盯着第一样，但**第三方的实际卡点在第二样**——这台机器上 `adb` 现在就**没装**。

## 二、DSH 那一侧：可以做到一条命令

`installBundle` 接受四种安装 spec（来源：`dsh-plugin-manager/lib/types/install-spec.d.ts`）：

| 形式 | 说明 |
| --- | --- |
| `registry` | npm 包名，可带版本范围 |
| `path` | **只接受绝对路径**；相对路径被拒（理由：相对 profile 解析会指到 profile 内部） |
| `tarball` | 压缩包 URL |
| `git` | git 地址，安装前用 `git ls-remote` 探测可达性 |

`dsh plugin` 命令与服务**共用同一套包管理操作**。所以发布到 npm 之后，别人的安装就是：

```powershell
dsh plugin --profile web add @you/dsh-ark-ai-op
```

**和你现在装插件的方式一模一样。**

附带三条便利：

- 注册表顺序是"指定的 → 配置的 → `fallbackRegistries`"，而 `fallbackRegistries` 默认就是 `https://registry.npmmirror.com/`。国内用户**自动回落镜像源**，不用额外配置。
- **用 CLI 比用工具省事**：CLI 继承终端与认证环境，且不受 `idleTimeoutMs` 这个无输出上界约束；服务侧则用清理后的环境、捕获输出，还要过审批。
- git 与 tarball 形式也能装，不必非得发 npm。

### 三条"零摩擦"红利，都来自实现本身

1. **没有依赖 → 永远不会卡在构建脚本审批上。** pnpm 11 会拦下依赖的构建脚本，让安装失败并在 `pendingBuilds` 里报一串包名，等人批准。我们的 bundle 是纯配置、零依赖，这条根本不触发。
2. **没有 DSH peer 依赖 → 永远不会卡在版本兼容检查上。** 点名包的安装会在 pnpm 运行**之前**检查声明的 peer，不兼容就直接失败。我们什么都不声明，检查必然通过。
3. **不发 npm 也能装**：把 bundle 源目录放在仓库里，别人 `add` 它的绝对路径即可。

## 三、真正的负担是引擎

引擎要 Python 3.12、numpy / OpenCV，以及 `adb`（platform-tools）。这部分无论架构怎么设计都要装，而且它才是会劝退人的地方。

三种分发形态：

| 形态 | 好处 | 代价 |
| --- | --- | --- |
| (a) 发 Python 包，用户自己 `pip install` | 最省事，改动最小 | 用户要会配 Python 环境 |
| (b) 打成单文件可执行，随 Release 发 | 用户不用碰 Python | 构建与体积是新的维护面；OpenCV 打进去不小 |
| (c) 暂不考虑分发，先自己用 | **零成本** | 别人装不上 |

**建议：(c) 现在，(b) 以后。**

理由是：**现在还不知道引擎里到底有多少依赖、有多大**。在核心闭环跑通之前为"别人怎么装"做设计，是在猜。等闭环跑通，依赖清单和体积都是已知数，那时候选 (a) 还是 (b) 是十分钟的决定。

## 四、两条限制要记住

1. **管理器不能编辑 `agent` 预设组合。** 官方文档原文：管理器不能关闭自身所需的管理组件、修改其他 profile 或**编辑 `agent` 预设组合**；Web 插件页里**预设条目保持只读**。
   - 对我们的方案，这其实是**好事**：预设跟着 bundle 自带的补丁走，装一次就位。
   - 但反过来也意味着：**装完之后不能在界面里改预设内容**，要改就得改 bundle 源目录再重装。这与第五节"把 bundle 当可重建的派生物"是同一条纪律。
   - **这一条建议在真正安装时实测确认一次。**
2. **改动影响该 profile 的全部会话。** 安装 bundle 不是"只影响这个项目"。

另有一条上机注意：替换已有包后需要**重启进程**才能加载新的 JavaScript 模块版本；纯配置变更在启用 HMR 时立即生效。Desktop 版的包管理由 Desktop shell 负责，路径不同。
