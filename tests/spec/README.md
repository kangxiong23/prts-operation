# 规划者的检查（`tests/spec/`）

**这个目录是规划者的，不是执行者的。** 谁写哪个目录、这批检查为什么不能当任务
清单交出去 —— 规矩在[决策记录/全局](../../docs/20-决策记录/全局.md) 的
**D-全局-17**（两个目录不互相 import）与 **D-全局-22**（这套检查只归规划者用；
`pytest` 默认不收这里）。**那份是权威，这里不重述**，只写这个目录自己的事：
里面有什么、怎么跑、写一条检查要守什么。

## 里面有三种东西

| 种类 | 文件名长什么样 | 进不进 `pytest` | 回答什么 |
| --- | --- | --- | --- |
| **基准集回归** | `<层>_spec.py` + 外壳 `test_<层>_spec.py` | **进** | "规格说的那些话成立吗" |
| **第二张网** | `<层>_extra_spec.py`（**故意没有外壳**） | 不进 | "它是不是**只**对那唯一一批样本成立" |
| **自检探针** | `check_the_checks.py` | 不进 | "上面那些检查是不是**永远绿**" |

第二张网**故意不带 `test_*.py` 外壳**：外壳是"一列要做的事"的形状，而它的用处
恰恰是**不被当成一列要做的事**。少一个外壳不是图省事，那条界线本身就是它的用处。

**不是每条检查都有探针。** 探针要有一个"把公开面换成坏的那一版"的动作；有些检查
（例如"35 帧都读对"）的反例要伪造一整批帧，代价大于收益。**探针优先盖"断言的是
形状、而不是某个值"的那些** —— 形状类断言最容易写成永远绿。

**现状要如实记一笔**：N 族（[备战席点名](../../docs/10-规格/视觉层/备战席点名.md) 那一套）
**一条探针都没有**（**条数不在这里写死**：以那一份文件末尾那张 `CHECKS` 表为准 ——
写死了，下次加一条它又过期）。按上面那条它排在后面（它们多半断言的是**值**：真值逐位 ·
阈值的两侧 · 文档与常量逐个数对齐），但"一条都没有"是**欠账**，不是判断。
**其中最该先补的是 N17**（单条那条路的代价不随库长）：它是那一族里唯一
**行为测试替代不了**的一条 —— 扫完全库再挑出那一条，答案一模一样，只有调用次数看得见。
所以它自己写歪了也没人看得见，探针（把单条换成全扫，看它会不会红）的收益最大。
顺带分清一件事：N13 里那两条"检查自己写歪了"的自检（行序对齐 · 抓到的个数对齐）
**不等于探针** —— 探针要动的是**被测的那一侧**。

## 怎么跑

```powershell
$env:PYTHONPATH="src"
.venv\Scripts\python.exe tests\spec\<层>_spec.py          # 一层，直接跑，不需要 pytest
.venv\Scripts\python.exe tests\spec\<层>_extra_spec.py    # 那一层的第二张网
.venv\Scripts\python.exe tests\spec\check_the_checks.py   # 证明那些检查会红
.venv\Scripts\python.exe -m pytest tests\spec -q          # 有外壳的那些（规划者自己跑）
```

每个套件都是 `main()` + 一张 `CHECKS` 表：**绿行给证据、红行给出处**，退出码非零
就是有红的。外壳只是把那张表逐条变成 pytest 用例。

## 写一条检查的三条纪律

1. **只用公开面。** 只 import 各层**对外承诺**的名字。碰 `_` 开头的内部名，检查就
   绑死在实现上了 —— 内部名一改检查就红，而规格一个字没动，那它就不是验收。
2. **每条都带规格出处。** 没有出处的是**发明规范**；出处对不上的是**发现了规格洞**。
   两种都要在报告里看得出来。
3. **证据行里的数字要从数据来，不许手抄。** 手抄的数字会**静默过期**：代码没改、
   规格没改，只有那句证据在说假话。**已经出过三次**（都在 `cost_spec.py`）：
   "1 位 8 帧、2 位 23 帧"（真值 9 / 22）、"规格钉住的 5 个数"（真值 6）、
   "8 个矩形"（真值 `len(DOC_RECTS)`）。写成 `len(...)` 或就地数一遍。

**分工不是形式**：执行者写的测试**和它自己的实现共享同一套心智模型** —— 它测的是
它想到的那些面，想不到的那一面正好是漏洞所在（实例：`Exact` 的值域，48 条单元测试
全绿而硬伤照样在）。所以这个目录的检查要**从规格出发写**，不是从实现出发写。

## 为什么不按种类再开子目录

**不开。** 开一层的判据是"**同一性质的东西攒到 3 个文件**"，不是"感觉该分了" ——
一个文件开一个目录就是搭空架子，还会让人以为"新目录 = 新规矩"。现在三种东西各
只有一两个文件，而它们的区别**已经写在上面那张表里**；表比目录便宜。

`tests/spec/` 本身已经是按**作者与性质**分出来的那一层（`tests/unit/` 是执行者的、
`tests/contract/` 是机器强制的边界、`tests/帧样本/` 是夹具），再套一层只会多一个
要记住的名字。**跨层一致性**那一类检查（"两层的规定互相不打架"）以后会出现，
它不属于任何单层 —— 等它攒到 3 个文件，那才是开 `tests/spec/跨层/` 的时候。
