## 技力有**数字读数**，但它属于"选中干员"那一套 UI（用户确认）

干员被**选中**时，场上出现一个 **⚡ + `当前/上限`** 的小读数（这一例是 `16/26`）。**它不是常驻的** —— 必须选中（= 点开面板那一次动作）才出现，所以**不是"不用点"的免费真值**。

- **它不是弹药**：那一位是极境，技能 `支援号令·γ型`，标签 `自动回复 · 手动触发 · 8秒`，不是弹药技；
- 所以它是**技力**。推论（待验）：**充能中显示这个数字，满了它被黄菱形取代** —— 规格里「菱形 ⟺ 手动触发 且 技力满」那条正对得上；
- **线上仍然只读条**（用户裁定）：读数字是文字识别，比读条贵，**不做线上通道**；
- **但它是技力唯一的精确真值来源**（面板给不了技力），而且**跟面板同一次选中一起出现** —— 所以真值帧里它白拿；
- **规格里没有这一条**（`场上我方干员.md` §1 只列了 蓝条 / 绿条 / 橙条 / 橙条+竖线 / 黄菱形 / 层数指示物）→ **规格缺口**。

**真值帧一次选中拿到三样**：面板的 `生命 当前/上限`（血量真值）+ 那个 `N/M`（技力真值）+ 被选中干员的条（露在面板外，给链读）。

## 面板给出了什么、没给出什么（实测）

**给出**：干员名 · 模组 · 等级 · 攻击 / 防御 / 法抗 / 阻挡 · 攻击范围（格子图）· **生命（当前 / 上限）** · 技能页：技能名 + **标签**（`自动回复` / `手动触发` / `40秒`）+ 描述 · 三个页签 `技能 / 特性 / 天赋`。

**没给出（关键）**：**当前技力 / 充能进度**。技能页只有名字、标签与描述，**没有任何 SP 数字或 SP 条**。

→ 所以：**血量比例的权威真值有着落；技力比例没有**。这条要么另找一个读数处（待定，问用户），要么只能人工读区间。

**顺带一条有用的**：面板的技能页直接写着 **`手动触发`** 这个标签 —— 而那正是「可释放菱形」出现条件的一半（规格：只有**手动触发**且技力满才显示菱形）。所以这一批里**菱形出现与否**可以拿面板的标签当已知量，不必等数据库。

## 相机机制（用户确认）—— 它解决了"哪个条是被选中的那个"

**点场上一个干员**开详情面板时，**被点中的那个干员会被挪到屏幕较中心的位置，场景跟着一起挪**。
**点备战席**则不同：整个场景朝**固定的右上方**挪，与被点的卡在哪无关。

**两个后果：**

1. **面板帧是自足的**：真值（面板的 `生命 当前/上限`）与**那根被读的条**在同一帧里，
   而且那根条在**屏幕较中心处** —— 面板只占左边约三分之一，所以两者不打架。
   **不用采"配对"**，一帧就够。
2. **被选中的那根条 = 离屏幕中心最近的那根**。这一条是**机制**，不是真值，可以交给执行者
   （它要靠这条去裁对那一根）。

**顺带**：备战席那条"场景朝右上固定挪"以后投影 / 地形那边要用（它意味着点备战席会整体平移视图）。
