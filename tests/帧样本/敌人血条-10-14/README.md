# 敌人血条：run-06 那 6 张原生帧的验收块

这一批是 **10-14 用户补进来的 6 张原生真帧**（`screenshots/run-06/`）上裁下来的验收块：
每一块 **640×640**、**一个像素都不缩**、带原点；验收时**贴回画布再喂链** —— ROI 的取法
仍然真的在被测。**真值在 `取材.json` 的 `truth` 一栏**；`判据读数.json` 是链读出来的，
它**不判断够不够**（那是规划者的事）。

**单 5 加了第 8 块 `不在_boss_红门.png`**（boss 那一帧右上角那道**红门**）：红族最像条的
两块都在它里面 —— `boss.png` **整帧**就是红族的反例。

## 这一版改了哪几条判据（单 5）

1. **红族只有 boss**（用户裁定）：第二支参考色 `ENEMY_FILL_RED = (197,41,40)`，
   外加**红族的宽度门** `RED_MIN_COLUMNS = 60` —— boss 是**宽**的（实测 115 列），
   红门那两块只有 18 / 23 列。**两族各筛一遍、不并掩膜**（并起来会把本来分开的块连成
   一块，实测 `敌条互叠2` 会因此丢掉 7 根条 —— 那是改量法，不是加一族颜色）。
2. **形状门**（两族共用）：**矩形**（**每一列都亮着**的那几行要装下整块
   >= `RECT_FILL_MIN = 0.95` 的像素）+ **内部均匀**（那 8 行取**逐行**中位色，
   通道极差 <= `RECT_ROW_SPREAD_MAX = 20`）。
3. **两道宽度门**：`MIN_CANDIDATE_COLUMNS = 7`（候选的门 —— 现有最短真条是 7 列）与
   `MIN_FILL_COLUMNS = 12`（够不够量比例的门）。**7…11 列那一档照样报「在」、
   比例落未采样** —— 「在门以下」不是通往「不在」的一条路。
4. **「1.0 照报」**（用户裁定 3）：代码里**从来没有**「报 1.0 ⇒ 落未采样」那条，
   这一版也没加。满血条不该存在，所以真读出 1.0 只有两种可能：那不是一条，或者
   整长算错了 —— 两种都要**当缺陷线索去追根因**（见下面第 3 条缺口）。

## 缺口与代价（没覆盖到的 / 已知脆弱点）

1. **「认不出」真帧零**：三态里中间那一档这一批一次都没出现过（只有合成用例钉）。
2. **一根敌条的连续时间序列零**（要录像）—— 所以「同一根条在两帧之间的填充变化」没被验过。
3. **boss 那根红条的比例是错的 1.0**（**这一批最硬的一条缺陷线索**）：画面里它的填充
   115 列、右边还有一段暗轨（x1677…1716，(45,44,42)），真实比例约 0.74。
   根因量出来了：**那根条有 10 行**（不是 8），而空轨那一步按 8 行取上下底，
   于是「带内 vs 带下」的差被条自己多出来的两行拉平到 **7…11 < TRACK_CONTRAST=12** ——
   轨没被认出来，整长 = 填充段，比例报 1.0。**没有拿未采样去盖**（用户裁定 3）。
4. **红族的宽度门是 shot26 那块红块唯一的挡板**（见上）。
5. **`全满血` 那块橙黄警戒线离假阳性只差 1 行**：它 13 行（线 12）、进得了色的门
   （整块中位 (231,112,61)、链那套取法 (232,116,59)、逐通道最大差 13 / 14）；
   这一版它还被**形状门**兜住（条身比 112/172 = 0.65 < 0.95）。
6. **`raw_b` 里那两块红色平片（26 / 58 列）被宽度门挡在外面**：它们可能是条、也可能是
   贴图 —— 这一版量不出是哪一种（26 列那块中位色 (187,41,45) 离红族只有 10）。
7. **「分不开」的判据是本链新立的**（同一条带里相邻两根 + 整长交叠/相接 或 中间有混色列）：
   只被互叠那两帧验过，而且混色那一支是布尔的，没有余量。
8. **整长档次只有 24 / 42 / 115 / 122 / 154**：不是分布，是几个点。
9. **红族的颜色半径沿用了橙族那支 34**：红族只有**一个**真值样本（boss 那根），
   量不出更窄的线；「窄」是靠参考色 + 宽度门 + 形状门做的。
10. **`RAW` 那一支**：这一批只有 PNG 裁剪，没有设备原始帧 —— `frame_from_raw`
    那一头由别的批次看。
