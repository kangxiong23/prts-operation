# 先粗后细：能不能同时买到「尺子铺得更宽」与「更快」

> 这一份是**测量**，不是判据。产品代码与判据参数一个字节没动。

## 问的什么

点名那条链内层是「一块身份区 × 一条库 × 一档尺度 → 一张相关图」（`cv2.resize` +
`cv2.matchTemplate(TM_CCOEFF_NORMED)`）。尺度档数 × 库条数 × 卡位数 就是那一笔账；
而现在尺度只扫 1.05–1.15 这 11 档，**下界那一刀截掉了峰**（组2 三位峰在 1.01 / 1.02 / 1.02）。

用户点的思路：**先用少量像素粗挑最好的倍率，再精算**（起点 225 = 15x15 个像素）。
粗可以在三个地方做 —— **档（尺度）· 位置 · 像素**。

**硬约束**：报出来的分必须仍然来自**全分辨率那一次精算**；粗探只用来挑档 / 挑位置。
所以这一份量的不是「换一条链」，而是「换一条**找**那条链该在哪里算的搜索路径」。

## 怎么重建

`~
.venv\Scripts\python.exe scripts\bench_roster_coarse.py
`~

跑完覆盖本目录的 `读数.json`。第一次跑要二十几分钟建**取值域曲线**（26 档 0.95…1.20，
4030 对），缓存落在 gitignored 的 `data/probe/coarse_cache.json`，之后秒开
（加 `--fresh` 强制重算）。

**它不是另写的一份匹配**：曲线就是那条链内层那一步逐档重跑，它在今天那 11 档上的最大值
与 `roster_scores` 逐位核对过（`crosscheck.all_equal`，**4030 对 · 不等 0**），
对不上就报错。

## 五张表

### 1 / 2 粗探准不准 · 报出的分逐位同不同（4030 对）

「选档准」= 粗探挑中的档 == 全分辨率峰所在的档；「峰在窗内」= 真峰同时落在精算的档窗
与位置窗里；「逐位同」= 这样报出来的分与那条链**逐位相等**。

| 走法 | 选档准 | 峰在窗内 | 逐位同 | 最大差 |
| --- | --- | --- | --- | --- |
| 全分辨率全档（今天） | 4030 | 4030 | **4030** | 0 |
| 只粗档 步0.05·精算±2档 | 3029 | 3897 | 3897 | 0 |
| 只粗档 步0.05·精算±3档 | 3029 | 3988 | 3988 | 0 |
| 只粗像素 15x15·精算挑中那档 | 1899 | 1899 | **1899** | 0 |
| 只粗像素 15x15·精算±1档 | 1899 | 2259 | 2259 | 0 |
| 粗像素15x15 + 粗档0.05±2 | 2595 | 3051 | 3051 | 0 |
| 只粗位置 步4·精算±32px | 2214 | 3915 | **1579** | 3.9e-6 |
| 粗像素15x15 + 粗位置±32px | 1899 | 1720 | 742 | 3.4e-6 |
| 粗档0.05±2 + 粗位置±32px | 2808 | 3442 | 1461 | 3.3e-6 |
| 三处一起粗：15x15 + 0.05±2 + ±16px | 2595 | 2645 | 1061 | 5.0e-6 |
| 宽区间 + 全分辨率全档 | 4030 | 4030 | **4030** | 0 |
| 宽区间 + 三处一起粗 | 1834 | 2260 | 862 | 3.2e-6 |

**两件事分开看**（`max_abs_delta_when_peak_inside` 就是凭据）：

- **档粗 / 像素粗丢的分，一分为二都是「挑错了档」** —— 真峰在窗内时，报出来的分
  与那条链**逐位相同**（最大差 **0**）。所以「粗探挑档 + 全分辨率精算」只要**档挑对了**，
  报出的分就是线上那个分。
- **位置粗那一刀另加一笔**：把立绘裁到窗口里再 `matchTemplate`，值与整张图上同位置
  **不再逐位相同**（OpenCV 的相关在缩过的图上重排补零，舍入跟着图变）。实测差
  **3e-7 … 5e-6** —— 都在落盘那个 6 位小数附近，所以**读数表那一层多半看不出来，
  但「逐位」过不去**。而且它一次调用也没省（见下表）。

### 3 代价（真跑 8 张卡 / 88 条库条目，各跑 3 次取中位）

| 走法 | `matchTemplate` 真次数 | 墙钟 |
| --- | --- | --- |
| 全分辨率全档（今天） | 1936 | 28.167 s |
| 只粗档 步0.05·精算±2档 | 560 | 7.647 s |
| 只粗档 步0.05·精算±3档 | 664 | 9.026 s |
| 只粗位置 步4·精算±32px | 1936 | 16.532 s |
| 只粗像素 15x15·精算挑中那档 | 1056 | **1.481 s** |
| 只粗像素 15x15·精算±1档 | 1176 | 3.144 s |
| 粗像素15x15 + 粗档0.05±2 | 528 | 3.819 s |
| 粗像素15x15 + 粗位置±32px | 1056 | **0.595 s** |
| 三处一起粗：15x15 + 0.05±2 + ±16px | 528 | 0.739 s |
| **宽区间** + 全分辨率全档 | 4576 | 59.550 s |
| 宽区间 + 三处一起粗 | 840 | **0.825 s** |

- **每多扫一档多花多少**：今天那 11 档 = 1936 次 / 28.167 s → **每档 176 次 · 2.56 s**；
  宽区间 26 档 = 4576 次 / 59.550 s → **每档 176 次 · 2.29 s**。**次数是尺子定的，与卡数成正比。**
- **把区间铺宽 2.4 倍 = 墙钟 2.1 倍**（28.2 → 59.6 s）；三处一起粗在宽区间上只要 **0.82 s**
  —— 但它报出的分**只有 862/4030 对逐位相同**。
- **位置那一轴单独粗省不下**：`cv2.matchTemplate` 总是算整张相关图，把立绘裁小才省钱，
  而一裁就动了报出的分（上一节）。所以它只有与「像素」合用才省 —— 代价也在那里。

- **新出现的错名字 0 张**；宽区间下错名字**一共 0 张**（真值 54 格 + 立绘两组那 20 张按
  「读到另一组就是错」的结构判）。
- 精确 → 未知 **0 张**；其余 140 张未知全部是「库里没有这个人」（分数 ~0.47）。

### 5 最少要多少个像素

粗探只用 p×p 个像素挑档，然后**全分辨率精算**（档窗 ±1 / ±2 档）。「逐位同」= 报出的分
与那条链逐位相等。

| p×p | 像素数 | 选档准 | 逐位同（±1 档） | 逐位同（±2 档） |
| --- | --- | --- | --- | --- |
| 8x8 | 64 | 1261 | 1555 | 2372 |
| 10x10 | 100 | 1678 | 2567 | 2720 |
| 15x15 | **225** | 1899 | 2259 | 2468 |
| 20x20 | 400 | 1938 | 2220 | 3217 |
| 25x25 | 625 | 2518 | 2877 | 3221 |
| 30x30 | 900 | 1984 | 2388 | 2615 |
| 40x40 | 1600 | 2052 | 3437 | 3697 |
| 50x50 | 2500 | 2154 | 3450 | 3762 |
| 75x75 | 5625 | 2997 | 3683 | 3907 |
| 100x100 | 10000 | **4030** | **4030** | **4030** |

**结论：这条曲线没有拐点。** 粗探像素从 64 加到 5625（**56% 的像素**），选档准从
31% 爬到 74%，逐位同最好也只到 **91%**；只有 p=100（**一点不缩**）才是 100%。
换言之：**「先粗后细」在像素这一层买得到速度（15x15 时快 19 倍），买不到「报出的分不变」。**

# 多层细化（第二单）：一层比一层细，把一帧的墙钟压下来

> 这一份还是**测量**，不是判据。产品代码与判据参数一个字节没动。

## 这一单问什么

上一单量出：粗在**像素**那一层买得到速度（15×15 快 19 倍），买不到「报出的分逐位不变」。
这一单把「报出的分逐位不变」这条硬约束**撤掉**（规划者裁定：产品只守**零假事实 · 召回 · 速度**），
改成设计一条**多层**搜索 —— 图先缩小再放大回来 · 档距先粗后细 · 位置先粗后细 —— 并量它
（① 选档一致率 ② 判定账 ③ 墙钟，对着「一帧至少降 10 倍」这条门槛报「到没到」）。

开销规律（上一单实测，这一单设计就照它）：

```
一次调用的代价 ~ 搜索位置数 x 模板像素数        （缩图是平方级的便宜）
```

所以每一层要做的事只有一件：**把下一层该看的地方缩小**。报出的分**只**来自最后一层
（`pixels = 100`，全分辨率那一次 `matchTemplate`），前面几层一个分都不许报。


## 1) 资产是什么（裁定 1 / 5 / 6 / 7 / 8）

资产里存的是**对应关系本身**，不是那两个数：

    立绘坐标 = (offset_x, offset_y) + 档 × 卡内坐标

`SlotGeometry.from_position(档, 位置, 卡内框)` 从"某一档上、某块卡内框的模板左上角
落在立绘的哪一点"反推它；`art_top_left(卡内框)` 从它算出**任意一块取区**的落点。
所以**方框上算出来的那份对应关系，搬到红罩那个圆盘上照样成立**（两个框的卡内原点不同，
换一下 `卡内框` 就行）—— 这正是它能跨取区复用的原因。**里面没有身份**：谁能被读出来，
每一帧都在这份对应关系上**重新**逐条目算。

键 = **(库指纹, 卡距, 画布尺寸) ＋ 卡位下标**。库指纹是**名字 ＋ 立绘块的每一个字节**的
blake2b（同一套名字换一套皮肤必须算**另一把库**）。键一变就**清空整本账**并记一次重建；
这一局 `rebuilds = 0`。

第一次是**每个卡位各自的**第一次：开局有卡位是空的，那一格没有几何；等它回来时才跑满。
整段 60 帧上：**首帧 19 次**（干净 12 · 红罩 7）。

## 乙10 红罩 `confidence` 的含义（裁定 9）
