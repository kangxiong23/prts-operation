# 帧样本 / 顶部两个数

顶部条带上**并排那两个数**（已击杀数 / 敌人总数 与 蓝门血量）的**测试夹具**，同时是**第二批基准集**。原生分辨率下的一块裁剪，一帧一文件。

## 这是什么，从哪来

- **不是新抓的帧**：31 张从 `data/precheck/live/shot01..37.png` 里裁出来（vivo V2338A，真机取像，**2800×1260**），另 4 张从 `data/probe/{m2_view,m2x_pview,raw_a,raw_b}.png` 里裁。那批原帧是 gitignored 的临时产物，所以把**要用的那块**搬进版本库，让验收能反复跑；
- **只裁了顶部那一条**，没有搬整帧——35 张全帧要 470 MB，全裁出来只有 **794 KB**；
- **裁的是原生像素，一个像素都没缩**：`shot01.png` 里的 `(5, 8)` 就是原生画布上的 `(1200, 33)`。

## 怎么用：把裁剪还原成画布

`index.json` 每条都记了 `origin`（裁剪在原生画布上的左上角）与 `size`，所以能把裁剪**贴回**一张 2800×1260 的画布，再喂给读数链——**这样 ROI 的取法仍然是真的在被测**，而不是把 ROI 预先替它做好。

裁剪窗口是 `(1195, 25) – (1649, 79)`（455 × 55），**同时装得下** `enemy_count` 与 `life_digits`（[顶部两个数](../../../docs/10-规格/视觉层/顶部两个数.md) §两个窗口）。

## 里面有什么

| 文件 | 内容 |
| --- | --- |
| `shotNN.png` | 31 张顶部条带裁剪（`shot01`–`shot09`、`shot16`–`shot37`） |
| `m2_view.png` 等 4 张 | 另一局的静帧裁剪（那一局生命是 `3`、敌数是两位数） |
| `index.json` | 每张的原点、尺寸、源帧路径与**源帧 sha256**（钉住"这份裁剪出自哪一帧"） |

`shot10`–`shot15`、`shot38`–`shot40` **不在这里**——那几帧是转场画面，不是战斗界面。

## 它是第二批基准集

按[基准集](../../../docs/10-规格/采集与验收/基准集.md) 的格式，这个目录是**第 1 版**（`index.json` 里的 `version`）。加载它走 `ark.offline.bench.batch.load_batch`，喂进识别链走 `ark.offline.bench.feed.replay_frames`——**全程不用真机**。

**它也没有 `facts`**：抓这批帧的时候没记前提头，所以它和费用那批一样，**不能用来验设备事实那条路**。顶部这两个数的读数不依赖方向，不影响它的用途。

`index.json` 里那个 `box` 是这一批自己的额外字段（裁剪窗口的公共范围），**不是格式的一部分**——格式认的帧名是 `file` 去掉扩展名。

**这一批的 35 帧全是静帧通道**（`screencap`）：生命那个粉是平的 `(255,120,120)`，35/35 一致。**没有混进录像帧**——录像通道会把颜色整体抬几格（[D-全局-20](../../../docs/20-决策记录/全局.md)），那会让"同一个粉"变成两种。
