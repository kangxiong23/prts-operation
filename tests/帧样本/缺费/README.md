## 为什么是**一对**，不是随便两张

**1–5 号卡两帧状态没变，6–10 号才是效应组**（用户裁定 6 的零假设对照）。实测：

| 组 | 身份区不同像素 | 身份区 mean\|D\| | 整卡不同像素 | 整卡 mean\|D\| |
| --- | --- | --- | --- | --- |
| 1–5 号（状态没变） | **0** | **0.000** | 8–360 | 0.000–0.021 |
| 6–10 号（缺费 → 够费） | 9998–10000 | **76.8–103.2** | 34908–42248 | 48.8–81.8 |

**噪声地板是 0**（不是"很小"）：1–5 号的身份区逐位相同。条带里卡以外那一片有 4.63% 的
像素不同、mean\|D\| 2.492 —— 第二帧场上多了一个敌人，它**不在这条带里**（在 y ≈ 168）。
`灰罩卡_备战席.png` 与 `干净卡对照_备战席.png` 两帧只差这一个变量：**当前费用 20 → 28**。

## 标签是**代数**的，不是目视的

`index.json` 的 `labels` 那一段（用户裁定 7）：

| 字段 | 内容 |
| --- | --- |
| `current_cost` | 灰罩帧 **20**、对照帧 **28**（`cost.read_cost_digits`，链的置信度都是 **0.9986**） |
| `card_cost_right_to_left` | **25 · 23 · 22 · 21 · 21 · 19 · 16 · 13 · 12 · 11**（下标 0 = 最右那张） |
| `card_cost_chain_read_right_to_left` | 链真正读出来的那一份（**idx5 / idx8 是 `null`**） |
| `card_cost_eyeballed` | `{"5": 19, "8": 12}` —— 链在两帧上都读不出的那两位，按原图**目视**读 |
| `insufficient_right_to_left` | `[true ×5, false ×5]` —— `卡费 > 当前费`（灰罩帧） |

**idx5 / idx8 的读不出是费用链自己的欠账**，两帧一样（同一位干员上了红罩就读得出、
没上就读不出是另一条链的事；这里两帧都是"读不出"）。那两位都不是缺费，所以它们怎么填
**都不改零假设组与效应组的分组** —— `差图.json` 里逐格记着。

## 差图说了什么（`差图.json`）

**灰罩是「整片乘 0.5」**（用户裁定 3 的三个模型排到只剩这一个）：

- **①色度被乘小：是。** 五对的身份区逐像素 `G/C` 中位 **0.5024 / 0.5021 / 0.5021 / 0.5022 / 0.5025**；
- **②色度被整片抹平：否。** 抹平的话灰罩卡该没有色度，实测它还剩 `chr>20` 的像素
  **2786 / 675 / 23 / 696 / 1094** 个；
- **③连亮度一起变：是，而且就是同一个标量。** 亮度比 **0.5071 / 0.5060 / 0.5055 / 0.5058 / 0.5066**，与色度同一条。

⇒ **是「乘小了」，不是「抹平了」**：还原**一个算式**就够（乘回去），**不需要库**，
那条"先认出是谁、再回填颜色"的两趟流程**没有它的位置**。

**还原到什么程度**：五对的身份区与对照帧逐像素平均差 **89.589 → 2.042**（>8 的像素
29993 → 2210）。剩下那 2 是罩子里的加法项（`G = 0.5·C + K`），它随位置变、
但**与是哪张卡无关**（五张卡的 K 均值 1.001 / 1.044 / 1.076 / 1.052 / 1.045）。

## 怎么用

清单格式照[基准集](../../../docs/10-规格/采集与验收/基准集.md)（`version` / `canvas` /
`device` / `box` / `crops`），加载走 `ark.offline.bench.batch.load_batch` ——
**贴回画布之后再喂识别链**，这样 ROI 的取法仍然是真的在被测。

**这一批没有 "取材 / 验收" 的拆分**：两张是**一对**，缺一张这条差图就不成立，
所以两张都在这儿、两张的标签都在这儿。

**它没有 `facts`**：抓帧的时候没记前提头，所以它不能用来验设备事实那条路。
