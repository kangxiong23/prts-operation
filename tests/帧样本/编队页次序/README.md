# 帧样本 / 编队页次序

**合成**的一帧编队页 ＋ 一份**合成**响应 —— 它证的是**次序**，不是任何真画面上的读数。

（A2 做3a 交的夹具；那条跨层检查写在 `tests/spec/` 一侧。）

## 这是什么，从哪来

| 文件 | 是什么 |
| --- | --- |
| `合成编队页.png` | 2800×1260，**不是截图**：第 i 张卡（cut_order）那块立绘**整块**填一个常数颜色，块外全黑 |
| `合成响应.json` | **不是任何一次接口调用**：10 个词框按竖排拼图的格子摆，一格一个 |

具体填什么颜色、哪一格配哪个名字，都在 `index.json` 的 `paint.per_slot` 与 `names_by_slot`。

## 怎么读它

- **立绘那一侧**：`cut_formation_arts(page, counts=[5, 5])[i]` 整块 = `paint.per_slot[i]`；
- **名字那一侧**：`read_names(..., grid=VERTICAL)` 的格 `i` 收到 `names_by_slot[i]`。

两边**各自**都能独立读出来，所以「第 i 个名字配的确实是第 i 张卡的立绘」这句话是可验的 ——
**配对**就是那条跨层检查要验的东西。

## 它证不了什么（重要）

它证的是**次序**：切卡的次序与那一读出的 slot 次序是**同一套**（上行在前、行内左到右）。
它**不是**任何真画面上的读数 —— 颜色是我们画的、名字是我们摆的。真帧那一次在秤里
（`scripts/bench_roster_names.py` 的 A2 那两段），它读 `screenshots/`，所以不进单测。

## 通道序

盘上是 PNG（编码器口径 BGR），内存里是 RGB —— 与仓里其余那份同一个惯例。

## 拍平的那件事

每一块立绘是**一个常数颜色**：它把"这块不是那块"这一条做到最容易读，而次序正是这里唯一
要验的东西。要看真实立绘的像素，用 `tests/帧样本/编队页名字竖排/` 那一份。
