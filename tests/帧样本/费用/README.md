# 帧样本 / 费用

费用读数链（T3）的**测试夹具**。原生分辨率下的**费用面板**裁剪，一格一文件。

## 这是什么，从哪来

- **不是新抓的帧**：从 `data/precheck/live/shot01..37.png`（vivo V2338A，真机取像，**2800×1260**）里裁出来的。那批原帧是 gitignored 的临时产物，所以把**要用的那块**搬进版本库，让验收能反复跑；
- **只裁了费用面板那一块**，没有搬整帧——31 张全帧要 140 MB，全裁出来只有 **695 KB**；
- **裁的是原生像素，一个像素都没缩**：`shot35.png` 里的 `(10, 10)` 就是原生画布上的 `(2590, 850)`。

## 怎么用：把裁剪还原成画布

`index.json` 每条都记了 `origin`（裁剪在原生画布上的左上角）与 `size`，所以能把裁剪**贴回**一张 2800×1260 的画布，再喂给读数链——**这样 ROI 的取法仍然是真的在被测**，而不是把 ROI 预先替它做好。

裁剪窗口是 `(2580, 840) – (2800, 975)`，**同时装得下** `cost_icon` / `cost_digits` / `cost_bar`。

## 里面有什么

| 文件 | 内容 |
| --- | --- |
| `shotNN.png` | 31 张费用面板裁剪（`shot01`–`shot09`、`shot16`–`shot37`） |
| `index.json` | 每张的原点、尺寸、源帧路径与**源帧 sha256**（钉住"这份裁剪出自哪一帧"） |
| `取材.json` | **字形模板只许从这些帧取材**（11 帧，值由规划者目视确认） |

`shot10`–`shot15`、`shot38`–`shot40` **不在这里**——那几帧是转场画面，不是战斗界面。

## 取材与验收是分开的两批

`取材.json` 里的 11 帧是**给执行者做字形模板用的**（相当于训练集）。剩下 20 帧**不告诉它值**，是验收用的（相当于测试集）——不然"自己写自己测"就没有独立性了。

验收的真值（31 帧全量）住在 `tests/spec/cost_spec.py`，**执行者不许读 `tests/spec/`**。

## 它同时是第一批基准集

按[基准集](../../../docs/10-规格/采集与验收/基准集.md) 的格式，这个目录是**第 1 版**（`index.json` 里的 `version`）。加载它走 `ark.offline.bench.batch.load_batch`，喂进识别链走 `ark.offline.bench.feed.replay_frames` —— **全程不用真机**。

**它没有 `facts`**：抓这批帧的时候没记前提头，所以**它不能用来验设备事实那条路**。费用读数不依赖方向，不影响它的用途。

`index.json` 里那个 `shot` 整数是这一批自己的额外字段（`cost_spec.py` 在用），**不是格式的一部分** —— 格式认的帧名是 `file` 去掉扩展名。
