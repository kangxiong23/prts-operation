# 帧样本 / 场上干员回归

**亮底那五帧**（橙条纹地板 / 青地板 / 花丛）—— 技力那一侧「亮底上整条判成填满」
那个现象的**回归样本**。

## 它是**回归批**，不是干净基线

这一批**见过**：技力那一侧现在的判据（`field.SKILL_FILL_TOL` 的「颜色像不像填充色」）
就是拿这五帧的现象改的。所以：

- 它**不是**独立真值批，**不能**当「没被动过的基线」；
- 它**没有真值** —— **`取材.json` 里一个真值字段都没有**（真值住在规划者那边）；
- 它**没有** `判据读数.json`：钉读数的是 `tests/unit/test_vision_field.py` 里那一段回归用例
  （`REGRESSION_READINGS`）—— 那才是「这五个数一字不许变」这句话的载体。

## 这五帧的读数钉在单元测试里，不在这儿

五个数写在 `tests/unit/test_vision_field.py` 的 `REGRESSION_READINGS` 里，逐帧跑一遍必须
对得上。**它们不是真值**，是这一版链的输出；规划者独立核过 `s02` / `s03`。

## 这是什么，从哪来

| 文件 | 内容 |
| --- | --- |
| `s0N.png` | 5 块 `300×420` 的原生像素裁剪（一个都不缩） |
| `index.json` | 每块的原点、尺寸、源帧路径与**源帧 sha256** |
| `取材.json` | 每块的**取区**、来源、以及**这一帧的底是什么**（就这些） |

源帧是 `data/probe/sp_series/s00.png` … `s04.png`（那一批是 gitignored 的临时产物，
所以把要用的那一块搬进版本库）。血条左上角五帧都是 `(1487, 709)` —— 建批时**当场自检**：
按它开的取区里必须真的有一根条，而且左缘必须落在取区里的 `(40, 320)`。

## 为什么一帧一个底

那五帧是**同一次取帧会话**里连拍的（间隔约 12 秒，见源目录的 `meta.txt`），
底换了三种：橙条纹地板（`s00` / `s04`）、花丛（`s01`）、青地板（`s02` / `s03`）。
轨道是**半透明**的，底一亮，旧判据（比亮度）就整条判成填满 —— 这三种底是**那个现象的
三个变体**，所以各留一帧。

## 怎么重跑

    .venv\Scripts\python.exe scripts\bench_field.py

它把**三**批一起建：基准集、真值批、回归批（回归批只落裁剪与清单，**不落读数文件**）。
同一条命令**跑两次**，那两份判据读数文件都逐字节一样。

## 这一层不判断「够不够」

这五帧的读数只是**冻在那儿防回退**；「够不够」是规划者的事。
