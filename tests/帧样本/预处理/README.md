# 帧样本 / 预处理

**A2c 那一单**（红罩反解之后的「灰」能不能靠像素变换救回来）的测试夹具 —— 一组
「同一张卡、一次罩着、一次干净」的**配对**，另附每张裁剪喂线上那条链的读数。

## 这是什么，从哪来

来自 `data/precheck/cd/`（**一局真机战斗里每 3 秒截一张、连截 60 张**，帧名
`cd01`…`cd60`）。那批全帧是 gitignored 的临时产物，所以把**要用的那几块**
搬进版本库，让读数能反复跑。

| 文件 | 内容 |
| --- | --- |
| `cdNN_K.png` | **一整张备战席卡**（204×214，原生像素、一个都不缩） |
| `index.json` | 每张的原点、尺寸、源帧路径与**源帧 sha256** |
| `取材.json` | **44 对配对表** + 每张裁剪喂线上那条链的读数 |
| `预处理.json` | `scripts/bench_redcap_preprocess.py` 落下的读数表（**17 行**并排 + **三条对照**） |
| `绝对线.json` | `scripts/bench_redcap_identity.py` 落下的读数表（**A3**：一条绝对线成不成立 —— **七条规格**并排 + 分布那一族 + 锐度那一份 + 四档敏感性） |

**裁剪口径与另两批（红罩 / 余量）不同**：那两批裁的是**整条横带**（2500×220），这一批
只裁**那一张卡**。理由是这一单只用得到卡片自己：44 对要用到 **32 个源帧**，整条横带一张
约 830 KB（32 张约 26 MB），只裁卡片一张 46–88 KB —— 39 张一共 **2.4 MB**。

**取区原点**：`index.json` 里每条裁剪的 `origin` = **这一帧像素读出来的卡心
（`squad_card_centres`）减 102**（卡宽 / 2）；纵向是契约层 `squad_card_rect` 的
`y = 1045`。**不是常量网格** —— 本批实测卡心与常量网格**最大差 1 px**（卡位 4/6/8/9 各
−1，卡位 0/1 为 0；本批没有卡位 10）。同一个卡位在这 39 张上是同一个数，配对两端的原点
也是同一个数（44/44），所以两块画面的像素是对齐的。

## 44 对是怎么数出来的

判据**不另立**：沿用 `tests/unit/test_vision_redcap.py` 的 `pair_ok` —— 两帧卡数相同 ·
**恰有一个卡位**的罩状态不同 · 其余每个卡位只差一次亮度（逐通道仿射，斜率 0.9…1.1、残差
rms ≤ 3）· 那个卡位自己差一次仿射（残差 rms ≤ 12）。

60 帧按「卡数 + 罩状态向量」分成 **13 个类**；类与类之间**恰差一个卡位**的只有 **9 组**
（共 **256 个「帧对 × 卡位」组合**）。把 `pair_ok` 逐组跑一遍，收下 **44 对**。

| 卡位 | 对 | 那一格是谁（按**干净那一端**读） |
| --- | --- | --- |
| 0 | 4 | 斩业星熊 |
| 1 | 2 | 维什戴尔 |
| 4 | 26 | **白面鸮 / 黍**（两个时段） |
| 6 | 7 | **歌蕾蒂娅 / 白面鸮**（两个时段） |
| 8 | 3 | 极境 |
| 9 | 2 | 新约能天使 |

**同一个卡位在不同时段可以是不同干员**（卡位 4、6 都是），所以真值一律取**干净那一端**
读出来的那个名字 —— 一对一个真值，不按卡位记。判据自己也把跨时段那种配挡住了。

**44 对不是 44 份独立画面**：39 张裁剪里只有 **32 张互不相同**（`cd47_4` `cd50_4`
`cd54_4` `cd56_4` `cd57_4` `cd59_4` `cd60_4` 七张逐字节相同、`cd29_6`/`cd31_6`
两张相同），44 对里只有 **29 个互不相同的画面组合**。

`预处理.json` 的 `redundancy` 那一栏有**两个去重键**，报数时必须说清用的是哪一个：

| 去重键 | 罩着端 | 干净端 |
| --- | --- | --- |
| **整块卡面**（`dedup_key`） | **19 块** | **13 块** |
| **身份区**（`dedup_key_identity_region`，那把尺子真正看到的那一块） | 19 块 | **8 块** |

按块算的过线数也跟着键走：整卡键下罩着端 **15/19**、干净端 12/13；身份区键下干净端
**7/8**（中位余量 0.348）。**「40/44」里有很大一份是重复时段的贡献** —— 按块算远
不是 40。（这几个数跟着余量线走：线 0.30 时它们是 9/19 · 9/13 · 5/8 · 31/44。）

**这些过线数不落盘**：由线决定的布尔值一律**读者按当下的线算** —— 文件里只有分数与
余量（`score` / `runner_up` / `margin`），线一挪就离线重算，不必把整批重跑。
本段写的是**读数**，不是文件里的栏；`绝对线.json` / `圆盘取区.json` 原来那两个
`passes_line` / `passes_both_rules` 已经**收掉**（它们那时还是按 0.30 算的）。
这里余下的「线 0.30 时它们是……」是**历史**，不是现状。

## 另一份读数：绝对线.json（A3）

`绝对线.json` 是 **A3**（把余量那条规则去掉、让一条绝对线够用）那一单的读数表，
由 `scripts/bench_redcap_identity.py` 落下来。与 `预处理.json` 不是一回事：

- `预处理.json` 比的是**预处理**（反解之后那块灰能不能靠像素变换救回来），17 行；
- `绝对线.json` 比的是**判据**：**七条规格**（掩码 552 · 不掩码 10000 ·
  环带回填 半径 45 · 取区原点 x−1 / x+1 · 锐度-磨参考图 σ=1 · 锐度-只磨不平移 σ=1），
  每条都报**罩着端与干净端**两组的**真值最低分**与**次高最高分**、它们各自的出处
  （哪一对、哪个库条目），以及
  **比值 = (1 − 真值最低分) / (1 − 次高最高分)**（**< 1 才叫分得开**）；
- 另带三块：`distribution`（不逐像素比的那一族，两种取法各一行）·
  `sharpness_share`（亚像素对齐收益与「只磨不平移」那个对照）·
  `sensitivity`（窗 / 强度 / 半径 / 原点 四档自变量）；
- **去重键**：`distinct_readings` 按**读数完全相同**（真值分 + 错解分）算 ——
  罩着端 **11 块**、干净端 **8 块**（与 像素匹配诊断 §5 对上）；画面键
  （整卡 19 / 13 · 身份区 19 / 8）另行并排报；
- **它不判「够 / 不够」** —— 那一格是规划者的。

## 真值从哪来

干净卡的身份**不是目视的**：把**它自己的身份区**（`roster.identity_region`，卡内
`(52, 76, 100, 100)`）喂**线上那条链**（`roster_scores`）读出来 —— 最高分过
`ROSTER_SOLID_MATCH_SCORE = 0.85`、而且余量拉开 `ROSTER_AMBIGUITY_MARGIN = 0.25`。
`取材.json` 的 `reads` 把 39 张的读数都记了下来。

**这条真值自己是有前提的**：它就是线上那条链的读数。同一时段里逐帧给出同一个名字，那是
它稳的证据；但它**证不到底** —— 链错它就跟着错。

## 库在哪

卡面库借 [`../点名/编队页.json`](../点名/编队页.json) 指的那一帧（与这批**不同源**，
那是常态）。这一批只放**裁剪与配对**，不另拷一份库。

## 它同时是一批基准集

按[基准集](../../../docs/10-规格/采集与验收/基准集.md) 的格式，`index.json` 是**第 1 版**。
加载它走 `ark.offline.bench.batch.load_batch` —— **全程不用真机**。

**它没有 `facts`**：抓这批帧的时候没记前提头。

## 目录里那个不属于这一串的文件

抓帧的目录里一共 61 个 PNG，其中 **60 个**是 `cdNN`；第 61 个叫 `_c0.png`。那个
**不是这一串里的**：它的卡数是 9、罩状态向量是 `#0C #1. #2. #3. #4C #5C #6. #7. #8C`，
与 `cd01`…`cd60` 里**任何一个类都不同**（那一串里卡位 1、2 要到第 14、20 帧才干净，
而这一张的卡数只有 9）。它看起来是另一次抓取或另一局的散件，**没有进样本，也没有进任何读数**。

## 备注：这三份读数都是**十一档时代**的（第五单）

`预处理.json` / `绝对线.json` / `圆盘取区.json` 是按**当时那条链**（`IDENTITY_SCALES` =
`1.05…1.15` 十一档 · 固定余量线 `0.25` · 报出来的分是**全局最大分**）量的。之后线上那条链
变了四处（尺度区间扩到 `1.00…1.17` 十八档 · 余量线随分数走 · 判据满足即停 ·
粗层直接接受），详见 [`../先粗后细/README.md`](../先粗后细/README.md)。

**这一批没有重跑，也不做兼容层**（用户裁定）：它们是**历史对照**，不是今天这条链的期望值。
