# 帧样本 / 余量

**「红罩那条路要救，余量从哪来」的测试夹具** —— 一整批**干净卡**（没被红罩盖住的备战席卡），
用来量「换一块取区之后，认得出/认不出的空档有多大」。

## 这是什么，从哪来

来自 `data/precheck/cd/`（**一局真机战斗里每 3 秒截一张、连截 61 张**）。那批全帧是 gitignored 的
临时产物，所以把**要用的那几帧**搬进版本库，让读数能反复跑。

裁剪口径 · 命名 · 清单字段**照 [`../红罩/`](../红罩/README.md) 与 [`../备战席/`](../备战席/README.md)**：
窗口 `(300, 1040)` 起、`2500×220`（原生像素，一个都不缩），一帧一文件，帧名就是 `cdNN`。

| 文件 | 内容 |
| --- | --- |
| `cdNN.png` | 14 帧备战席横带 |
| `index.json` | 每张的原点、尺寸、源帧路径与**源帧 sha256** |
| `余量.json` | **读数表**：掩码版取区与最大矩形取区并排，逐张卡一行（见下） |

**为什么是这 14 帧**：这一局的备战席是**一帧一帧长出来**的（每次部署多一张干净的卡），所以
帧挑得越靠后、能用的干净卡越多。**14 帧按时间铺开**，覆盖从 2 张到 10 张干净卡；到 `cd43` 之后
10 张全干净。名字覆盖库里 11 条里的 **10 条**（`流明` 这一局没上场）。

**它只放干净卡**：被红罩盖住的那些在 [`../红罩/`](../红罩/README.md) 里，两个目录各管一段 ——
这一单**没有改那一批**。

## 真值从哪来

干净卡的身份**不是目视的**：拿它**自己的身份区**（`roster.identity_region`，卡内 `(52, 76, 100, 100)`）
喂**线上那条链**（`roster_scores`）读出来 —— 最高分过 `ROSTER_SOLID_MATCH_SCORE = 0.85`、
而且余量拉开 `ROSTER_AMBIGUITY_MARGIN = 0.25`，两个都过才算这一张有真值。
**读不出来的卡不进 `余量.json`**（它们不是「认错了」，是「没认」）。

**这条真值自己是有前提的**：它就是线上那条链的读数。本局同一张卡在几十帧上给出同一个名字
（`index` 与名字逐帧一致），那是它稳的证据；但它**证不到底** —— 链错它就跟着错。

**`余量.json` 的行集合是按线筛出来的**：进表的条件就是上面那两条线（`ROSTER_SOLID_MATCH_SCORE`
与 `ROSTER_AMBIGUITY_MARGIN`，见常量，不是这张表里的字面量）。所以**挪线就要重跑这一份** ——
线一改，哪些卡进表、表有多少行都会跟着变；`tests/unit/test_vision_redcap_margin.py` 里
「两条线落在实测空档里」那一条也是拿这一份的读数当空档的下头钉住的。

## 读数怎么产生

```
.venv\Scripts\python.exe scripts\bench_redcap_margin.py
```

**尺子不是线上那条**：读数是 `ark.engine.vision.margin.MaskedRuler` 给的 —— 与 `roster_scores`
**同一个统计量**（逐通道减均值的零均值归一化相关），但收「一块形状 + 一个掩码」而不是一个矩形。
**线上链条一个字节没动**，这把尺子也**不接线上**。掩码全开时它与 `roster_scores` **逐位相同**
（`tests/unit/test_vision_redcap_margin.py` 里那条基线和 `余量.json` 的 `baseline` 就是这件事）。

**`余量.json` 逐字节可复现**：没有时间戳、没有绝对路径、没有随机量。


## 备注：这批读数是**十一档时代**的（第五单）

这一份是按**当时那条链**量的，之后线上那条链变了**四处**（见
[`../先粗后细/README.md`](../先粗后细/README.md)）：

1. **尺度区间按数据扩宽**：`IDENTITY_SCALES` 从 `1.05…1.15`（十一档）变成
   `1.00…1.17`（**18 档**）；
2. **余量那条线随分数走**：`次高 <= 2 × 最高 - 1.09`（`ROSTER_AMBIGUITY_MARGIN = 0.25`
   只作为**历史夹具的对照**留着，线上不再用它）；
3. **扫法**换成"扩到整段 · 近的先试 · 判据满足即停"，报出来的分变成
   **第一个满足判据的那一档上的分**（从前是全局最大分）；
4. **粗层直接接受**：锚点层上分线取 `0.9` 的话就在那一层判精确（全分辨率那条路的分线
   `0.85` 一个字没动）。

**这一份没有重跑，也不做兼容层**（用户裁定）：它记的是**当时那条链**的读数，行集合
也是**按当时那两条线**筛出来的（`余量.json` 尤其如此 —— 线一挪，哪些卡进表就跟着变）。
要拿它当"今天这条链应该给什么"用，得先重跑。它在本仓库里剩下的用途只有两样：
**历史对照**，以及 `tests/unit/test_vision_redcap_margin.py` 里那几条把它当基线钉住的断言。
