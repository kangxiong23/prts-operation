# 塞雷娅那一对：为什么在干净卡取区上只有 0.83（乙：只找原因）

> 这一份是**测量**，不是判据。产品代码与判据参数一个字节没动。

## 问的什么

组2 编队页切出来的「塞雷娅」那块 与 组2 备战席上她那张卡，在**干净卡取区**
（`roster.identity_region`，卡内 `(52, 76, 100, 100)`）上像度 **0.8309**；
同一位干员在**组1**那一对上是 **0.9875**。

## 三个答案（证据在 `读数.json` 与两张图里）

1. **差在哪（机制）**：**尺度区间那条下界把峰截掉了**。把那条链内层那一步按尺度
   一档一档重跑（`0.80…1.40`，步长 0.01），组2 那一对的峰落在 **1.01 = 0.9758**，
   而 `IDENTITY_SCALES` 从 **1.05** 起 —— 1.05 已经在峰的**下坡**上：
   `1.01→0.9758 · 1.02→0.9638 · 1.03→0.9293 · 1.04→0.8771 · 1.05→0.8309`。
   峰很陡（每 0.01 约 0.02–0.04 分），所以 4% 的尺度差就是 **0.1449** 分。
   组1 那一对的峰正好落在 **1.05**（下界上）—— 它只是恰好没被截掉。
   位置与亮度**不是**原因：十位的「最优位置残差」都在 **14.9–27.4 px**，塞雷娅的
   23.7 px 在中间；而 `TM_CCOEFF_NORMED` 对逐通道仿射免疫，整体亮度差进不来。
   对照图 `对照_身份框.png` 能看见同一个 100×100 框里**组2 那张脸更大** ——
   这就是「同样的卡框在立绘上对应的尺度更小」的样子。
2. **是不是这一套皮肤的特例**：**不是这个人的问题，是这套立绘与卡框的比例问题**。
   同一批里还有两张同病：**组2·圣聆初雪**（峰 1.02 = 0.9837，线上 0.8771）、
   **组2·白面鸮**（峰 1.02 = 0.9826，线上 0.9108）。组1 十位一位都没掉到 1.05 以下。
   跨批对照：**白面鸮 / 圣聆初雪 / 歌蕾蒂娅 / 极境 / 维什戴尔** 这五位在红罩那一批
   （另一局、另一份库）上读的是 **0.9709–0.9921** —— 所以不是「这个人不好认」。
3. **若是普遍原因，影响哪些卡**：凡是**卡框里的脸比立绘上大**（有效卡→立绘比例
   小于 1.05）的卡都会中。这一批 20 条里中了 **3 条**（都在组2）；上一批 16 张
   真匹配落在 1.06–1.15，就是因为那批的立绘没有这一档。**改法不由这一份提**。

## 怎么重建

```
.venv\Scripts\python.exe scripts\bench_roster_twin_probe.py
```

跑完覆盖这一目录下的 `读数.json` · `对照_那一对.png` · `对照_身份框.png` · `曲线.png`。
它只**调用** `ark.engine.vision.roster.roster_scores`（以及 `squad_card_scores` /
`find_squad_card`），曲线是那条链内层那一步逐档重跑，**最大值与它逐位核对**
（`读数.json` 的 `crosscheck.all_equal`，不相等就报错）。
