# 帧样本 / 立绘两组

**「同一位干员两套立绘同时在库里」那件实测的测试夹具** —— 两组编队页各切出 10 条立绘，
合成一把 **20 条**的库，用来量「库里有相似条目时余量会被压到多少」。

| 文件 | 内容 |
| --- | --- |
| `组1_编队页.png` / `组2_编队页.png` | 两套立绘的编队页（库的来源） |
| `组1_备战席.png` / `组2_备战席.png` | 两帧备战席（要读的卡） |
| `库1.json` / `库2.json` | 两把各 10 条的卡面库 |
| `取材.json` | 逐卡真值 |
| `点名.json` | **读数表**：20 条库下逐张卡的读数 |

它是**基准集**（`index.json` 第 1 版），加载走 `ark.offline.bench.batch.load_batch` —— 不用真机。

## 备注：这三份读数是**十一档时代**的（第五单）

`点名.json`（以及 `取材.json` 里的读数）是按**当时那条链**量的：`IDENTITY_SCALES` =
`1.05…1.15`（十一档）· 余量那条线是**固定的** `ROSTER_AMBIGUITY_MARGIN = 0.25` ·
"报出来的分是**全局最大分**"。之后线上那条链变了五处 —— 尺度区间扩到 `1.00…1.17`
（十八档）· 余量线随分数走（`次高 <= 2 × 最高 - 1.09`）· 判据满足即停（报出来的分变成
**第一个满足判据的那一档上的分**）· 粗层直接接受（锚点层分线 0.9）· 红罩那条路换成
**三层收窄**（第六单）。详见 [`../先粗后细/README.md`](../先粗后细/README.md)。

**这一批没有重跑，也不做兼容层**（用户裁定）：它是**历史对照**，不是今天这条链的期望值。

### `点名.json` 的格式：第六单**复原**过一次

那个文件是 `scripts/bench_roster_twins.py` 落下来的（第 388-389 行：
`json.dumps(report, ensure_ascii=False, indent=2) + "\n"`，`newline="\n"`）。
**第五单**我往它的 `note` 里追加过一段、而且顺手把缩进改成了 1 —— 那是**错的**；
**第六单复原**：`note` 回到脚本里那一份、缩进回到 2、行尾回到 LF（LF 折算 sha256
`ae6fda16edbb76faae530596c6c821768d8c6c7bcce65a2339d055a85a17fd0e`，5010 行）。
**备注不再住在夹具里，改住这里** —— 上面 §备注 那一段就是它。

**这个目录整个是未追踪的**（`git status` 里是 `?? tests/帧样本/立绘两组/`），
所以 `git diff` 拿不出"只有 note 那一行变了"这种证明。复原的口径是**按写它的那个脚本的
序列化格式**：`json.loads` 之后再按那一行代码序列化一次，**逐位等于**盘上那一份
（固定点）。
### 第七单：这个目录**入了仓**

`git add tests/帧样本/立绘两组/`（15 个文件：4 张 PNG · 2 份库 · `index.json` ·
`取材.json` · `点名.json` · `塞雷娅/` 下 3 张 PNG + `读数.json` + `README.md`）。
**只入索引，没有提交**（执行者不许提交）。

入仓前逐文件核过"**按写它的那段代码自己那个 indent 再序列化一次，逐位等于盘上那一份**"：

| 文件 | 写它的代码 | indent | 再序列化一次逐位相同 |
| --- | --- | --- | --- |
| `点名.json` | `scripts/bench_roster_twins.py` 第 388-389 行 | 2 | ✅ |
| `塞雷娅/读数.json` | `scripts/bench_roster_twin_probe.py` 第 432-435 行 | **1** | ✅ |
| `index.json` · `取材.json` · `库1.json` · `库2.json` | 仓里没有写它的脚本 | 2 | ✅ |

**`塞雷娅/读数.json` 的 indent 是 1，不是 2** —— 它由另一个脚本落盘。所以"再序列化一次"
这件事**必须按写它的那段代码**来，不能拿一个统一的 indent 去套（套错了会误判成"没复到位"）。
行尾一律 LF。
